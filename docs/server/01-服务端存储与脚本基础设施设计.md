# 01 · 服务端存储与脚本基础设施设计（MySQL · Redis · MongoDB · Lua 热更）

> **定位**：服务端企业化的**技术地基设计**——三存储分库（MySQL/Redis/MongoDB 按数据特征分库）、
> 三驱动的 RAII 封装、专用存储线程池、Lua 配置热更。对应实施排期 **D1~D2**。
>
> **配套文档**：[02-服务端业务逻辑设计](02-服务端业务逻辑设计-账号·战绩·模式.md)（三大功能的业务规则与协议，依赖本文的地基）；
> [架构设计文档](../架构设计文档.md)（六边形分层依据）；[字节协议与传输详解](../字节协议与传输详解.md)（协议契约）。
>
> **设计总纲**：**缩小的是部署规模，不缩小的是架构边界**——企业拓扑（网关/账号/大厅/战斗/数据服务）
> 折叠为单进程内五个边界清晰的模块，跨进程 RPC 退化为同进程的端口调用；未来拆进程只动 adapter。

## 一、设计原则（四条铁律）

| # | 原则 | 说明 |
|---|---|---|
| 1 | **按数据特征分库** | 强一致+查询 → MySQL；热/短命/要排序 → Redis；结构灵活+整场快照 → MongoDB。不"选一个库"，按数据归类 |
| 2 | **部署折叠，边界不折叠** | 每个模块（Auth/Lobby/Battle/Data）有自己的 Service + Repository 端口 + 自己的表，互相只经接口说话 |
| 3 | **存储 IO 不进网络线程** | epoll 线程禁止任何阻塞调用；SQL/Redis/Mongo 一律投递到专用存储线程，结果 `queueInLoop` 回投 |
| 4 | **每个存储必须有真实用途** | Redis 管 token 会话(TTL)/在线状态/排行榜 ZSET；Mongo 管对局事件流文档——不是堆技术，是三类数据的天生归属 |

## 三、数据归属与真实用途

### 3.1 MySQL（强一致、要查询）

```sql
-- 账号
CREATE TABLE account (
  account_id   BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  account      VARCHAR(32)  NOT NULL,
  pass_hash    CHAR(64)     NOT NULL,        -- SHA-256(密码+固定盐)，简易版约定
  nickname     VARCHAR(32)  NOT NULL,
  created_at   DATETIME DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_account (account)
);

-- 战绩汇总（登录摘要直读；排行榜的持久化底座）
CREATE TABLE player_stats (
  account_id   BIGINT UNSIGNED PRIMARY KEY,
  wins         INT UNSIGNED DEFAULT 0,
  losses       INT UNSIGNED DEFAULT 0,
  kills        INT UNSIGNED DEFAULT 0,
  deaths       INT UNSIGNED DEFAULT 0,
  updated_at   DATETIME DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

-- 对局索引
CREATE TABLE match_record (
  match_id     BIGINT UNSIGNED PRIMARY KEY AUTO_INCREMENT,
  mode         TINYINT UNSIGNED NOT NULL,
  winner_id    BIGINT UNSIGNED NOT NULL,
  started_at   DATETIME,
  ended_at     DATETIME DEFAULT CURRENT_TIMESTAMP,
  duration_sec INT UNSIGNED
);
```

### 3.2 Redis（热、短命、要排序——三个真实功能因此才有资格做）

| Key 设计 | 类型 | 功能 |
|---|---|---|
| `token:{accountId}` = 随机 token，**EX 86400** | STRING | 登录签发会话；断线重连凭 token 免密（W7 地基） |
| `online` = SET（登录 SADD / 踢出 SREM） | SET | **在线人数/在线列表**（主菜单“当前在线 N 人”） |
| `lb:kills` = ZSET（结算 ZINCRBY） | ZSET | **击杀排行榜**：`ZREVRANGE lb:kills 0 9` 出 Top10 |

> 排行榜是引入 Redis 才“有资格做”的功能——MySQL ORDER BY 也能排，但企业做法就是 ZSET（天然带分更新与排序）。

### 3.3 MongoDB（结构灵活、整场快照）

```
集合 battle_logs：每场一个文档
{
  matchId: 42, mode: 1, startedAt: ISODate,
  events: [ {t:3.2, type:"kill", killer:1001, victim:1002}, ... ],
  endStats: [ {accountId:1001, kills:3, deaths:1}, ... ]
}
```

**用途**：对局详情归档（整场事件流）。**伏笔**：录像回放功能的数据地基（求职文档 W6 后演进位）。
**双写顺序**：结算时先 MySQL（战绩汇总）→ 后 Mongo（对局文档，幂等重写）；失败策略 = Mongo 重试队列（不参与判定，允许延迟）。

## 四、三驱动封装设计（RAII 逐类展开）

### 4.1 MySQL —— libmysqlclient（Oracle Connector/C），三层封装

**背景**：C API 全是裸指针（`MYSQL*`/`MYSQL_RES*`/`MYSQL_STMT*`），异常路径忘 free/close = 泄漏/悬空。RAII 把释放绑死在对象生命周期上。

```cpp
// ── 层1：连接 RAII（构造即连，析构即关，断线自动重连）──
class MysqlConnection
{
public:
    explicit MysqlConnection(const MysqlConfig& cfg);   // mysql_init + real_connect
    ~MysqlConnection() { if (conn_) mysql_close(conn_); }

    bool ensureConnected();                              // mysql_ping 探活，断开重连（防 8 小时断连）

    ResultSet query(const std::string& sql);             // 有结果集查询
    bool execute(const std::string& sql);                // 无结果集执行

    // Prepared statement（防 SQL 注入的标准姿势，禁止字符串拼接）
    bool prepare(const std::string& sql);
    void bindInt(int idx, int32 value);
    void bindString(int idx, const std::string& value);
    bool executeStmt();
    ResultSet fetchResults();

private:
    MYSQL*      conn_ = nullptr;
    MYSQL_STMT* stmt_ = nullptr;
    MysqlConfig cfg_;
};

// ── 层2：结果集 RAII（忘 mysql_free_result 就漏内存——析构兜死）──
class ResultSet
{
public:
    explicit ResultSet(MYSQL_RES* r) : res_(r) {}
    ~ResultSet() { if (res_) mysql_free_result(res_); }
    ResultSet(const ResultSet&) = delete;                // 禁拷贝
    ResultSet(ResultSet&& other) noexcept;               // 可移动
    bool next();                                         // mysql_fetch_row
    std::string getString(int col);
    int32       getInt(int col);
private:
    MYSQL_RES* res_;
};

// ── 层3：连接池（取借还——TCP+认证握手贵，必须复用）──
class MysqlPool
{
public:
    explicit MysqlPool(const MysqlConfig& cfg, int poolSize);
    std::unique_ptr<MysqlConnection> acquire();          // 空闲队列取；无则条件变量等待
    void release(std::unique_ptr<MysqlConnection>);      // 归还（不是关闭）
private:
    MysqlConfig cfg_;
    std::vector<std::unique_ptr<MysqlConnection>> idle_;
    std::mutex mtx_;
    std::condition_variable cv_;
};
```

### 4.2 Redis —— hiredis（Redis 官方 C 客户端）

**背景**：每条命令返回 `redisReply*` 必须 `freeReplyObject`——整个 hiredis 最容易漏的资源。

```cpp
// reply 的 RAII（一次命令一次 free，析构兜死）
class RedisReply
{
public:
    explicit RedisReply(redisReply* r) : r_(r) {}
    ~RedisReply() { if (r_) freeReplyObject(r_); }
    bool isOk() const;
    std::string asString() const;
    int64_t asInteger() const;
    std::vector<std::pair<std::string,double>> asScoreArray() const;  // ZREVRANGE 解析
private:
    redisReply* r_;
};

class RedisConnection
{
public:
    explicit RedisConnection(const RedisConfig& cfg);    // redisConnect
    ~RedisConnection() { redisFree(c_); }
    bool ensureConnected();                              // 失败(null)→ 重连

    RedisReply  command(const char* fmt, ...);           // 通用命令（hiredis 格式化）
    // 语义化快捷方法（业务代码不写裸命令字符串）：
    void        setEx(key, val, ttlSec);                 // 会话 token
    std::optional<std::string> get(key);
    void        sadd(key, member); void srem(key, member);                                   // 在线状态
    void        zincrby(key, incr, member);                                                  // 排行榜
    std::vector<std::pair<std::string,double>> zrevrange(key, start, stop);
private:
    redisContext* c_ = nullptr;
    RedisConfig   cfg_;
};
```

### 4.3 MongoDB —— mongocxx（官方 C++ 驱动，含底层 mongoc）

```cpp
// ⚠️ 生命周期规则：instance 全进程只能有一个（存储线程池初始化时构造）；
//    client 非线程安全 → 每存储线程各自持有一个 client
class MongoClient
{
public:
    explicit MongoClient(const MongoConfig& cfg)
        : client_{mongocxx::uri{cfg.uri}} {}
    void insertBattleLog(const bsoncxx::document::value& doc);   // 整场事件流一次写入
private:
    mongocxx::client client_;
};

mongocxx::instance& MongoInstance();   // 全局唯一，首次使用时构造
```

| 驱动 | CMake 集成 | 线程约束 | 集成成本 |
|---|---|---|---|
| libmysqlclient | find_path/find_library（Win 装 Connector/C，Linux libmysqlclient-dev） | 阻塞 API → 存储线程 | 低 |
| hiredis | add_subdirectory 或 libhiredis-dev | 同上 | 低 |
| mongocxx + mongoc | find_package(mongocxx/bsoncxx)，vcpkg 或源码编译（依赖 OpenSSL/ZLIB） | instance 全局一次；client 非线程安全 | **中偏高（三库之最）** |

## 五、存储线程池（StorageIO）

```cpp
class StorageIO
{
public:
    void start(const DbConfig& dbCfg, const RedisConfig& rCfg, const MongoConfig& mCfg);
    void stop();

    /** 主 EventLoop 调用：投递存储任务（立即返回，绝不阻塞网络线程） */
    void post(std::function<void(StorageContext&)> job);

    /** 存储线程调用：结果回投到主 EventLoop 执行（复用 Reactor 跨线程投递机制） */
    void postBackToMain(std::function<void()> cb);

private:
    void run();   // while(running_) { auto job = queue_.pop(); job(ctx_); }

    ThreadSafeQueue<std::function<void(StorageContext&)>> queue_;
    std::thread worker_;
    EventLoop* mainLoop_ = nullptr;
    StorageContext ctx_;   // { MysqlPool, RedisConnection, MongoClient }
};
```

**业务侧用法（登录复合任务）**：

```cpp
storageIO_.post([this, account, passHash](StorageContext& ctx) {
    // —— 以下整段运行在存储线程 ——
    auto conn = ctx.mysql.acquire();
    auto row  = conn->query("SELECT account_id, pass_hash, nickname FROM account WHERE account=?")...;
    if (验证失败) { postBackToMain([=]{ 下发登录失败; }); return; }

    ctx.redis.setEx("token:1001", token, 86400);          // 同线程顺手签 token（复合任务内串联，少一次跨线程往返）
    ctx.redis.sadd("online", account);

    postBackToMain([=] {                                   // 回投主线程
        组装 S2C_LoginAck(playerId, nickname, token, 战绩摘要) 下发; 进入大厅;
    });
});
```

## 六、Lua 层（配置热更 + 数值热更）

### 6.1 行业事实与采档边界

Lua 是游戏服务端脚本的事实标准（网易/腾讯 MMO、Skynet、OpenResty、WoW）。企业用法三档，风险递增：

| 档 | 用法 | 采纳 |
|---|---|---|
| ① 配置热更（表驱动：DB 地址/端口/数值） | ✅ **本期做**（风险最低、收益直接） |
| ② 数值/规则热更（winKills、respawn 时长） | ✅ **本期做**（参数化已就绪） |
| ③ 玩法逻辑脚本化（夺旗规则整段 Lua） | ⬜ 暂缓——状态迁移/沙箱逃逸是真难题，演进位 |

### 6.2 选型：Lua 5.4 官方 C API 自封装（推荐） vs sol2

| 方案 | 评价 |
|---|---|
| **Lua 5.4 C API + 自写薄封装（~150 行）** | ✅ 推荐——零第三方依赖；面试叙事“自己封装 Lua C API 绑定”比“用了 sol2”更硬 |
| sol2（单头文件，MIT） | 开发效率高；备选 |

### 6.3 封装类

```cpp
class LuaVM
{
public:
    bool loadFile(const std::string& path);     // 新建 lua_State → 沙箱化 → luaL_dofile
    bool hotReload(const std::string& path);    // 校验后原子交换，失败保留旧配置
    std::string getString(const char* table, const char* key, const char* def);
    int         getInt(const char* table, const char* key, int def);
    double      getNumber(const char* table, const char* key, double def);
private:
    void sandbox();                              // 摘除 os/io/require（防任意执行）
    std::shared_ptr<lua_State> L_;               // shared_ptr 原子换
    std::mutex mtx_;
};
```

**沙箱（安全要点）**：`luaL_openlibs` 后摘除 `os.execute`/`io`/`require` 等危险库——配置脚本虽是自己写的，沙箱纪律是企业脚本系统标配（防将来策划脚本升级成玩法脚本时带进任意执行）。

### 6.5 热更机制与边界（诚实标注）

| 可热更 | 需重启 |
|---|---|
| heartbeat 超时、win_kills、respawn_ms、max_players、日志级别 | 监听端口、MySQL 地址（连接池重建可做，标“进阶”） |

**触发方式**：服务器控制台输入 `reload`（main 开 stdin 读取线程）→ `hotReload()` → 成功打日志“配置已热更 win_kills=3→5”；失败保留旧配置。未来加 C2S_Admin 管理协议。

## 八、错误降级（企业缩小版必备）

| 故障 | 降级行为 |
|---|---|
| MySQL 不可用 | 登录回“服务繁忙”错误码；对局不受影响 |
| 战绩落库失败 | 内存重试队列（进程内），不阻塞对局 |
| Redis 不可用 | 降级纯内存会话（token 存内存，TTL 逻辑不变）——接口不变，实现切换 |
| MongoDB 不可用 | 对局文档跳过（重试队列），战绩汇总照常 |

## 九、面试叙事（这套设计的含金量）

1. **“按数据特征分库”**——被问“为什么用三个库”，答案是“因为它们是三类数据”；
2. **存储线程与网络线程分离**——SQL 不阻塞事件循环，回投复用自研 Reactor 跨线程投递；
3. **token + TTL 会话**——断线重连的地基；
4. **RAII 资源纪律**——libmysql/hiredis 裸指针用 RAII 层兜死，业务层零手动 free；
5. **Lua 沙箱 + 热更边界表**——脚手架级细节最能证明真做过；
6. **接口诞生时机的一致性**——全项目接口始终“需求第二实现时才建”，存储端口（IMatchRepository）是最新例证。
