# Sightline 协议登记表（服务端与 UE 的共同契约）v4

> 传输：TCP 流。帧格式：`[2B len][2B msgid][payload]`，**小端**。
> `len` = msgid(2B) + payload 的总字节数（不含 len 自身）。
> 任何一端改动本表 = 契约变更，必须同步另一端并在本文件记录变更历史。
> **向后兼容铁律：已登记的 msgid 只增不改**——1~3（第 1 期）一个字节不动。

## 消息枚举

### 第 1 期（心跳链路，保持不变）

| msgid | 名称 | 方向 | payload 结构 | 说明 |
|-------|------|------|--------------|------|
| 1 | MSG_S2C_WELCOME | S → C | `[8B serverNowMs]` | 连接建立后服务器立即发送；C 可据此校时 |
| 2 | MSG_C2S_HEARTBEAT | C → S | `[4B seq][8B clientTs]` | C 每 1s 发送；seq 从 1 递增 |
| 3 | MSG_S2C_HEARTBEAT_ACK | S → C | `[4B seq][8B clientTs][8B serverTs]` | S 原样回显 + 附加 serverTs；C 按 seq 匹配算 ping |

### 第 2 期（登录 + 房间）

| msgid | 名称 | 方向 | payload 结构 | 说明 |
|-------|------|------|--------------|------|
| 4 | MSG_C2S_LOGIN | C → S | `[1B 名长 n][nB UTF-8 名字]` | 连接建立后第一个业务帧；名字非空且 ≤16B |
| 5 | MSG_S2C_LOGIN_RESULT | S → C | `[1B 结果码][4B PlayerId]` | 码：0=成功 / 1=重名拒绝（**预留**：顶号策略下服务器不发此码——同名走顶号=新连接成功、旧连接收 KICKED(1)）/ 2=名字非法 |
| 6 | MSG_C2S_CREATE_ROOM | C → S | `[1B 名长 m][mB UTF-8 房间名]` | 需已登录且不在房间；房间名非空且 ≤24B；**允许重名**（身份=RoomId） |
| 7 | MSG_S2C_CREATE_RESULT | S → C | `[1B 结果码][4B RoomId]` | 码：0=成功 / 1=未登录 / 2=已在房间 / 3=房间名非法 |
| 8 | MSG_C2S_JOIN_ROOM | C → S | `[4B RoomId]` | 需已登录且不在房间 |
| 9 | MSG_S2C_JOIN_RESULT | S → C | `[1B 结果码][4B RoomId][1B 人数]` | 码：0=成功 / 1=未登录 / 2=房间不存在 / 3=已满(4人) / 4=已在房间 |
| 10 | MSG_C2S_LEAVE_ROOM | C → S | 空 payload | 仅在房中有意义；离开后回大厅 |
| 11 | MSG_S2C_ROOM_LIST | S → C | `[2B 房间数 N]{[4B RoomId][1B 人数][1B 房间名长][房间名][1B 房主名长][房主名]}×N` | **推送**：登录成功后发一次全量；此后每次房间增减/人数变化推给所有"已登录未进房"连接 |
| 12 | MSG_S2C_ROOM_STATE | S → C | `[4B RoomId][1B 房主名长 h][hB 房主名][1B 人数 n]{[1B 名长][名字]}×n` | **推送**：房间成员变化时发给房内所有人；**房主=剩余成员中最早加入者**（房主离开自动转移） |
| 13 | MSG_S2C_KICKED | S → C | `[1B 原因码]` | 1=顶号（同名新登录） / 2=登录超时（连接 60s 内未 LOGIN） / 3=服务器关闭。**服务器随后主动断开** |

### 第 3 期（朴素移动同步对局）

| msgid | 名称 | 方向 | payload 结构 | 说明 |
|-------|------|------|--------------|------|
| 14 | MSG_C2S_START_MATCH | C → S | 空 payload | **仅房主**、在房中；请求开始对局 |
| 15 | MSG_S2C_MATCH_START | S → C | `[4B 玩家数 n]{[4B PlayerId][1B 名长][名字][1B 出生点序号]}×n` | 开始对局广播：全员切对局关卡，按名册+出生点生成角色 |
| 16 | MSG_C2S_MOVE_REPORT | C → S | `[12B pos xyz f32][4B yaw f32][4B pitch f32][1B flags]` | 30Hz 上报；flags bit0=腾空；**直发版服务器只转发不校验** |
| 17 | MSG_S2C_ENTITY_STATE | S → C | **v4**：`[2B 数量 n]{[4B PlayerId][12B pos][4B yaw][4B pitch][1B flags][4B ackedSeq]}×n`（29B/实体） | 33ms tick 广播房内全员（**v4.1：含接收者自己**——自实体的权威位+ackedSeq 即客户端预测和解的对账基准；v3 滤自己随权威收回废止）；v4 语义升级：pos/朝向 = **服务器权威推算值**；ackedSeq = 已确认输入序号（**破例已批 D4-01**） |
| 18 | MSG_S2C_ENTITY_LEAVE | S → C | `[4B PlayerId]` | 成员离开房间/断线 → 对端销毁其角色 |

### 第 4 期（预测与和解 · 基础设施升级）

| # | 常量 | 方向 | payload 布局 | 语义 |
|---|------|------|--------------|------|
| 19 | MSG_C2S_PLAYER_INPUT | C → S | `[4B seq][12B pos][4B yaw][4B pitch][1B flags]`（25B） | 对局期位置上报 v2：seq = 客户端本地预测序号（uint32 单调，回绕安全）；**对局期内替代 16 号**（R10） |

17 号升级为 v2（见上表）——**契约破例已批（D4-01，2026-10-19）**：「只增不改」保护的是对外承诺；17 号第 3 期才定、第 4 期立即演进，属同一演进窗口，双端同仓同 tag 同步部署，无独立发布的旧客户端，真实兼容成本为零。破例在此记录在案。

## 会话规则（契约正文）

1. **登录前宽限期**：连接建立 60s 内未发合法 `LOGIN(4)` → 服务器发 `KICKED(13, 码2)` 并断开。
2. **顶号**：同名字第二次 `LOGIN` 成功 → 新连接正常，旧连接收 `KICKED(13, 码1)` 后被服务器断开（一个账号一处在线）。
3. **心跳不变**：2/3 契约在任何会话状态下持续有效；LAG/重连逻辑不受本期影响。**重连后须重新 LOGIN**（会话不跨连接保活）。
4. **房主规则**：建房者即房主；房主离开/断线 → 房主转移给剩余成员中**最早加入**者；房间人数归 0 即解散。房主权限 = "开始对局"（v3 规则 7 兑现预留）。
5. **权威原则**：房间列表/成员/满员与否以服务器为准；客户端只发意图（4/6/8/10），一切状态以服务器推送（11/12）与请求-回执（5/7/9）为准。
6. **优雅关闭**：服务器收到关闭信号时，向所有在线连接发 `KICKED(13, 码3)` 后退出。
7. **开始对局**（v3）：仅房主可发 `START_MATCH(14)`；服务器校验房主身份后广播 `MATCH_START(15)`，**出生点序号 = 名册序**（按加入顺序）；对局期内房主离开自动转移（规则 4 照旧），新房主可再次开始（幂等由客户端切图状态保证）。
8. **对局期成员变动**（v3）：任何成员离开房间/断线 → 服务器向余下成员广播 `ENTITY_LEAVE(18)`；直发版**不做胜负/结束判定**（对局结束 = 房间解散或全员离开）。
9. **直发版权威边界**（v3）：位置以客户端上报为准**只转发不校验**——朴素版的工程边界；位置权威 ep04 收回（上行改输入），合法性校验与踢人 ep08 落地。（本条语义被规则 12 部分取代）
10. **对局期上行切换**（v4）：对局内客户端停发 16 改发 `PLAYER_INPUT(19)`；服务器收到对局期 16 视为无效帧静默丢弃。
11. **ackedSeq 语义**（v4）：快照中实体的 ackedSeq = 服务器已确认的最新输入序号；客户端以它为回滚/重放的对账基准（v4.1：自实体随包下发——"对账基准"即自实体那一行）。
12. **位置权威收回**（v4，兑现规则 9 预留）：17 号位置/朝向为**服务器权威推算值**（按输入推算 + 最小合法性钳制——完整合法性校验与踢人仍 ep08 落地）；权威修正触发与重放语义属客户端实现，不构成协议义务。
