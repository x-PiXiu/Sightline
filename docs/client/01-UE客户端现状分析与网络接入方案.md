# UE 客户端现状分析与网络接入方案

> 读者：接手 Sightline UE 客户端的 Agent 或开发者。
> 前置：本文假设你已经读过 `docs/项目交接与UE客户端实现指南.md`（知道协议和九步计划）。
> 本文解决一个具体问题：**已有一个纯蓝图 FPS 项目，怎么把网络层接进去**。

### 1.4 什么能读、什么不能读

| 能读 | 不能读 |
|------|--------|
| 目录结构/文件名（推断资产类型与用途） | .uasset 内部（二进制格式） |
| Config/*.ini（引擎配置） | 蓝图节点图与连线 |
| .uproject（JSON） | 动画状态机转换条件 |
| | UI 布局与绑定 |

**结论**：从结构看这个项目有完整的单机 FPS 闭环（移动/开火/换弹/动画/UI），缺的只是网络层。接入策略是"保留全部表现层，叠加网络层"。

## 二、接入方案总览

### 2.1 改动范围（三层递进，每层可独立验收）

```
第 1 层：转 C++ 工程 + 网络子系统        ← 只加文件，不动现有蓝图
第 2 层：BP_FPSPlayer 叠加网络上报       ← 改现有蓝图的 Event Graph
第 3 层：BP_RemotePawn + 远端表现        ← 新增蓝图类
```

### 2.2 网络消息流全景（接入后的完整图）

```
本地玩家操作                    服务器                        远端玩家看到的
────────────────              ──────────                    ──────────────
键盘 WASD                                                收到 S2C_Move(6)
  → IA_Move 触发                                           → RemotePawn 插值
  → CharacterMovement 移动                                  
  → [10Hz 定时器] ─────→  C2S_Move(5) → 采纳 → 广播 ─────→ 插值动画
                               │
鼠标左键                        │
  → IA_Fire 触发               │
  → 本地播枪口特效(预测)        │
  → ─────────────────────→  C2S_Fire(7) → hitscan 判定
                               │                    ┌── 命中 → S2C_Hit(8) → 扣血特效
                               │                    └── 未中 → S2C_Hit(8, victim=0) → 弹道特效
                               │
换弹 R                        │
  → IA_Reload 触发             │
  → AN_Reload 动画通知         │
  → ─────────────────────→  C2S_Move(5) 兼作心跳      （换弹纯本地，不上报）
                               │
2 秒定时器                     │
  → ─────────────────────→  C2S_Ping(10) → S2C_Pong(11) → RTT 显示
                               │
对局结束                       │
  ←───────────────────────  S2C_GameOver(9) → 结算 UI
```

## 三、第 1 层：转 C++ 工程并添加网络子系统

### Step 1.1 转纯蓝图工程为 C++ 工程

1. 在 UE 编辑器中：Tools → New C++ Class → 选 None（空类）→ 命名 `Marker` → Create Class
   - 这会生成 `Source/FPS_Game/` 目录和 `.Build.cs` 等构建文件
   - 编辑器会提示关闭并重新编译——同意
2. 验证：`Source/FPS_Game/FPS_Game.Build.cs` 存在；VS 能打开 `.sln`

> **为什么必须转 C++**：蓝图没有原生 Socket API；我们的 `SightlineNetSubsystem` 是 C++ 写的。

### Step 1.2 添加网络子系统代码

把以下两个文件放入 `Source/FPS_Game/Public/` 和 `Source/FPS_Game/Private/`（或直接放 Source/FPS_Game/ 下，根据项目惯例）：

- `SightlineNetSubsystem.h / .cpp` —— 完整代码见 `docs/项目交接与UE客户端实现指南.md` Step 2（~100 行）
- `SightlineProto.h` —— 协议辅助库，见同文档 Step 3（~80 行）

> **代码适配**：交接文档代码里的 `SIGHTLINECLIENT_API` 宏要全部替换为本工程的 `FPS_GAME_API`
> （UE 按工程名生成导出宏，工程名不同宏名不同；不匹配则链接报 unresolved symbol）。

**注意 `.Build.cs` 需要加两个模块依赖**：

```csharp
PublicDependencyModuleNames.AddRange(new string[] {
    "Core", "CoreUObject", "Engine", "InputCore",
    "Sockets", "Networking"   // ← 新增这两个
});
```

### Step 1.3 编译验证

1. 关闭 UE 编辑器 → VS 里 Rebuild → 0 error
2. 重新打开 .uproject → 内容浏览器搜 `Sightline` → 能找到 SightlineNetSubsystem 和 SightlineProto

**第 1 层验收**：编译通过，子系统在编辑器中可见。此时蓝图可以 `Get Game Instance Subsystem` 拿到它了。

## 四、第 2 层：在现有蓝图中叠加网络上报

> **原则**：只加节点，不删现有逻辑。所有改动在 BP_FPSPlayer 的 Event Graph 里。

### Step 2.1 连接与登录（Event BeginPlay）

在 BP_FPSPlayer 的 Event Graph 中，找到 BeginPlay 区域，追加以下节点：

```
[已有的 BeginPlay 逻辑保持不变]
    ↓
Get Game Instance Subsystem → SightlineNetSubsystem
    ↓
Connect (Ip="127.0.0.1", Port=8888)
    ↓ (Return Value = true)
SendFrame (MsgId=1, Payload=SightlineProto::EncLogin("Player1"))
    ↓
SendFrame (MsgId=3, Payload=[])  ← JoinRoom，空载荷
```

### Step 2.2 绑定消息事件（Event BeginPlay 之后）

```
Get Game Instance Subsystem → SightlineNetSubsystem
    ↓
Bind Event to On Net Message → 创建自定义事件 "OnServerMessage"
    ↓
Bind Event to On Disconnected → 创建自定义事件 "OnServerDisconnect"
```

### Step 2.3 移动上报（10Hz 定时器）

在 BeginPlay 里加 Set Timer by Event（Time=0.1，Looping）：

```
定时器触发（每 0.1 秒 = 10Hz）
    ↓
Get Actor Location → Get Actor Rotation → Break Rotator (取 Yaw)
    ↓
SightlineProto::EncMove(Location, Yaw)
    ↓
SendFrame (MsgId=5, Payload=上一步结果)
```

**注意**：不要在 Tick 里发——60 FPS 发 60 次/秒太多了。10Hz 是服务器设计频率。

### Step 2.4 心跳（2 秒定时器）

```
Set Timer by Event (Time=2.0, Looping)
    ↓
Get World Time Seconds → 转 int64 毫秒
    ↓
SightlineProto::EncPing(TimeMs)
    ↓
SendFrame (MsgId=10, Payload=上一步结果)
```

### Step 2.5 开火上报（在 IA_Fire 的回调里追加）

找到 IA_Fire 触发的逻辑（应该有"生成投射物/射线检测"等），**在现有开火逻辑之后**追加：

```
[已有的开火逻辑：动画/特效/本地判定 保持不变]
    ↓
Get Control Rotation → Get Forward Vector
    ↓
Get Actor Location → 作为 Origin
    ↓
SightlineProto::EncFire(Origin, ForwardVector)
    ↓
SendFrame (MsgId=7, Payload=上一步结果)
```

**关键理解**：本地播特效 = 客户端预测（体验零延迟）；服务器做权威判定 = 防外挂。两者不冲突。

### Step 2.6 消息处理（OnServerMessage 事件）

用 Switch on Int (MsgId) 分发：

| MsgId | 处理逻辑 |
|-------|----------|
| 2 (LoginAck) | DecodeU32(Payload,0) 取 playerId → 存到变量 → 显示在屏幕 |
| 4 (RoomStart) | 解析玩家列表 → 为每个非自己的 playerId Spawn BP_RemotePawn |
| 6 (MoveEvt) | DecodeU32 取 pid → DecodeF32×3 取位置 → 找对应 RemotePawn → 存目标位置 |
| 8 (Hit) | shooter/victim/dmg/hp/dead → 如果 victim==自己 → 扣血/死亡表现；如果 shooter==自己 → 显示命中标记 |
| 9 (GameOver) | winner → 显示"Victory/Defeat" |
| 11 (Pong) | 当前时间 - Payload 里的时间 = RTT → 显示 |
| 12 (Kick) | 显示"被踢" → 跳回主界面 |
| 13 (PlayerLeft) | 移除对应 RemotePawn |
| 14 (Respawn) | 重置自己的位置和血量 |

### 第 2 层验收

单开 PIE → 服务器日志出现 `conn#N in` → 屏幕 playerId 显示 → RTT 滚动。此时还没有"看到别人"——那是第 3 层。

## 五、第 3 层：远端玩家表现（BP_RemotePawn）

### Step 3.1 创建 BP_RemotePawn

1. 内容浏览器右键 → Blueprint Class → Parent 选 **Pawn**
2. 命名 `BP_RemotePawn`，放入 `Content/Code/Player/`
3. 添加一个 Static Mesh（先用 Cube 或角色简化模型）
4. 加变量：`PlayerId`（int）、`TargetLocation`（Vector）、`TargetYaw`（float）

### Step 3.2 Tick 插值

```
Event Tick
    ↓
VInterpTo (Current=GetActorLocation, Target=TargetLocation,
           DeltaTime=DeltaTime, InterpSpeed=10.0)
    ↓
SetActorLocation
    ↓
RInterpTo (Current=GetActorRotation.Yaw, Target=TargetYaw,
           DeltaTime=DeltaTime, InterpSpeed=10.0)
    ↓
SetActorRotation
```

**这就是插值**：服务器 10Hz 快照，客户端 60 FPS 渲染，中间靠 InterpTo 补帧。看到的远端玩家有 ~100ms 观察延迟——这是刻意付出的平滑成本（与 PUBG 同理）。

### Step 3.3 玩家 ID → Pawn 映射

在 BP_FPSGameMode（或一个全局 Actor）里维护一个 Map：

```
变量：RemotePawnMap (Map<int32, BP_RemotePawn*>)

收到 RoomStart(4)：
  解析玩家列表 → 对每个非自己的 pid：
    SpawnActor(BP_RemotePawn) → 设 PlayerId → 加入 Map

收到 MoveEvt(6)：
  pid → RemotePawnMap.Find(pid) → 设 TargetLocation / TargetYaw

收到 PlayerLeft(13)：
  pid → Map.Find → Destroy Actor → Map.Remove
```

### Step 3.4 双开联调

Play 下拉 → Number of Players = 2（Net Mode 保持 **Standalone**）。

| 窗口 A 操作 | 窗口 B 应看到 |
|-------------|--------------|
| WASD 移动 | A 的方块平滑跟随 |
| 左键开火 | 弹道特效 + 自己屏幕显示命中标记（如果打中了 A） |
| A 被打 4 次 | A 死亡 → 3 秒后重生 |
| A 关闭窗口 | B 收到 PlayerLeft → A 的方块消失 |

### 第 3 层验收

**双 PIE 完整对局**：登录 → 互见 → 对射 → 击杀 → 重生 → 胜负 → 自动重开。

## 六、与现有蓝图逻辑的融合点

| 现有资产 | 融合方式 |
|----------|----------|
| BP_FPSPlayer 的移动 | 不动——CharacterMovement 本地走，10Hz 定时器额外上报 |
| IA_Fire 的开火 | 不动——保留本地特效（预测），追加网络上报 |
| IA_Reload 的换弹 | **不上报**——纯本地表现（服务器不管换弹） |
| E_WeaponState / E_PlayerState | 不动——这些驱动本地动画状态机 |
| ABP_FPSPlayer 动画 | 不动——本地动画照跑；远端玩家的动画后续可加（M4 打磨） |
| UI_MainUI | 需要在编辑器里打开看绑定——血量条改绑服务器权威 HP 而非本地 |
| BI_Fire 接口 | 不动——武器蓝图实现这个接口，网络层不干扰 |
| 物理材质 PM_Dirt/PM_Metal | 不动——本地射击反馈 |

## 七、常见坑与排障

| 坑 | 症状 | 解法 |
|----|------|------|
| WSL2 端口不通 | Connect 返回 false | 用 WSL `hostname -I` 的 IP；确认 localhostForwarding |
| 8 秒被踢 | 收到 Kick(12) | Ping 定时器没启动或间隔 >8s |
| 双开互看不到 | 各自正常但没对方 | 两个 PIE 都要发 JoinRoom(3)；确认 RoomStart(4) 解析 |
| 移动瞬移 | 远端方块跳变 | 直接 SetActorLocation(Target) 忘了 VInterpTo |
| 收到消息但字段乱 | 数字巨大或 0 | 字节序/偏移错——对照服务器 protocol_codec.h 逐字段核对 |
| UE 自动启网络 | 报 NetDriver 错误 | Net Mode 没设 Standalone |
| 编译报缺模块 | 'Sockets' not found | Build.cs 没加 "Sockets","Networking" |
| 旧构建缓存 | 改了 .Build.cs 但不生效 | 删 Binaries/ + Intermediate/ → 重新编译 |
| PIE 双开只连上一个 | 第二个窗口无 playerId/共用连接 | PIE 默认 **Run Under One Process**：所有实例同进程共享 GameInstance → 共享同一个子系统 → 共用一个 socket（第二个 Connect 拆掉第一个）。Play ▶ 下拉 → Multiplayer Options → **取消勾选 Run Under One Process**；打包后手动开两个 exe 是更真实的验证 |

## 九、本项目的网络层与 UE Replication 的关系

| | 本项目 | UE Replication / DS |
|---|---|---|
| 服务器 | 自研 C++ Sightline（epoll + 自定义协议） | UE Dedicated Server |
| 同步机制 | 手写（10Hz 上报 + 广播 + 插值） | 引擎自动（NetUpdateFrequency + RepNotify） |
| 优势 | 完全控制延迟/带宽/判定逻辑；不依赖 UE 授权 | 开箱即用，蓝图拖 Replicated 就行 |
| 劣势 | 要自己写（但这就是学习目的） | 服务器被引擎绑死（性能/弹性/授权） |
| 适用 | **学习网络原理 + 展示底层功底** | 快速开发多人游戏 |

**我们的选择**：自研——因为面试叙事需要证明"我理解同步的每一层"，而不是"我会拖 Replicated 复选框"。
