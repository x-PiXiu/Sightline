# 案例 07 · Lyra 资产迁移——骨架统一与第三方素材合规

> **标签**：资产管线 · 骨架兼容性 · 第三方素材合规 · 迁移工具链
> **一句话**：从 Epic 官方 Lyra 项目搬运人物/武器/动画全家桶到自研项目——
> 技术上是 Migrate 依赖链管理，法务上是 EULA 许可边界，求职上是叙事纪律。

---

## 一、背景与目标（Situation）

项目需要：远端傀儡同步下蹲/持枪/瞄准动画（Phase 1~3）、官方品质的人物骨骼网格体、
配套枪械模型。选定 Epic 官方示例项目 **Lyra Starter Game**（5.7，与本项目同引擎版本）
作为素材源。目标：**全项目骨架统一到 UE5 Manny rig**——本地玩家、远端傀儡、
动画资产一套体系。

## 二、技术判断：什么能迁、什么不能迁（Action）

**核心区分：数据资产 vs 逻辑资产。**

| 类型 | 判定 | 原因 |
|---|---|---|
| 动画序列（`MM_*` 走姿/蒙太奇/受击/死亡/AO/BS） | ✅ 直接迁 | 纯数据；与 SKM_Manny 同 rig（`MM_`=Manny 男性，`MF_`=Quinn 女性不用） |
| 骨骼网格体/骨架/物理资产（`SKM_Manny/SK_Mannequin`） | ✅ 迁 | 动画的硬依赖 |
| 材质/贴图（`MI_*/T_*`） | ✅ 迁（整依赖链） | 网格依赖，不迁会紫 |
| **动画蓝图（`ABP_*`）** | ❌ **不迁** | 节点引用 Lyra 的 C++ 模块（LyraGame 等），跨工程必断链——**搬动画，状态机自己搭** |
| **GAS 资产（`GA_*/GE_*`）** | ❌ 不迁 | Gameplay Ability System 全家桶，体系不兼容 |
| AnimNotify / AnimModifiers | ❌ 不迁 | 挂 Lyra C++ 基类；效果已烘焙进动画数据，删除零影响（**强制删除安全的特例**：引用者是动画的编辑器历史，运行时不读） |
| `ALI_*` 动画层接口 | 暂不迁 | 只有搭 Linked Layer 分层体系才需要；我们用 Layered Blend Per Bone 绕过 |

## 三、正确工具：Migrate 而非手动拷贝

右击资产/文件夹 → **Asset Actions → Migrate** → 引擎自动列出全部硬依赖
（骨架/材质/贴图/物理资产）→ 目标选**对方工程的 Content 目录**。
手动 Copy .uasset = 依赖链断裂（紫色材质/丢失引用）。

**报告审核清单**（逐行勾选）：

| 看到什么 | 操作 |
|---|---|
| 动画序列 / 骨架 / 网格 / 材质贴图 / 物理 / 音效 | ✅ 勾 |
| `ABP_*` / `GA_*` / `GE_*` / `AN_*` / `ALI_*`（视需要） | ❌ 取消勾选 |
| "Animation Locomotion Library"插件内容 | 未勾选=正常（插件内容不属于工程，目标工程启用插件即可） |

**真实事故复盘**：首次迁移直接确认报告，把 `ABP_Mannequin_Base` 一起带过来——
打开即 Broken（引用 LyraGame 模块）。教训：**报告不是只能点确认，勾选状态可以改**；
以及清理时**不要 Force Delete 有引用的资产**，AnimModifier 的 297 个引用者是
动画的"编辑器修改历史"，运行时不读，属安全特例。

## 四、骨架绑定事故与修复

`SKM_Manny` 提示"未绑定有效骨骼"时，弹窗**新建**了 `SKM_Manny_Skeleton`（空骨架）
而非选择已有 `SK_Mannequin` → 空骨架无骨骼层级 → 顶点权重全部失效 →
**模型渲染为空、材质变灰**。且动画序列内部硬编码骨架路径
（`/Game/Characters/...`），整理目录到 `/Game/Lyra/Characters/...` 后路径失配，
出现"无法找到动画的骨骼"弹窗。

**修复**：删除 Lyra 人物资产**推倒重迁**——骨架/网格/动画**同批迁移、落在同一
路径树下**，动画内部记录的骨架路径与实际落盘路径天然一致；之后**绝不移动目录**。
（或编辑器内 Property Matrix 批量重指骨架。）

**流程教训**：① 跨资产引用含硬路径，"迁移后整理目录"必须整批完成且在验证前不动；
② 弹窗"新建骨架"永远是陷阱，永远先找已有骨架。

## 五、迁移后的统一收益

- **一套骨架三处复用**：本地玩家（CharacterMesh0 = SKM_Manny）、远端傀儡、
  全部 Lyra 动画同一 rig——傀儡的 ABP 本地玩家直接用，零重定向；
- **第一人称升级路径**：UE5.6+ 官方 First-Person Rendering
  （`First Person Primitive Type`，单 Pass morph 几何：防穿墙/防 FOV 拉伸/不投影不进反射），
  替代旧"双 Actor/第二 Pass"反面教材；
- 素材分层清晰：Lyra 本体在 `Content/Characters|Weapons`，自建逻辑在 `Content/Code/`
  （**Lyra 目录不新建自研文件**）。

## 六、素材合规（求职视频场景）

Lyra 随 **Unreal Engine EULA** 分发，官方示例内容的授权要点：

- ✅ 允许：任何 UE 项目中使用（含商业游戏）；发布含这些内容的截图/视频/直播——
  **求职视频、社媒发布完全在许可范围内**；
- ❌ 禁止：把素材本身当商品转卖（如打包上架卖 Lyra 动画）；
- Fab/商城素材同理：项目内使用 + 视频展示均允许。

**真正的风险不是法律而是叙事**：面试官认得出 Lyra 的 Manny 和商城素材——
声称自制当场翻车的是诚信。正确姿势是**主动标注 + 叙事重心放在自研系统**
（epoll 服务器、字节协议、状态同步、对象池、性能排查）："动画与部分素材来自
Epic Lyra / Vefects"一行字，显示懂引擎生态、做事规范。技术岗用现成素材不是减分项。

## 七、追问演练

**Q：怎么判断两套骨架能不能直接共用动画？**
A：看 rig 是否同源（骨骼树/命名/层级）。UE5 的 Manny/Quinn 是同一套 UE5 rig，
Lyra 用的就是它；本项目旧傀儡也是 SKM_Manny 系。个别不匹配右键 Retarget 一键重定向。
**反例**：Lyra 的 `Mannequin_UE4/` 目录是旧 UE4 骨架（骨骼名不同），不能混用。

**Q：为什么动画序列能跨工程，动画蓝图不能？**
A：动画序列是**纯数据**（曲线/关键帧+骨架引用）；动画蓝图是**编译的逻辑**——
节点图引用了宿主工程的 C++ 类和函数库，跨工程时那些符号不存在，节点全断。
同理 GA/GE（GAS）、PawnData（Lyra 专用数据类）都属逻辑资产。

**Q：AnimModifier 有 297 个引用为什么敢强制删除？**
A：引用者是动画序列的"编辑器修改历史"字段（记录曾被哪些工具处理过，
用途仅为编辑器里重跑工具），运行时播放代码完全不读。修改器的效果早已
烘焙进动画数据本体。判断标准：**引用链通不通到运行时**。

**Q：为什么不把 Lyra 资产 gitignore 掉（像商城包那样）？**
A：商城包可从 Vault 重装，gitignore 合理；Lyra 内容是**迁移加工过的**
（筛选过、重排过目录），重迁成本高且双机协作必须经 git 同步——
故这次选择全部入库。代价是仓库涨几百 MB，个人项目可接受。

## 八、30 秒速答卡

> "Lyra 素材迁移我总结成一条主线：**数据资产直接迁，逻辑资产自己搭**。
> 动画序列、骨架、网格、材质用引擎 Migrate 走依赖链自动打包；动画蓝图、GAS、
> 通知这些挂宿主工程 C++ 模块的，迁过来必断链，要按报告逐行取消勾选。
> 踩过的坑有两个：报告里混进 ABP 导致蓝图 Broken，以及骨架绑定弹窗手滑新建了
> 空骨架导致网格渲染为空——最后用整批重迁、同路径树落地根治。
> 合规上 Lyra 随 UE EULA 分发，项目内使用和求职视频展示都明确允许，
> 唯一要点是别声称素材自制，主动标注来源、把叙事重心放在自研的服务器和系统上。"
