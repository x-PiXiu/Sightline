# 案例 11 · 蓝图属性默认值继承陷阱——显式 None 覆盖冻结继承

> **标签**：蓝图序列化 · delta 继承 · 属性覆盖 · 静默失效
> **一句话**：父类蓝图设置了属性默认值，子类"没有设置"却被运行时读成 None——
> 因为子类序列化里存了一条**显式 None 覆盖**，冻结了继承。这不是 bug，是
> UE 蓝图属性继承机制的固有语义。

---

## 一、现象（Situation）

- 父类蓝图（BP_Weapon_Base）类默认值设置了 `ImpactFXConfig = DA_SightlineImpactFX`；
- 子类蓝图（BP_Weapon_Rifle）"没有设置"该属性；
- 运行时子类实例读取 `ImpactFXConfig` → **None** → 依赖该配置的功能全部静默失效
  （贴画/音效/碎屑不出现），且**没有任何编译错误**。

直觉预期："子类是 None → 应该回退用父类的值"——**实际不回退**。

## 二、机制：UE 蓝图属性的 delta 序列化继承

### 2.1 子类 CDO 的构造过程

```
子类 CDO（Class Default Object） =
    复制父类 CDO（继承父类全部默认值）
  + 叠加子类资产里【序列化的差异项】
```

- **未存储差异的属性** → 跟随父类（父类默认值修改后，子类加载时自动跟随）✅
- **显式存储了覆盖的属性**（哪怕覆盖值是 None）→ 冻结为存储值，**不回退父类** ❌

### 2.2 "显式 None 覆盖"是怎么产生的

只要在子类编辑器里对属性做过一次**修改并保存**（选中→清空、设了又改回、
误触），该属性就作为一条差异被序列化进子类资产。此后：

- 父类默认值修改 → 子类**不再跟随**（差异已固化）；
- 若差异值恰是 None → 运行时读出 None，依赖它的功能**静默失效**。

本次事故还原：排查期间在 BP_Weapon_Rifle 里触碰过该属性并保存 →
显式 None 覆盖入库 → 运行时实例读 None。

### 2.3 为什么 UE 这样设计（而不是"None 回退父类"）

如果 None 自动回退父类，你将**永远无法表达"这个子类故意没有 X"**——
清空父类提供的默认值会成为不可能的操作（一清空就弹回父类的值）。
所以"显式设为 None"是合法且必须被尊重的覆盖。代价是它静默失效，
需要开发者自己管理覆盖状态。

## 三、排查工具（三件套，按成本排序）

### ① 属性旁的覆盖标记 / 重置箭头（最快）

打开子类蓝图类默认值 → 找到目标属性 → 看**值右侧**：

- 有 **↺（重置为默认）箭头** 且高亮 → 该属性存在**显式覆盖**（子类存储了自己的值）；
- 箭头置灰/无标记 → 未覆盖，正跟随父类。

点 ↺ → 清除子类覆盖 → 恢复继承父类当前值。

### ② C++ 诊断日志（跨属性、跨类通用）

在 C++ 侧打印实例的实际属性值（含父类名，一并验证继承链）：

```cpp
UE_LOG(Warning, TEXT("[诊断] %s | 父类=%s | 属性=%s"),
    *GetName(),
    *GetClass()->GetSuperClass()->GetName(),
    Property ? *Property->GetPathName() : TEXT("None"));
```

一行日志同时回答："父类对不对" + "实例值是什么"——把"继承问题"和
"赋值问题"两类故障一刀切开。

### ③ 引用查看器 / Reparent 面板

排除父类本身的问题（父类资产是否存在、值是否真的设置、父类链是否正确）。

## 四、修复

| 方案 | 操作 | 适用 |
|---|---|---|
| **子类显式填值**（推荐） | 类默认值 → 属性 → 手动选目标资产 → 编译保存 | 值确定且不常变 |
| **重置为默认**（↺ 箭头） | 清除子类覆盖，恢复跟随父类 | 想恢复动态继承父类修改 |
| **Reparent 修正** | File → Reparent Blueprint | 父类挂错时 |

## 五、工程纪律（本次事故的沉淀）

> **配置类属性在子类蓝图里只有两种合法状态**：
> ① 显式填值（有意覆盖）；② 未覆盖（跟随父类）。
> **"显示 None 但你以为在继承"的中间态最危险**——不报编译错、编辑器无红字、
> 只在运行时表现为功能静默失效。

配套习惯：

- 跨蓝图改默认值后，**抽查一两个子类**的属性是否跟随（防止 delta 已固化）；
- 项目拷贝/迁移/合并后，优先跑一遍关键功能的 PIE 冒烟（属性序列化状态可能变化）；
- 用 C++ 诊断日志定位属性断点（临时加、闭环后删）——比在蓝图里逐节点排查快一个量级。

## 六、追问演练

**Q：为什么"子类为 None"不回退父类？大多数语言不是这样吧？**
A：UE 蓝图属性是**序列化差异**模型而非运行时回退模型——None 是一条被显式
存储的合法覆盖值（表达"这个子类故意没有"）。若 None 自动回退，"清空父类
默认值"的操作将无法实现。回退语义需要靠 **Reset to Default**（清除差异）显式触发。

**Q：怎么区分"显式覆盖"和"未存储差异"？**
A：编辑器看属性值旁的**重置箭头（↺）是否可点/高亮**；或 C++ 诊断日志打印
实例属性值。序列化层面：子类资产里是否存在该属性的条目。

**Q：父类改了默认值，子类会自动跟吗？**
A：**未覆盖的属性会**（加载时子类 CDO 从父类 CDO 构造再叠差异）；
**有显式覆盖的不会**（差异固化）。这也是"尽量少在子类存覆盖、共享配置上浮
到父类/C++"的组织学理由——覆盖越少，传播越顺。

**Q：这类静默失效为什么编译器不报错？**
A：None 是属性的合法值（对象引用可以为空），序列化和编译都不视为错误——
它只在**运行时行为**上表现为功能缺失。防御手段：关键配置在 C++ BeginPlay
加判空警告日志（如本项目的 `[Weapon] ImpactFXConfig 未配置` 会打 Warning）。

## 七、30 秒速答卡

> "UE 蓝图属性继承是 delta 序列化模型：子类只存与父类的**差异**，没存差异的
> 属性跟随父类；一旦在子类里编辑并保存过——**哪怕值是 None**——就成为显式
> 覆盖被冻结，父类后续修改不再传播。None 覆盖的运行时表现是功能静默失效、
> 无编译错误，只能靠日志或属性旁的重置箭头发现。修复两选一：子类显式重选值，
> 或重置为默认恢复继承。工程纪律是：配置属性要么显式填、要么确认无覆盖，
> 不留'显示 None 但以为在继承'的中间态。"
