# 案例 09 · 角色倾斜与相机挂点——视模型与全身角色的架构差异

> **标签**：第一人称架构 · 相机挂点 · Tick 旋转链 · 视模型遗产
> **一句话**：角色倾斜、视线向下全身倒、朝向垂直于视角——三个症状,
> 三个根因，最后收敛为一个架构结论：**视模型（Viewmodel）与全身角色的第一人称
> 实现是两套不同体系，不能混搭**。

---

## 一、现象（Situation）

换装 Lyra 全身 Manny（替换旧"独立手臂"方案）后，出现一组诡异症状：

1. 角色在第三人称观察下是**倾斜**的（不垂直于地面）；
2. **视线向下 → 整个身体跟着向前倒**（相机俯仰驱动全身俯仰）；
3. 角色朝向与相机视角**垂直**，按 W 横着滑行。

## 二、三个根因（Action · 逐层下钻）

### 根因 ①：相机挂在 head 骨骼上（用户自行发现 ✅）

相机 Attach 到 Manny 的 head 骨骼 → 相机被**动画**驱动（待机动画低头/转头 →
视角跟着歪斜）。正确位置：挂胶囊体下 + **Use Pawn Control Rotation** +
位置 Z≈75（眼睛高度）——**相机绝不挂任何骨骼**。

### 根因 ②：Tick 旋转链（旧视模型遗产）——"视线向下全身倒"的元凶

BP_LyPlayer 事件图表（复制自旧 BP_Player）存在一条链：

```
事件 Tick → 获取控制旋转 → 设置世界旋转（目标 = 网格体）
```

**来历**：旧"独立手臂"方案是**视模型（Viewmodel）架构**——手臂网格体必须
每帧跟随相机旋转（相机往哪看，手臂朝哪摆）。这条链在旧方案里是**正确**的。

**换全身 Manny 后**：作用对象从"手臂网格"变成"全身网格"——鼠标 Pitch 直接
驱动**整个身体俯仰**。即"视线向下 → 全身向前倒"。且 C++ 构造函数里
`PrimaryActorTick.bCanEverTick = false`——这条链**理论上根本不该跑**（复制
图表时连着事件一起带过来的遗产），它的存在本身就是蓝图复制迁移的坑。

**修复**：整条链删除（含链尾的 SyncWeaponVisualState——新武器 ABP 不再消费
MoveX/MoveY，贴画/HUD 走事件，无消费者）。

### 根因 ③：Mesh Yaw 补偿缺失——"朝向垂直于视角 + 横着移动"

UE5 Manny 原生**面朝 +Y**，而 Character 约定面朝 **+X**——差 90°。
CharacterMesh0 的旋转必须 **Yaw = -90**（Roll/Pitch 恒为 0）。

| Mesh Yaw 值 | 视觉表现 |
|---|---|
| -90（正确） | 面朝移动方向，跑动自然 |
| 0（常见手滑/排查时误清零） | **侧对移动方向 90°** → 宽站位侧视角 = "冲浪/倾斜"观感 |
| +90 | 面朝正后方 |

宽站位（Lyra 战备待机的双腿开立）+ 侧向 90° = 从相机看是"倾斜的冲浪姿势"——
与症状完全吻合。

### C++ 侧排除（grep 实锤）

角色 C++ 代码里唯一影响旋转的是 `bUseControllerRotationYaw = true`——
**只让 Actor 水平转向（Yaw），不存在 Roll/Pitch 操作**；
`MeshRotationOffset / SetActorRotation` 只存在于远端傀儡类。
**倾斜不可能来自代码**——只能来自蓝图变换字段、动画姿势、或相机挂点。

## 三、正确的第一人称架构（修复后终态）

```
相机：挂胶囊下 + Use Pawn Control Rotation（眼睛独立俯仰，不挂骨骼）
身体：bUseControllerRotationYaw 只管水平朝向，永远竖直
头部：Phase 1 共用 ABP 的 AimOffset——视线俯仰驱动头/脊柱**加法旋转**
      （"视线向下 → 头和枪口向下看"，身体和腿不动）——11 方案已规划
```

**与旧视模型方案的对照**（面试点）：

| | 旧：独立手臂视模型 | 新：全身角色 + First Person 渲染 |
|---|---|---|
| 网格 | 独立手臂骨架（需每帧跟相机转） | 全身 Manny（自然站立） |
| 相机 | 挂手臂/驱动旋转 | 独立于身体，控制旋转驱动 |
| 防穿墙 | 深度偏移 trick / 近平面 | 5.6+ First Person Primitive Type（单 Pass morph） |
| 动画 | 手臂专用 ABP | Lyra 全套持枪动画直接复用 |
| 骨架 | 与角色骨架两套 | **与远端傀儡一套**（统一红利） |

## 四、追问演练

**Q：为什么 Tick 链在旧方案里是对的、新方案里是错的？**
A：架构语义变了。旧方案手臂是**视模型**——手臂姿态=相机姿态，SetWorldRotation
(控制旋转) 正确；新方案身体是**世界中的角色**——身体只应水平跟随（Yaw），
Pitch 属于视线（相机/AimOffset），写进身体 = 全身倾倒。**同一段代码换个架构
语义就反了**——判断标准不是"代码对不对"，是"它服务的架构假设还成立吗"。

**Q：为什么"视线向下 → 头向下看"不用旋转身体实现？**
A：人的生理结构——视线俯仰由**颈部/眼部**完成，躯干不参与。游戏实现即
ABP 的 AimOffset：把控制 Pitch 经 AO 动画加法混合到头/脊柱骨骼，身体和腿
保持战备姿态。旋转身体会让腿脚离地/穿地，是明显的假动画。

**Q：C++ 里 bCanEverTick=false，为什么 Tick 链还跑了？**
A：两种可能并存——蓝图副本继承时 Tick 设置被类默认值重开；或链根本没跑、
倾斜全部来自 ③（Mesh Yaw）。用 Print String 探针实测最稳。

**Q：怎么判断"倾斜"该查哪里？**
A：三个候选按成本排序——①相机挂点（head 骨骼=动画驱动）②Mesh 变换三字段
（Roll/Pitch/Yaw）③动画自身的姿势设计。F8 弹出环绕看：静止就歪=②③，
只在动/看的时候歪=①。

## 五、30 秒速答卡

> "角色倾斜的根因是架构混搭：旧'独立手臂视模型'方案的遗产（相机挂骨骼、
> Tick 每帧把控制旋转写进网格体）被复制到了全身角色蓝图上——视模型语义下
> '手臂跟相机转'是对的，全身角色下就变成'身体跟着视线倾倒'。另外 Manny
> 原生朝 +Y，缺 Yaw=-90 补偿时侧对移动方向 90°，宽站位侧视角就是'冲浪姿势'。
> 修复：相机独立挂胶囊+控制旋转；删 Tick 旋转链（身体只水平跟随）；
> '视线低头'由共用 ABP 的 AimOffset 加法层实现——头动身不动，这才是人的视线模拟。"
