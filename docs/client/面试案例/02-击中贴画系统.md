# 案例 02 · 击中贴画系统——对象池与数据驱动的表现层

> **标签**：GC 债务 · 对象池 · 数据驱动 · 加法设计
> **一句话**：子弹打墙要有弹孔——用"64 环形池 + 表面查表 + 客户端表现层 trace"
> 三件套，把一个功能需求做成了 GC/性能/架构的三合一案例。

---

## 一、需求与约束（Situation）

子弹命中需要弹孔/音效/碎屑，且不同材质表现不同。约束：

1. 射速 10 发/秒，长对局不能有 GC 尖刺；
2. 各表面的首次表现不能卡顿（项目刚经历过首枪卡顿，见案例 01）；
3. 服务器 hitscan 只做伤害判定，**弹着点表现完全是客户端本地事务**
   （尤其 miss 时子弹打在哪，只有开火客户端自己知道）。

## 二、设计决策（Action · 三层拆解）

### 决策 1：数据从哪来——表现层 trace，协议零改动

伤害判定在服务器，但表现需要命中点/法线/材质。**不改协议**：客户端开火时
本地补一条 `LineTraceSingleByChannel(ECC_Visibility)`（忽略自己），
拿到 `Hit.Location / ImpactNormal / PhysMaterial` → `DetermineSurfaceType`。
这与"本地立即表现、判定权在服务器"的既有原则一致——miss 的弹着墙面恰恰
只有客户端自己知道，服务器判 miss 不影响客户端贴弹孔。

### 决策 2：弹孔怎么生成——64 环形池，永不销毁

知识库 1.4 的推演：`SpawnActor/Destroy` 只是标记待回收，机枪每秒 10 发 =
每秒 10 个 UObject 生灭，GC 周期性尖刺就是这笔账。方案：

```cpp
// USightlineDecalPoolSubsystem (GameInstanceSubsystem)
// 预生成 64 个 UDecalComponent 挂在 WorldSettings 上（连 Actor 都省了）
SpawnDecal(Mat, Loc, Normal, Size) {
    auto* Decal = Pool[Cursor++ % Pool.Num()];   // 环形覆盖最旧
    Decal->SetWorldLocationAndRotation(Loc + Normal*0.5f,  // 抬0.5cm防Z-fighting
        FQuat(Normal, FRandRange(0,2π)) * MakeFromX(Normal)); // +X对齐法线+随机滚转
    Decal->SetDecalMaterial(Mat); Decal->SetVisibility(true);
}
```

**特性**：零分配、零 Actor、零 Destroy；打满 64 发覆盖最旧（6.4 秒历史，符合直觉）；
GC 每轮"没账可收"。

### 决策 3：不同材质怎么分流——SurfaceType 查 DataAsset

- 地图材质挂 `UPhysicalMaterial`（PM_Concrete 等，各配不同 SurfaceType）；
- trace 命中 → `DetermineSurfaceType` 解出枚举 →
  `DA_SightlineImpactFX.TryGetImpactFX(Surface)` 查表 → `{弹孔材质, 音效, 碎屑特效}`；
- **查不到回落 Default 行**（材质忘挂 PM / DA 没建该行，都有兜底）。

### 决策 4：首次表现不卡——错峰预热

13 套碎屑特效每个都要运行时编译（实测单个 0.6~4.3s）。**挤同一帧 = 把首枪卡顿
换成开局卡顿**。方案：子系统 `Warmup()` 每隔 0.1s 在视野外
（-99999）`SpawnSystemAtLocation` 一个，**逐个错峰编译**，每步打日志可核对。

### 决策 5：分工契约

C++ 负责 trace、解表面类型、管池子和预热；**蓝图只决定"这个表面长什么样"**
（BP_OnShotImpact 钩子里查 DA 调池子）；判定权仍在服务器。

## 三、结果（Result）

- 日志验收序列：`已预生成 64 个贴画组件` → `开始预热 N 个命中特效系统` →
  每 0.1s 一条`预热发起` → `预热完毕`；
- 第二次 PIE 编译日志 0 条（DDC 命中），首枪零卡顿；
- 6 条卡顿帧 RTT 假尖刺全被滤波拦截，稳态 RTT 显示 4ms（真实值）。

## 四、追问演练

**Q：为什么池子挂 WorldSettings 而不是 Spawn 一个管理 Actor？**
A：与引擎 `SpawnDecalAtLocation` 的归属策略一致——贴画本质是"世界的装饰"，
WorldSettings 是天然的、必然存在的常驻 Owner，省一个 Actor 的生成与生命周期管理。

**Q：Spawn 时为什么要先 SetVisibility(false) 再 true？**
A：可见性切换触发渲染代理重建，保证同帧内改的材质/尺寸/朝向全部生效——
UDecalComponent 热更新属性时渲染侧有延迟，先隐藏再显示是强制刷新的标准做法。

**Q：Impact Normal 和 Normal 有什么区别？**
A：两对字段描述"谁的几何"——`Normal/Location` 描述**发起 trace 的查询形状**
（球 trace 时是指向球心的球面法线），`ImpactNormal/ImpactPoint` 描述**被击中物体的表面**。
LineTrace 下两者相等，但武器将来升级 SphereTrace（子弹带半径）后 Normal 会歪，
所以贴表面的表现一律读 Impact\* 引脚——现在养成习惯，换 trace 类型零改动。

**Q：为什么 13 套特效不合并成一个通用系统加参数？**
A：正在做——方案是 1 个通用系统 + SurfaceType 动态参数（编译/预热/PSO 变体 ×1
而不是 ×13），差异大的（玻璃碎裂、水面）保留独立。这是知识库 4.2"减变体本身"的落地，
属于第二期优化。

**Q：远端玩家开火的弹着点怎么办？**
A：当前协议 S2C_Hit 不带弹道 origin/dir，远端弹着点暂时出不了。协议演进时在
Fire 广播补两个字段即可复用整池（"谁开火谁出弹着"的结构已预留）。

## 五、30 秒速答卡

> "弹孔系统我做了三层：**数据层**用 SurfaceType 查 DataAsset 拿材质音效特效配置，
> 查不到回落 Default 兜底；**表现层**用 64 个 UDecalComponent 的环形池，覆盖最旧、
> 永不销毁，GC 每轮没账可收；**预热层**把各表面碎屑特效每 0.1 秒错峰编译一个，
> 避免把首枪卡顿换成开局卡顿。判定权和表现分离——服务器管打没打中，
> 客户端自己 trace 拿弹着点，协议零改动。上线后第一枪零卡顿，长对局零 GC 尖刺。"
