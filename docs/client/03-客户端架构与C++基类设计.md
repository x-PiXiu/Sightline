# 客户端架构与 C++ 基类设计

> 本文回答四个问题：**客户端分几层、每个类管什么、数据怎么流、为什么这样设计**。
> 与服务端《架构设计文档》对位——服务端的那句总览在这里是：
> **UE 只做表现层：一颗 C++ 会话内核（Character）驱动数据傀儡（RemotePawn），武器表达开火意图，字节搬运收口在子系统（NetSubsystem），翻译收口在协议库（Proto）。**
> 所有类名、成员、调用关系与代码一一对应（截至基类落地版本，客户端仓库 commit `a657e22`）。

---

## 一、总览：类图与依赖方向

```
USightlineNetSubsystem (GameInstance 级,每实例一份)
  Connect / SendFrame / OnNetMessage委托 / OnDisconnected委托
  只搬字节:连接、组帧拆帧、断线检测            ← 谦卑对象,零业务
        │ 委托
        ▼
ASightlineCharacter (Abstract)   ←──── ReportFire ──────┐
  会话:Login/JoinRoom/10Hz Move/2s Ping                  │
  状态:MyPlayerId / MyHP / bIsDead (只读)                │
  路由:OnServerMessage → Handle* × 9                     │
  远端表:Map<playerId, ASightlineRemotePawn*>            │
        │ Spawn/SetTarget/Destroy                        │ 意图
        ▼                                                │
ASightlineRemotePawn (每个远端玩家一个)                   │
  SetTarget → Tick 插值(VInterpTo/RInterpTo)             │
        │                                                │
USightlineWeapon ◄── GetOwner() 派生持有者 ──────────────┘
  FireShot: CanFire→冷却→弹药 → ReportFire → BP_OnFireEffects

USightlineProto (纯静态):EMsg 枚举 + Enc*/Decode* 全套语义编解码
  两端共同契约的服务器侧对位物:include/adapters/protocol_codec.h
```

**依赖方向**：蓝图子类 → C++ 基类 → Subsystem/Proto；Weapon → Character → Subsystem。**没有任何反向 include**。

## 二、五件套职责详解

### 2.1 USightlineNetSubsystem —— 字节搬运工（谦卑对象）

| 成员 | 说明 |
|---|---|
| `Connect(Ip,Port)` / `ConnectWith(Config)` | 阻塞连接（本地毫秒级）后切非阻塞；`FSightlineConnConfig{Host,Port}` 是服务器 `SightlineConfig` 的客户端对位物 |
| `SendFrame(MsgId, Payload)` | 组帧 `[2B len][2B msgid][payload]`（小端），含部分写循环 |
| `OnNetMessage` 委托 | 拆包后的完整消息（MsgId + Payload），蓝图/C++ 均可绑定 |
| `OnDisconnected` 委托 | 断线广播（生命周期内只播一次） |
| `Tick → PumpRecv/ExtractPackets` | 非阻塞收包 + 长度前缀拆包（粘包/半包） |

**关键实现语义**（读引擎 `SocketsBSD.cpp` 确认，两次联调踩坑的结晶）：
- UE 流式 socket 的 `Recv`：`(true,N>0)`=有数据；**`(true,0)`=无数据**（引擎已把 EWOULDBLOCK 归一化，勿当优雅关闭）；`(false,0)`=连接结束；
- 断线判定带 `GetConnectionState()` 保护：PIE 双开 Tick 被挤压数秒时的瞬态 false 不误报。

**为什么它是谦卑对象**：难测试的 socket 操作被剥得只剩搬运，任何业务判断都不存在——单测它没有意义，单测 Proto 和 Character 才有意义。

### 2.2 USightlineProto —— 翻译官（协议库）

- `EMsg` 枚举：`None=0`（UHT 要求）+ msgid 1~14，与服务器 `MsgId` 严格一致；
- 编码侧 `EncLogin/EncMove/EncFire/EncPing`：显式按小端拼字节；
- 解码侧提供**语义节点**：`DecodeMove` 一个函数返回 pid/pos/yaw，且**内含坐标换轴**（服务器 y-up → UE Z-up）；`DecodeHit` 一次返回五字段；
- 字节序契约与"加尾不改头"演进规则：见《字节协议与传输详解》第十一节契约面清单。

### 2.3 ASightlineCharacter —— 会话内核（本类是客户端的心脏）

**成员三组**：

| 组 | 成员 | 可见性 | 说明 |
|---|---|---|---|
| 状态 | `MyPlayerId`（0=未登录）、`MyHP`、`bIsDead` | `VisibleAnywhere` **只读** | 唯一写入口 = `Handle*`（即服务器事件） |
| 配置 | `PlayerName`、`bAutoLogin`、`ConnConfig`、`MoveReportInterval=0.1`、`PingInterval=2`、`RemotePawnClass`、`DefaultWeaponClass` | `EditDefaultsOnly` | 蓝图子类 Details 面板可调 |
| 内部 | `RemotePawns`（Map）、`CurrentWeapon`、`Net`（弱引用）、两个 TimerHandle、`PingSentMs` | private | — |

**方法分层**：

```
BeginPlay/EndPlay          绑定委托、自动装备、登录、定时器；退场清理
LoginToServer              Connect(如未连) → Login → JoinRoom
ReportMove / SendPing      定时器驱动；内部自守卫(未登录/断线不发)——断线重连自愈
OnServerMessage            switch(EMsg) → 9 个 Handle*(全部 virtual)
Handle*                    ★状态落地 + 调 BP_On* 表现钩子
SpawnRemotePawns 等        跳过自己、跳过重复(重开一局的 RoomStart 会再来)
ReportFire / CanFire       ★全项目唯一发送 C2S_Fire 的地方
```

**M3 教训的 C++ 化**：`HandleHit` 里 `击杀` 的双条件 `Shooter == MyPlayerId && bDead` 是一行代码——蓝图里连这条线曾接出"每枪都报击杀"的 Bug，C++ 里这类错误无法存在。

**表现钩子（BlueprintImplementableEvent × 8）**：`BP_OnHitReceived / BP_OnKillConfirmed / BP_OnRespawned / BP_OnGameOver / BP_OnRttUpdated / BP_OnKicked / BP_OnPlayerLeft / BP_OnDisconnected`——C++ 算完状态后调用，蓝图子类覆盖它们画红闪/播报/UI。

### 2.4 ASightlineRemotePawn —— 数据傀儡

- 继承 **Pawn** 而非 Character：傀儡不需要移动组件/输入，Character 那 20 多个组件是纯浪费；
- `SetTarget(Pos, Yaw)` 是唯一数据入口；`SnapDistance=500`：目标距离超阈值直接吸附——覆盖**首帧生成位置**、**服务器重生传送**两种场景，不会出现"从 (0,0,0) 滑 18 米"的诡异动画；
- Tick 插值在 C++：`VInterpTo` 位置 + `RInterpTo` 朝向（只取 Yaw 回写），插值参数 `EditDefaultsOnly` 可调手感；
- **没有 IsDead 字段**——死亡表现（倒地/隐藏）走 Character 的 `BP_OnHitReceived(bDead=true)` 钩子，傀儡只管位置。

### 2.5 ASightlineWeapon —— 开火规则 + 弹药

```
StartFire → FireShot:
  ① GetOwningCharacter()->CanFire()   未登录/死亡 → 直接返回(死亡禁火)
  ② bReloading / IsOnCooldown          冷却用时间戳对比,不用 Timer(抗帧率波动)
  ③ 弹药:空仓且 bAutoReloadOnEmpty → 自动 Reload
  ④ ConsumeAmmo()                      扣弹 + BP_OnAmmoChanged
  ⑤ Character->ReportFire(枪口位置, 控制器朝向)   ★网络只走这一条路
  ⑥ BP_OnFireEffects                  本地特效(预测,不越权)
```

- **弹药是客户端本地演出**（当前协议服务器不管弹药），但带规则（换弹计时/容量约束）所以归 C++；蓝图只读 `AmmoInMag/ReserveAmmo` 显示；
- **换弹不上报**（协议无此消息），`Reload → Timer(ReloadTime) → FinishReload` 纯本地；
- **所有权单向**：Character 存 `CurrentWeapon`（`EquipWeapon` 设 Owner+引用）；武器侧 `GetOwningCharacter()` 从引擎 Owner **派生**、不存储——GC 安全、零循环引用（角色先死时武器侧自动拿到 nullptr）。

## 三、数据流全景：一枪命中"我"的客户端旅程

```
服务器 Hit 事件
    ↓ TCP
Subsystem::Tick → PumpRecv → ExtractPackets (拆帧)
    ↓ OnNetMessage.Broadcast(msgid=8, payload)
ASightlineCharacter::OnServerMessage
    ↓ switch → DecodeHit → HandleHit(shooter,victim,25,newHp,dead)
    ├─ Victim == MyPlayerId → MyHP=newHp; dead → bIsDead=true
    ├─ Shooter == MyPlayerId && dead → (击杀确认)
    ↓
BP_OnHitReceived(...)      ← 蓝图子类覆盖:红闪/扣血 UI/音效
```

对照服务器侧《架构设计文档》第三节——**同一条消息，服务器的 11 步在网线那头结束，客户端这头 5 步接住**，全程蓝图只出现在最后一步。

## 四、四条设计铁律（后续贡献者必读）

1. **状态唯一写入口 = 服务器事件**：`MyPlayerId/MyHP/bIsDead` 全部 `VisibleAnywhere`，蓝图想写都没有引脚——"服务器权威"是编译期约束，不是注释；
2. **C++ 管状态，蓝图管表现**：每条 `Handle*` 末尾调对应 `BP_On*`；蓝图子类只覆盖钩子，不出现 if(身份)/不出现字节；
3. **配置下行、数据上行**：`EditDefaultsOnly` 给蓝图配参数（枪种/插值速度/名字/IP）；位置/血量/事件只能从 C++ 流向蓝图；
4. **网络收口**：会话级 IO 只在 Character（Move/Ping/Fire/登录），Weapon/RemotePawn/蓝图**零网络接触**——换传输层（KCP）时只动 Subsystem 与 Character 的发送行。

## 五、蓝图迁移指南（从旧纯蓝图结构 → C++ 基类）

### 5.0 双机事实与迁移基地选择（重要）

**本机（D 盘）的 Content 是传输时的原始状态**（`git diff init -- Content/` 为空，uasset mtime 停在 09-06），即：原始 FPS 蓝图 + C++ 基类，**没有** A~F 网络 Blueprint 工作——那部分在另一台机器的编辑器里（且未提交）。

**因此选定本机为迁移基地**：不需要删除旧的 A~F 网络图（它们在设计上就是要被 C++ 取代的脚手架），迁移量从"改父类+删图+重连"缩减为"改父类+新建薄蓝图+连表现"。另一台机器**放弃本地未提交的 Blueprint 网络改动**（`git checkout -- Content/` 或删目录重 clone），拉取后与本机同构。

## 六、扩展点：多模式与协议演进

- **新消息**（W3 道具 / W4 夺旗）：契约面登记 → 服务器 codec 加 msgid → `SightlineProto` 加 EMsg + Decode → `OnServerMessage` 加一个 case + `HandleXxx`——基类结构不变；
- **新玩法模式**：客户端无"模式"概念，只认消息；模式差异 = 新消息类型 + `BP_On*` 新钩子；
- **W6 客户端预测/校正**：`ReportMove` 升级为带输入序列号的预测提交，服务器校正通过新消息回传——落点在 Character 内部，接口不变；
- **KCP/protobuf**：只动 Subsystem 与 Proto，Character/Weapon/RemotePawn 零改动。

## 七、已知限制（诚实清单）

1. **阻塞式 Connect** 在主线程：本地/局域网毫秒级无感；公网高延迟环境会卡 BeginPlay 一小段（演进位：改异步连接）；
2. **单武器槽**：`CurrentWeapon` 单引用，多武器切换（1/2/3 键）待需求出现再加 `TArray` + 切换用例；
3. **本地开火特效与服务器判定结果可能不一致**（本地预测未做校正回滚）：打空也出弹孔——MVP 接受，W6 预测校正时统一解决；
4. **远程傀儡无动画状态机**：只有位置/朝向插值，动作表现待 M4 按需加。
