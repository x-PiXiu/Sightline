# UE 客户端蓝图接入操作手册（逐步截图级）

> 前置：已读完 `01-UE客户端现状分析与网络接入方案.md`，了解三层递进。
> 本文是 Step 2（蓝图叠加网络上报）的**逐步操作细节**——每个蓝图节点的具体连法。
> 如果你是 Agent：请让用户在 UE 编辑器中按此文档逐步操作，你负责读代码和排查。
> 如果你是开发者：直接照做，每步有验证点。

---

## 准备工作

1. 服务器已在跑：`wsl bash scripts/serve.sh 8888 debug`
2. UE 项目能编译打开（第 1 层已完成：C++ 子系统可被蓝图访问）
3. 打开 BP_FPSPlayer 蓝图编辑器

## 操作 A：连接与登录（BeginPlay）

### A1 找到 BeginPlay

打开 BP_FPSPlayer → Event Graph → 找到 Event BeginPlay 节点。

> 注意：可能已有 BeginPlay 逻辑（设置输入/初始化动画等）——**保留不动**，我们在其后追加。

### A2 添加子系统获取节点

右键搜索栏输入 `Get Game Instance Subsystem`：

- Class 下拉选 `Sightline Net Subsystem`
- 得到一个返回 SightlineNetSubsystem 引用的节点

### A3 连接服务器

从 Subsystem 引脚拖出 → 搜索 `Connect`：

- Ip 输入 `127.0.0.1`（String 节点）
- Port 输入 `8888`（Integer 节点）
- 返回值连一个 **Branch** 节点

### A4 登录 + 进房（Connect 成功后）

> **蓝图连线规则**：白色箭头 = 执行流（决定顺序），绿色/蓝色线 = 数据流（传值）。
> 所有 SightlineProto 的编码函数（EncLogin、EncMove 等）有执行引脚，**必须接入执行流**。

从 Branch 的 True 白色箭头拖出：

1. 搜索并放置 `Sightline Proto - Enc Login` 节点（Name 输入 `"UEPlayer"` String）
2. 从 Enc Login 的**右侧白色执行箭头**拖出 → 搜索 `Send Frame`（Subsystem 引用）
   - Msg Id = `1`（C2S_Login）
   - Payload：从 Enc Login 的**绿色返回值引脚**（TArray<uint8>）拖线 → 连到 Payload
3. 从 Send Frame 的**右侧白色执行箭头**拖出 → 再放一个 `Send Frame`
   - Msg Id = `3`（C2S_JoinRoom）
   - Payload：连一个 **Make Literal Array** 节点（不加任何元素 = 空数组）

连线总图：
```
Branch(True) ──白──► Enc Login("UEPlayer") ──白──► Send Frame(1, Payload)
                                              │
                                         绿色数据线
                                              │
                                              └──► Send Frame(3, 空数组)
```

### A5 验证

**PIE 运行**，观察：
- 服务器日志出现 `conn#N in from 127.0.0.1:xxxxx`（debug 模式下可见）
- 服务器日志随后出现 `msg 1` 和 `msg 3`（登录和进房）

如果没出现 → 检查 Connect 是否成功（Branch 的 False 引脚加一个 Print String "Connect Failed"）。

## 操作 B：绑定消息事件

### B1 创建自定义事件

Event Graph 空白处右键 → Add Custom Event → 命名 `OnServerMessage`。

给这个事件加两个输入参数：
- `MsgId`（Integer）
- `Payload`（Array of Byte）

### B2 绑定到子系统

从 Subsystem 引脚拖出 → 搜索 `Bind Event to On Net Message`：

- Event 引脚连 `OnServerMessage` 的引用（从事件节点左侧拖出）

同样创建 `OnServerDisconnect` 自定义事件（无参数），绑定到 `Bind Event to On Disconnected`。

把这两个 Bind 也连在 BeginPlay 的 Connect 成功之后（Sequence 节点按顺序执行）。

### B3 消息分发骨架

从 `OnServerMessage` 的 MsgId 引脚拖出 → `Switch on Integer`：

- Case 2：LoginAck → `Decode U32 (Payload, 0)` → 得到 PlayerId → `Print String`
- Case 4：RoomStart → 暂时空着（第 3 层再做）
- Case 6：MoveEvt → 暂时空着
- Case 8：Hit → 暂时空着
- Case 11：Pong → `Decode` 时间戳 → 计算差值 → Print RTT

### B4 验证

PIE 运行 → 屏幕应显示 `PlayerId: 1`（或递增的编号）。

## 操作 C：移动上报定时器

### C1 创建定时器事件

BeginPlay 里追加：

1. `Set Timer by Event`
   - Time = `0.1`（10Hz）
   - Looping = `true`

2. 创建自定义事件 `OnMoveTimer`，连到 Timer 的 Event 引脚

### C2 移动上报逻辑

从 `OnMoveTimer` 拖出：

1. `Get Actor Location` → 得到 FVector
2. `Get Actor Rotation` → `Break Rotator` → 取 Yaw（float）
3. 从 `Sightline Proto` 库调 `Enc Move`，传入 Location 和 Yaw
4. 从 Subsystem 调 `Send Frame`：MsgId = `5`，Payload = 上一步结果

### C3 验证

PIE 运行 → WASD 移动 → 服务器日志每秒出现约 10 条 `msg 5`。

**不要在 Tick 里发**——60FPS 发 60 次/秒太多了。UE 的 Tick 和 Set Timer 是独立的。

## 操作 D：心跳定时器

### D1 创建定时器

BeginPlay 里追加：

1. `Set Timer by Event`：Time = `2.0`，Looping = `true`
2. 创建自定义事件 `OnPingTimer`

### D2 Ping 逻辑

从 `OnPingTimer` 拖出：

1. `Get World Time Seconds`（float 秒）→ `Multiply by 1000` → `Truncate`（转 int64 毫秒）
2. 从 `Sightline Proto` 调 `Enc Ping`，传入时间戳
3. 从 Subsystem 调 `Send Frame`：MsgId = `10`

### D3 Pong 处理（在 OnServerMessage 的 Branch True，msgid==11 分支后）

> Pong 载荷：8 字节（int64 毫秒时间戳），客户端用"当前毫秒 - 回传值"算 RTT。
> 协议库已有 `Decode Pong` 节点可直接用，不需要手动拆两个 U32。

**步骤一：获取当前毫秒时间戳**

1. 右键搜索 **Get Game Time in Seconds** → 放节点（返回 float 秒）
2. 从返回值拖出 → 搜索 **Multiply** → 另一个输入填 `1000`（Float Literal）
3. 从结果拖出 → 搜索 **Truncate** → 转成 int64 毫秒

**步骤二：解码 Pong 回传时间戳**

1. 右键搜索 **Decode Pong**（Sightline|Proto 分类）→ 放节点（Pure 节点，无执行引脚）
2. OnServerMessage 的 **Payload** 引脚 → 连到 Decode Pong 的输入
3. Decode Pong 返回 int64（C++ 内部已处理8字节拼接）

**步骤三：计算 RTT**

1. 搜索 **Subtract**（减法，int64 类型）
2. **A** = 步骤一的"当前毫秒"（Truncate 输出）
3. **B** = 步骤二的"回传时间戳"（Decode Pong 输出）
4. 结果 = RTT（int64 毫秒）

**步骤四：显示**

1. 搜索 **To String (int64)** → 把 RTT 转成字符串
2. 搜索 **Append**（字符串拼接）→ `"RTT: "` + 数字 + `" ms"`
3. 搜索 **Print String** → 连上拼好的字符串
4. 从 Branch(True) 白色执行线 → 连到 Print String

**连线总图：**

```
Branch(True, msgid==11)
    │
    ▼
Decode Pong(Payload) ──int64──► Subtract(B)
                                    │
Get Game Time × 1000 → Truncate ──► Subtract(A)
                                    │
                                    ▼ int64
                               To String → Append("RTT:" + value + "ms")
                                    │
                                    ▼
                               Print String
```

### D4 验证

PIE 运行 → 屏幕滚动显示 RTT（局域网应 < 5ms）。

**如果 8 秒后收到 Kick(12)**：说明心跳没发出去——检查定时器是否正确启动。

## 操作 E：开火上报

### E1 找到开火逻辑

打开 BP_FPSPlayer → Event Graph → 找到 IA_Fire 触发的处理区域。

> 可能是通过 `EnhancedInputAction IA_Fire` 事件节点触发的。

### E2 在现有开火逻辑之后追加网络上报

不要删现有逻辑（动画/特效/本地判定），在其后追加：

1. `Get Control Rotation` → `Get Forward Vector` → 作为 Direction
2. `Get Actor Location` → 作为 Origin
3. 从 `Sightline Proto` 调 `Enc Fire`，传入 Origin 和 Direction
4. 从 Subsystem 调 `Send Frame`：MsgId = `7`

### E3 验证

PIE 运行 → 左键射击 → 服务器日志出现 `msg 7`。

## 操作 F：远端玩家 Pawn（BP_RemotePawn）

### F1 创建 BP_RemotePawn

1. 内容浏览器 → Content/Code/Player/ 右键 → Blueprint Class → Parent = **Pawn**
2. 命名 `BP_RemotePawn`
3. 添加组件：Static Mesh（先放个 Cube，后续换角色模型）
4. 添加变量：
   - `PlayerId`（Integer，Instance Editable）
   - `TargetLocation`（Vector）
   - `TargetYaw`（Float）

### F2 Tick 插值

BP_RemotePawn 的 Event Graph → Event Tick：

```
Event Tick (Delta Seconds)
    ↓
VInterp To
    Current = Get Actor Location
    Target  = Target Location
    Delta Time = Delta Seconds
    Interp Speed = 10.0
    ↓ (Return Value)
Set Actor Location
    ↓
RInterp To
    Current = Get Actor Rotation . Yaw
    Target  = Target Yaw
    Delta Time = Delta Seconds
    Interp Speed = 10.0
    ↓
Make Rotator (Yaw = Return Value)
    ↓
Set Actor Rotation
```

### F3 收到远端移动时的处理

回到 BP_FPSPlayer 的 OnServerMessage → Case 6 (MoveEvt)：

```
Payload 解析：
  Decode U32 (Payload, 0)  → 远端玩家的 PlayerId
  Decode F32 (Payload, 4)  → X
  Decode F32 (Payload, 8)  → Y（服务器系）或 Z（映射到 UE Z）
  Decode F32 (Payload, 12) → 第三个坐标
  Decode F32 (Payload, 16) → Yaw
    ↓
用 PlayerId 查找对应的 BP_RemotePawn 实例
    ↓
设置它的 TargetLocation = Make Vector(X, ?, ?)
设置它的 TargetYaw = Yaw
```

**坐标系问题**（详见 01 文档）：最简做法是**不映射**，服务器的 (x,y,z) 直接当 UE 的 (X,Y,Z) 用。如果位置不对，在 Make Vector 里调换分量顺序即可。

### F4 RoomStart 生成远端 Pawn

BP_FPSPlayer 的 OnServerMessage → Case 4 (RoomStart)：

```
Payload 解析：
  Decode U32 (Payload, 0)  → 玩家数量 N
  循环 i = 0..N-1：
    Decode U32 (Payload, 4 + i*4) → 第 i 个 PlayerId
      ↓
    如果 PlayerId ≠ 自己的 PlayerId：
      Spawn Actor of Class (BP_RemotePawn)
      设 PlayerId
      存到 Map（PlayerId → Pawn引用）
```

蓝图里的 Map：在 BP_FPSGameMode（或 BP_FPSPlayer）加变量 `RemotePawnMap`（Map<Integer, BP_RemotePawn Reference>）。

### F5 PlayerLeft 销毁

Case 13：

```
Decode U32 (Payload, 0) → 离开的 PlayerId
  ↓
RemotePawnMap . Find(PlayerId) → Pawn 引用
  ↓
Destroy Actor
RemotePawnMap . Remove(PlayerId)
```

### F6 双开验证

Play 下拉 → Number of Players = 2 → 两个窗口：

> **先做这一步，否则双开必然失败**：Play ▶ 按钮旁的下拉 → Multiplayer Options →
> **取消勾选 "Run Under One Process"**。
> 原因：默认勾选时所有 PIE 实例跑在同一进程、共享同一个 GameInstance → 共享同一个
> SightlineNetSubsystem → 两个窗口共用一个 socket（第二个 BeginPlay 的 Connect 会拆掉
> 第一个的连接），症状是"只有一个窗口连上/共用一个 playerId"。取消后每个实例独立进程、
> 独立 GameInstance、独立连接。（Net Mode 依然保持 Standalone，两者不冲突。）

| 动作 | 预期 |
|------|------|
| 窗口 A WASD 移动 | 窗口 B 里 A 的 Cube 平滑跟随 |
| 窗口 B 左键射击 | A 受击 → 屏幕红闪/扣血 |
| A 被打 4 次 | A 死亡 → 3 秒重生（服务器控制） |
| A 关闭窗口 | B 里 A 的 Cube 消失（PlayerLeft） |
| 打满 3 杀 | GameOver → 5 秒后自动重开（Rematch） |

## 完整蓝图节点连线总图（ASCII 概览）

```
Event BeginPlay
  ├── [现有逻辑不动]
  ├── Get Subsystem → Connect(127.0.0.1, 8888) → Branch
  │     └── True:
  │           ├── SendFrame(1, EncLogin("UEPlayer"))
  │           ├── SendFrame(3, [])
  │           ├── BindEvent(OnNetMessage → OnServerMessage)
  │           ├── BindEvent(OnDisconnected → OnServerDisconnect)
  │           ├── SetTimer(0.1s, OnMoveTimer, Loop)
  │           └── SetTimer(2.0s, OnPingTimer, Loop)
  │
  ├── OnMoveTimer (10Hz)
  │     └── EncMove(Location, Yaw) → SendFrame(5)
  │
  ├── OnPingTimer (2s)
  │     └── EncPing(TimeMs) → SendFrame(10)
  │
  ├── IA_Fire 触发
  │     ├── [现有开火逻辑不动]
  │     └── EncFire(Origin, Dir) → SendFrame(7)
  │
  └── OnServerMessage(MsgId, Payload)
        ├── Case 2:  DecodeU32 → PlayerId → Print/存变量
        ├── Case 4:  解析玩家列表 → Spawn BP_RemotePawn ×(N-1)
        ├── Case 6:  解析pid/pos/yaw → RemotePawn.TargetLocation = ...
        ├── Case 8:  解析shooter/victim/dmg/hp → 扣血UI/命中标记
        ├── Case 9:  GameOver → 显示胜负
        ├── Case 11: Pong → 计算RTT → 显示
        ├── Case 12: Kick → "被踢" UI
        ├── Case 13: PlayerLeft → Destroy RemotePawn
        └── Case 14: Respawn → 重置位置/血量
```
