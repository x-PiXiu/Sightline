## 操作 A：连接与登录（BeginPlay）

### A1 找到 BeginPlay

打开 BP_FPSPlayer → Event Graph → 找到 Event BeginPlay 节点。

> 注意：可能已有 BeginPlay 逻辑（设置输入/初始化动画等）——**保留不动**，我们在其后追加。

### A2 添加子系统获取节点

右键搜索栏输入 `Get Game Instance Subsystem`：

- Class 下拉选 `Sightline Net Subsystem`
- 得到一个返回 SightlineNetSubsystem 引用的节点

### A3 连接服务器

从 Subsystem 引脚拖出 → 搜索 `Connect`：

- Ip 输入 `127.0.0.1`（String 节点）
- Port 输入 `8888`（Integer 节点）
- 返回值连一个 **Branch** 节点

### A4 登录 + 进房（Connect 成功后）

> **蓝图连线规则**：白色箭头 = 执行流（决定顺序），绿色/蓝色线 = 数据流（传值）。
> 所有 SightlineProto 的编码函数（EncLogin、EncMove 等）有执行引脚，**必须接入执行流**。

从 Branch 的 True 白色箭头拖出：

1. 搜索并放置 `Sightline Proto - Enc Login` 节点（Name 输入 `"UEPlayer"` String）
2. 从 Enc Login 的**右侧白色执行箭头**拖出 → 搜索 `Send Frame`（Subsystem 引用）
   - Msg Id = `1`（C2S_Login）
   - Payload：从 Enc Login 的**绿色返回值引脚**（TArray<uint8>）拖线 → 连到 Payload
3. 从 Send Frame 的**右侧白色执行箭头**拖出 → 再放一个 `Send Frame`
   - Msg Id = `3`（C2S_JoinRoom）
   - Payload：连一个 **Make Literal Array** 节点（不加任何元素 = 空数组）

连线总图：
```
Branch(True) ──白──► Enc Login("UEPlayer") ──白──► Send Frame(1, Payload)
                                              │
                                         绿色数据线
                                              │
                                              └──► Send Frame(3, 空数组)
```

### A5 验证

**PIE 运行**，观察：
- 服务器日志出现 `conn#N in from 127.0.0.1:xxxxx`（debug 模式下可见）
- 服务器日志随后出现 `msg 1` 和 `msg 3`（登录和进房）

如果没出现 → 检查 Connect 是否成功（Branch 的 False 引脚加一个 Print String "Connect Failed"）。

## 操作 B：绑定消息事件

### B1 创建自定义事件

Event Graph 空白处右键 → Add Custom Event → 命名 `OnServerMessage`。

给这个事件加两个输入参数：
- `MsgId`（Integer）
- `Payload`（Array of Byte）

### B2 绑定到子系统

从 Subsystem 引脚拖出 → 搜索 `Bind Event to On Net Message`：

- Event 引脚连 `OnServerMessage` 的引用（从事件节点左侧拖出）

同样创建 `OnServerDisconnect` 自定义事件（无参数），绑定到 `Bind Event to On Disconnected`。

把这两个 Bind 也连在 BeginPlay 的 Connect 成功之后（Sequence 节点按顺序执行）。

### B3 消息分发骨架

从 `OnServerMessage` 的 MsgId 引脚拖出 → `Switch on Integer`：

- Case 2：LoginAck → `Decode U32 (Payload, 0)` → 得到 PlayerId → `Print String`
- Case 4：RoomStart → 暂时空着（第 3 层再做）
- Case 6：MoveEvt → 暂时空着
- Case 8：Hit → 暂时空着
- Case 11：Pong → `Decode` 时间戳 → 计算差值 → Print RTT

### B4 验证

PIE 运行 → 屏幕应显示 `PlayerId: 1`（或递增的编号）。

## 操作 C：移动上报定时器

### C1 创建定时器事件

BeginPlay 里追加：

1. `Set Timer by Event`
   - Time = `0.1`（10Hz）
   - Looping = `true`

2. 创建自定义事件 `OnMoveTimer`，连到 Timer 的 Event 引脚

### C2 移动上报逻辑

从 `OnMoveTimer` 拖出：

1. `Get Actor Location` → 得到 FVector
2. `Get Actor Rotation` → `Break Rotator` → 取 Yaw（float）
3. 从 `Sightline Proto` 库调 `Enc Move`，传入 Location 和 Yaw
4. 从 Subsystem 调 `Send Frame`：MsgId = `5`，Payload = 上一步结果

### C3 验证

PIE 运行 → WASD 移动 → 服务器日志每秒出现约 10 条 `msg 5`。

**不要在 Tick 里发**——60FPS 发 60 次/秒太多了。UE 的 Tick 和 Set Timer 是独立的。

## 操作 D：心跳定时器

### D1 创建定时器

BeginPlay 里追加：

1. `Set Timer by Event`：Time = `2.0`，Looping = `true`
2. 创建自定义事件 `OnPingTimer`

### D2 Ping 逻辑

从 `OnPingTimer` 拖出：

1. `Get World Time Seconds`（float 秒）→ `Multiply by 1000` → `Truncate`（转 int64 毫秒）
2. 从 `Sightline Proto` 调 `Enc Ping`，传入时间戳
3. 从 Subsystem 调 `Send Frame`：MsgId = `10`

### D3 Pong 处理（在 OnServerMessage 的 Branch True，msgid==11 分支后）

> Pong 载荷：8 字节（int64 毫秒时间戳），客户端用"当前毫秒 - 回传值"算 RTT。
> 协议库已有 `Decode Pong` 节点可直接用，不需要手动拆两个 U32。

**步骤一：获取当前毫秒时间戳**

1. 右键搜索 **Get Game Time in Seconds** → 放节点（返回 float 秒）
2. 从返回值拖出 → 搜索 **Multiply** → 另一个输入填 `1000`（Float Literal）
3. 从结果拖出 → 搜索 **Truncate** → 转成 int64 毫秒

**步骤二：解码 Pong 回传时间戳**

1. 右键搜索 **Decode Pong**（Sightline|Proto 分类）→ 放节点（Pure 节点，无执行引脚）
2. OnServerMessage 的 **Payload** 引脚 → 连到 Decode Pong 的输入
3. Decode Pong 返回 int64（C++ 内部已处理8字节拼接）

**步骤三：计算 RTT**

1. 搜索 **Subtract**（减法，int64 类型）
2. **A** = 步骤一的"当前毫秒"（Truncate 输出）
3. **B** = 步骤二的"回传时间戳"（Decode Pong 输出）
4. 结果 = RTT（int64 毫秒）

**步骤四：显示**

1. 搜索 **To String (int64)** → 把 RTT 转成字符串
2. 搜索 **Append**（字符串拼接）→ `"RTT: "` + 数字 + `" ms"`
3. 搜索 **Print String** → 连上拼好的字符串
4. 从 Branch(True) 白色执行线 → 连到 Print String

**连线总图：**

```
Branch(True, msgid==11)
    │
    ▼
Decode Pong(Payload) ──int64──► Subtract(B)
                                    │
Get Game Time × 1000 → Truncate ──► Subtract(A)
                                    │
                                    ▼ int64
                               To String → Append("RTT:" + value + "ms")
                                    │
                                    ▼
                               Print String
```

### D4 验证

PIE 运行 → 屏幕每 2 秒滚动显示 RTT。
- Windows↔WSL2 localhost 转发：**19-25ms 正常**（Hyper-V 虚拟网卡开销，非 bug）
- 两台真机局域网：1-5ms
- 首次 100ms+ 尖刺属冷启动，后续稳定即正常

**如果 8 秒后收到 Kick(12)**：说明心跳没发出去——检查定时器是否正确启动。

## 操作 E：开火上报

### E1 找到开火逻辑

打开 **BP_WeaponBase** → Event Graph → 找到 **StartWeaponFire** 自定义事件。

> 实际架构：`IA_Fire → BP_FPSPlayer → BP_WeaponBase.StartWeaponFire → 本地开火逻辑`
> 网络上报加在 BP_WeaponBase 里（枪口位置比角色中心更准）。

### E2 在现有开火逻辑之后追加网络上报

不要删现有逻辑（动画/特效/本地射线判定），在 StartWeaponFire 的**最后**追加：

```
[现有开火逻辑（动画/特效/射线检测）]
    │
    ▼ (白色执行线接在最后)
Get Owner → Get Control Rotation → Get Forward Vector → Direction
Get Actor Location → Origin
    │
    ▼
Enc Fire(Origin, Direction) ──返回值──► Send Frame(7, Payload)
```

> **注意**：`Get Actor Location` 获取的是**枪口位置**（BP_WeaponBase 的位置），
> 比从 BP_FPSPlayer 获取更准。`Get Owner` 获取持有者 Player，
> 再 `Get Control Rotation` 拿射击方向（与现有射线检测用的方向一致）。
> 如果 StartWeaponFire 里已经有射击方向变量（如 TraceStart/TraceEnd），
> 直接复用那个方向，不用再算一次。

### E3 验证

PIE 运行 → 左键射击 → 服务器日志出现 `msgid=7 payload=24B pid=N`。

## 操作 F：远端玩家 Pawn（BP_RemotePawn）

### F1 创建 BP_RemotePawn

1. 内容浏览器 → Content/Code/Player/ 右键 → Blueprint Class → Parent = **Pawn**
2. 命名 `BP_RemotePawn`
3. 添加组件：Static Mesh（先放个 Cube，后续换角色模型）
4. 添加变量：
   - `PlayerId`（Integer，Instance Editable）
   - `TargetLocation`（Vector）
   - `TargetYaw`（Float）

### F2 Tick 插值

BP_RemotePawn 的 Event Graph → Event Tick：

```
Event Tick (Delta Seconds)
    ↓
VInterp To
    Current = Get Actor Location
    Target  = Target Location
    Delta Time = Delta Seconds
    Interp Speed = 10.0
    ↓ (Return Value)
Set Actor Location
    ↓
RInterp To
    Current = Get Actor Rotation . Yaw
    Target  = Target Yaw
    Delta Time = Delta Seconds
    Interp Speed = 10.0
    ↓
Make Rotator (Yaw = Return Value)
    ↓
Set Actor Rotation
```

### F0 BP_FPSPlayer 新增变量（F3/F4/F5 的前置准备）

在 BP_FPSPlayer 蓝图编辑器左上角 **My Blueprint** 面板 → 点 **+** 添加两个变量：

| 变量名 | 类型 | 作用 |
|---|---|---|
| `MyPlayerId` | **Integer** | 存自己的 playerId，RoomStart 时判断"哪个是自己" |
| `RemotePawnMap` | **Map<Integer, BP_RemotePawn>** | PlayerId → RemotePawn 映射表，MoveEvt 时查找用 |

**设置 MyPlayerId**：回到 OnServerMessage 的 Branch(msgid==2, LoginAck) 分支：

```
Branch(True, msgid==2)
    │
    ▼
Decode Login Ack(Payload) ──int32──► Set MyPlayerId
    │
    ▼
Print String("PlayerId:" + ToString)
```

**Map 变量创建方法**：My Blueprint → + → Variable → 类型下拉选 **Integer** → 旁边点开下拉选 **Map**（变成 Map<Integer, ???） → 值类型改为 **BP_RemotePawn**（Object Reference）。

### F3 收到远端移动时的处理

回到 BP_FPSPlayer 的 OnServerMessage → Case 6 (MoveEvt)：

```
Branch(True, msgid==6)
    │
    ▼
Decode Move(Payload) ──→ 输出三个值：PlayerId(int32), Pos(FVector), Yaw(float)
    │
    ▼
Branch ── Condition: PlayerId ≠ MyPlayerId    ← 排除自己（不给自己插值）
    │True
    ▼
RemotePawnMap → Find(PlayerId) ──→ 输出 BP_RemotePawn 引用
    │
    ▼
IsValid ──► True: Set Target Location(Pos) + Set Target Yaw(Yaw)
```

**连线细节**：
1. 从 Branch(True, msgid==6) 拖出 → 搜索 **Decode Move**（SightlineProto 分类，Pure 节点）
2. OnServerMessage 的 **Payload** 连 Decode Move 的输入
3. Decode Move 有三个输出：`Out PlayerId`、`Out Pos`、`Out Yaw`（C++ 里已做坐标换轴）
4. 搜索 **Not Equal (Integer)** → A = Decode Move 的 PlayerId，B = MyPlayerId 变量
5. 结果连 Branch 的 Condition
6. Branch(True) → 从 **RemotePawnMap** 变量拖出 → 搜索 **Find** → Key = Decode Move 的 PlayerId
7. Find 输出一个 BP_RemotePawn 引用 → **IsValid** 判断（防止 Map 里没有）
8. IsValid(True) → 拖出引用 → 搜索 **Set Target Location** + **Set Target Yaw**

### F4 RoomStart 生成远端 Pawn

BP_FPSPlayer 的 OnServerMessage → Case 4 (RoomStart)：

```
Branch(True, msgid==4)
    │
    ▼
Decode Room Start(Payload) ──→ TArray<int32> 玩家列表
    │
    ▼
For Each Loop（遍历每个 PlayerId）
    │
    ├── Branch: Array Element ≠ MyPlayerId
    │     │True
    │     ▼
    │   Spawn Actor from Class(BP_RemotePawn) → Location=(0,0,0)
    │     │
    │     ▼
    │   Set PlayerId（在 Spawn 出的 Pawn 上）
    │     │
    │     ▼
    │   RemotePawnMap → Add(Key=Array Element, Value=Spawned Pawn)
    │
    └── False（是自己，跳过）
```

**连线细节**：
1. 从 Branch(True, msgid==4) 拖出 → 搜索 **Decode Room Start**（Pure 节点）
2. Payload 连 Decode Room Start 输入 → 输出 `TArray<int32>` 玩家列表
3. 搜索 **For Each Loop** → Array 连玩家列表
4. Loop Body → 搜索 **Not Equal (Integer)** → A = Array Element，B = MyPlayerId
5. 结果连 Branch → True 后面：
6. 搜索 **Spawn Actor from Class** → Class 选 BP_RemotePawn → Location 填 (0,0,0)
7. 搜索 **Set PlayerId**（BP_RemotePawn 上的变量）→ 连 Array Element
8. **RemotePawnMap** 拖出 → 搜索 **Add** → Key = Array Element，Value = Spawn Actor 的返回值

### F5 PlayerLeft 销毁

Case 13（在 OnServerMessage 的 Branch 链末尾追加）：

```
Branch(True, msgid==13)
    │
    ▼
Decode Player Left(Payload) ──→ int32 离开的 PlayerId
    │
    ▼
RemotePawnMap → Find(PlayerId) ──→ BP_RemotePawn 引用
    │
    ▼
IsValid ──► True:
    │         Destroy Actor（引用）
    │         RemotePawnMap → Remove(PlayerId)
    │
    └──► False: 不存在，忽略
```

### F6 双开验证

Play 下拉 → Number of Players = 2 → 两个窗口：

> **先做这一步，否则双开必然失败**：Play ▶ 按钮旁的下拉 → Multiplayer Options →
> **取消勾选 "Run Under One Process"**。
> 原因：默认勾选时所有 PIE 实例跑在同一进程、共享同一个 GameInstance → 共享同一个
> SightlineNetSubsystem → 两个窗口共用一个 socket（第二个 BeginPlay 的 Connect 会拆掉
> 第一个的连接），症状是"只有一个窗口连上/共用一个 playerId"。取消后每个实例独立进程、
> 独立 GameInstance、独立连接。（Net Mode 依然保持 Standalone，两者不冲突。）

| 动作 | 预期 |
|------|------|
| 窗口 A WASD 移动 | 窗口 B 里 A 的 Cube 平滑跟随 |
| 窗口 B 左键射击 | A 受击 → 屏幕红闪/扣血 |
| A 被打 4 次 | A 死亡 → 3 秒重生（服务器控制） |
| A 关闭窗口 | B 里 A 的 Cube 消失（PlayerLeft） |
| 打满 3 杀 | GameOver → 5 秒后自动重开（Rematch） |

## 操作 G：战斗表现（M3 里程碑）

> M3 目标：双开对射，血量按服务器判定扣减；4 枪击杀 → 3 秒重生 → 再战 → 3 杀胜负。
> 服务器的判定逻辑（hitscan/伤害/重生/胜负）全部已完成，客户端只需接收事件并驱动表现。

### G0 BP_FPSPlayer 新增变量

在 My Blueprint 面板新增：

| 变量名 | 类型 | 作用 |
|---|---|---|
| `MyHP` | **Integer** | 当前血量，Hit 时扣减，Respawn 时复位 |
| `IsDead` | **Boolean** | 死亡标记，死亡期间禁止开火上报 |

### G1 处理命中（Case 8，OnServerMessage Branch 链追加）

```
Branch(True, msgid==8)
    │
    ▼
Decode Hit(Payload) ──→ Shooter(int32), Victim(int32), Damage(int32), VictimHp(int32), Dead(bool)
    │
    ├── 判断：Victim == MyPlayerId（我是被打的人）
    │     │True
    │     ▼
    │   Set MyHP = VictimHp
    │   Print String("受到 " + Damage + " 伤害，剩余 HP: " + VictimHp)
    │     │
    │     ├── Branch: Dead == true
    │     │     │True
    │     │     ▼
    │     │   Set IsDead = true
    │     │   Print String("你被击杀了！3 秒后重生...")
    │     │   （可选：屏幕红闪/死亡 UI 后续 M4 做）
    │     │
    │     └── Dead == false
    │           └── （可选：受击红闪特效，M4 再做）
    │
    └── 判断：Shooter == MyPlayerId（我是开枪的人）且 Dead == true
          │True
          ▼
        Print String("击杀！")
```

**连线细节**：
1. 从 Branch(True, msgid==8) 拖出 → 搜索 **Decode Hit**（Pure 节点）
2. Payload 连 Decode Hit 输入 → 五个输出：Shooter/Victim/Damage/VictimHp/Dead
3. 搜索 **Equal (Integer)** → A = Victim，B = MyPlayerId → 连 Branch
4. Branch(True) → **Set MyHP**（= VictimHp）+ Print String
5. 从 Print String 后 → 搜索 **Equal (Boolean)** → A = Dead → Branch
6. Branch(True) → **Set IsDead = true** + Print String("被击杀")
7. 回到步骤 3 的 Branch(False) → 再判断 Shooter == MyPlayerId AND Dead == true → Print("击杀")

### G2 处理重生（Case 14）

```
Branch(True, msgid==14)
    │
    ▼
Decode Respawn(Payload) ──→ PlayerId(int32), Pos(FVector), Hp(int32)
    │
    ▼
Branch: PlayerId == MyPlayerId
    │True
    ▼
  Set MyHP = Hp（复位到 100）
  Set IsDead = false
  Set Actor Location(Pos)   ← 传送到重生点
  Print String("重生！HP: " + Hp)
```

**连线细节**：
1. 从上一个 Case 的 Branch(False) 拖出 → Branch(msgid==14)
2. 搜索 **Decode Respawn**（Pure 节点）→ Payload 输入
3. 三个输出：PlayerId/Pos/Hp
4. Branch: PlayerId == MyPlayerId → True 后面：
5. **Set MyHP** = Hp，**Set IsDead** = false
6. **Set Actor Location**（BP_FPSPlayer 自身）→ New Location = Pos
7. Print String("重生！HP:" + Hp)

### G3 处理胜负（Case 9）

```
Branch(True, msgid==9)
    │
    ▼
Decode Game Over(Payload) ──→ Winner(int32)
    │
    ▼
Branch: Winner == MyPlayerId
    │True           │False
    ▼               ▼
Print String      Print String
("你赢了！")      ("获胜者: Player " + Winner)
```

### G5 开火时检查死亡状态

回到 BP_WeaponBase 的 **StartWeaponFire**，在现有逻辑最前面加一个 Branch：

```
Event StartWeaponFire
    │
    ▼
Get BP_FPSPlayer(Owner) → Get IsDead
    │
    ▼
```
