# 13 · 武器系统模块协作与数据流

> **定位**：以武器系统为中枢，梳理它与各模块的数据传输关系和协作时序；
> 并记录 Definition 数据驱动架构（P8 地基）的落地实现。
> **前置阅读**：类图基础见本文第一节；操作步骤见 12 手册模块 D。
> **对应代码**：`SightlineWeapon.h/.cpp`、`SightlineWeaponDefinition.h/.cpp`、`SightlineCharacter.cpp`

---

## 一、武器中枢全景图

武器是**表现层的中枢**：对上承接角色的装备与输入，对下驱动资产与子系统，对远端傀儡只同步事实不同步表现。

```
                        ┌────────────────────────┐
                        │  BP_FPSGameMode        │
                        │  .DefaultPawnClass     │
                        └───────────┬────────────┘
                                生成 │
┌──────────────────────┐   ┌──────────▼─────────────┐
│ BP_Weapon_Rifle      │◀──┤ BP_LyPlayer (角色)      │
│ (继承BP_Weapon_Base) │装备│ (继承ASightlineCharacter)│
└──────────┬───────────┘   └──────────┬──────────────┘
           │                          │
  ┌────────▼─────────┐       ┌────────▼─────────┐      ┌──────────────────┐
  │ USightlineWeapon │ 上报   │ GameState 组件    │      │ RemotePawnMgr     │
  │ (C++ 行为)        │──────▶│ 状态单一真源       │      │ 远端傀儡表          │
  └────────┬─────────┘ C2S_Fire└────────┬─────────┘      └──────────────────┘
           │                           │ S2C_* 落地
  ┌────────▼─────────┐          ┌───────▼──────────┐
  │ DA_Weapon_Rifle  │          │ NetSubsystem      │◀─── Sightline 服务器
  │ (Definition 数据) │          │ (收发/拆包/委托)    │
  └──────────────────┘          └───────────────────┘
```

## 二、武器系统 ↔ 各模块的数据传输关系表

| 模块 | 传输方向 | 传什么 | 机制 | 说明 |
|---|---|---|---|---|
| **Character（角色）** | 角色 → 武器 | 装备（Owner）、开火意图 | `EquipWeapon()` 设 Owner；输入蓝图调 `StartFire/Reload` | 武器经 `GetOwningCharacter()` 反向只读角色（CanFire 判活） |
| | 武器 → 角色 | 装备完成通知 | `BP_OnWeaponEquipped(W)` 钩子 | 角色在钩子里把武器挂到 hand_r |
| **GameState（状态）** | 武器 → 状态 | 开火意图的上报由 Character 收口（`ReportFire`），武器**不直接碰网络** | — | 职责契约：武器表达意图，角色管网络 |
| | 状态 → 角色 | 换弹开始事件 | `BP_OnReloadStarted`（GameState 钩子） | 角色播**手臂**蒙太奇（读武器 `GetArmReloadMontage()`） |
| **Definition（数据）** | DA → 武器 | 网格/动画类/音效/枪口偏移 | BeginPlay 回填资产槽（Definition 优先） | 一把枪 = 一个 DA，数据单源 |
| | DA → 角色 | 手臂蒙太奇 | `GetCurrentWeapon → GetArmReloadMontage()` | 加新枪角色侧零改动 |
| **DecalPool（贴画池）** | 武器(BP) → 池 | 命中点/法线/表面类型对应的材质 | `BP_OnShotImpact` → `SpawnDecal()` | 池化零 GC；预热由武器 BeginPlay 触发 |
| | DA_SightlineImpactFX → 武器BP | 表面 → 表现包 | `TryGetImpactFX(SurfaceType)` | 按表面分流 |
| **ItemActor（道具）** | 道具拾取 → 武器 | 加弹量 | Character 的 `HandleItemTaken` → `AddReserveAmmo()` | 弹药客户端本地非权威 |
| **HUD（UI）** | 武器 → HUD | 弹匣/备弹数 | `BP_OnAmmoChanged` 推送（现状：WBP_HUD 轮询绑定，待迁移） | 推模式实时且省每帧调用 |
| **RemotePawn（傀儡）** | 无直接传输 | — | — | 傀儡的动作同步走 Move 协议（flags/pitch），与武器实例无关；傀儡手里的枪是纯静态模型 |
| **NetSubsystem（网络）** | 间接 | C2S_Fire | Character 的 `ReportFire` → `SendFrame` | 武器与网络层隔两层，永不见面 |

## 三、三条核心时序

### 3.1 开火链路（输入 → 表现 → 网络）

```
鼠标左键 (IA_Fire, 蓝图)
  → Weapon.StartFire()                        [C++]
      → CanFire? (GameState: 已登录+未死)      [C++]
      → 冷却/弹药检查 → ConsumeAmmo            [C++]
      │    └▶ BP_OnAmmoChanged ─▶ HUD 刷新     [蓝图]
      → ReportFire(Origin, Dir) ──▶ 服务器      [C++, 唯一网络出口]
      → 枪声 + 枪口火焰 + 弹壳（资产槽自动播放）  [C++]
      → GunFireMontage（Definition）            [C++]
      → 表现层 trace → ▶ BP_OnShotImpact        [C++→蓝图]
      │    └→ SpawnDecal / 音效 / 碎屑           [蓝图, 查贴画DA]
      → ▶ BP_OnFireEffects                     [C++→蓝图, 可空]
服务器 → hitscan 判定 → S2C_Hit → 双方表现
```

### 3.2 换弹链路（含手臂联动——两段动画各自播）

```
按 R (IA_Reload, 蓝图)
  → Weapon.Reload()                          [C++]
      → 播 ReloadSound（Definition 提供）      [C++]
      → GunReloadMontage（枪身弹匣抽插）        [C++, Definition]
      → ▶ BP_OnReloadStarted（武器钩子）       [C++→蓝图]
      └→ 换弹计时器 → FinishReload
           → ▶ BP_OnAmmoChanged              [C++→蓝图]

同时（角色侧，同一事件的不同接收者）：
  GameState.BP_OnReloadStarted               [蓝图, BP_LyPlayer]
      → GetCurrentWeapon → GetArmReloadMontage
      → CharacterMesh0.PlayAnimMontage(手臂换弹)  ← 加新枪零改动
```

### 3.3 弹药箱链路（P2）

```
走过道具 → 服务器判定 → S2C_ItemTaken(typeId=2)
  → Character.HandleItemTaken
      → 自己捡的：GetCurrentWeapon.AddReserveAmmo(DA.AmmoAmount)
           → ▶ BP_OnAmmoChanged → HUD（与开火共用同一刷新链）
```

## 四、Definition 数据驱动架构（P8 地基）

### 4.1 类图

```
┌────────────────────────────────┐
│ USightlineWeaponDefinition     │  ← DataAsset：一把枪 = 一个实例
│ (DA_Weapon_Rifle / _Pistol...) │
├────────────────────────────────┤
│ 外观: Mesh / AnimClass /        │──┐
│       MuzzleOffset / CasingOffset│  │
│       MuzzleOffset              │  │ BeginPlay 回填
│ 音效: FireSound / ReloadSound   │──┤ ASightlineWeapon 资产槽
│ 枪身蒙太奇: GunFire / GunReload  │  │ (Definition 非空字段优先)
│ 手臂蒙太奇: ArmFire / ArmReload  │  │ GetArm*Montage() → 角色侧
│ [P8预留] 伤害/射速/弹匣 → 服务端   │  │
└────────────────────────────────┘  │
                                    │
┌────────────────────────────────┐  │
│ ASightlineWeapon               │──┘
│  + Definition (EditDefaultsOnly│
│                 BlueprintReadOnly)│
└────────────────────────────────┘
```

### 4.2 优先级规则

```
BeginPlay 资产槽解析顺序：Definition 非空字段 > 蓝图类默认值直填
（允许只配 Definition；也允许无 Definition 的裸蓝图武器——向后兼容）
```

### 4.3 自动播放矩阵（蓝图节点需求被压到最少）

| 表现 | 谁播 | 数据源 |
|---|---|---|
| 枪声 / 换弹音 | C++ 自动 | Definition.FireSound / ReloadSound |
| 枪口火焰 | C++ 自动（常驻组件） | MuzzleFlashTemplate（武器槽） |
| 弹壳 | C++ 自动（对象池 + CasingSocket 抛壳口锚点弹出，随机散布） | CasingClass（武器槽）+ Definition.CasingOffset |
| **枪身开火/换弹蒙太奇** | **C++ 自动** | Definition.GunFire/GunReloadMontage |
| **手臂换弹蒙太奇** | 角色蓝图（读武器） | Definition.ArmReloadMontage |
| 贴画/碎屑/命中音 | 武器蓝图 BP_OnShotImpact | DA_SightlineImpactFX（按表面） |
| 手臂走跑蹲/瞄准 | 共用 ABP（Phase 1） | Lyra 动画 + 协议状态 |

**蓝图事件的实际需求被压到只剩 2 个**：`BP_OnShotImpact`（贴画）和 `BP_OnAmmoChanged`（HUD）——都进 BP_Weapon_Base 写一次，子类永久继承。

## 五、多武器扩展步骤（未来加 Pistol 为例，约 30 分钟）

1. `Content/Code/DataAssets/` → 右键 → 杂项 → Data Asset → `SightlineWeaponDefinition` → `DA_Weapon_Pistol` → 填 SK_Pistol / 音效 / 蒙太奇；
2. `Content/Code/Weapon/` → 右键 → 蓝图类 → 父类 **BP_Weapon_Base** → `BP_Weapon_Pistol`；
3. Class Defaults → **Definition** = `DA_Weapon_Pistol`（唯一必填项）；
4. `BP_LyPlayer` → Class Defaults → Default Weapon Class 换/或做武器切换逻辑（`EquipWeapon`）；
5. **零事件节点、零 C++ 改动、角色侧零改动**。

## 六、蓝图事件速查（武器四钩子的最终分工）

| 事件 | 实现位置 | 内容 | 新武器需要动吗 |
|---|---|---|---|
| `BP_OnShotImpact` | **BP_Weapon_Base**（写一次） | 贴画三件套 | ❌ 继承即得 |
| `BP_OnAmmoChanged` | BP_Weapon_Base（可选，HUD 现为轮询） | HUD 刷新 | ❌ 继承即得（若接线） |
| `BP_OnReloadStarted` | 留空（枪身蒙太奇已由 C++ 自动播） | 额外表现才接 | ❌ |
| `BP_OnFireEffects` | 留空（标准表现已由 C++ 自动播） | 曳光等未来特性 | ❌ |

## 七、音效变体与资产加载时序（两问补充）

### 7.1 音效多随机变体：DA 字段已天然支持

`FireSound` 类型是 `USoundBase` 基类——SoundCue / MetaSoundSource 都是它的子类：

| 做法 | 说明 |
|---|---|
| SoundCue 随机 | 一个 Cue 挂 N 个 Wave + Random 节点（可加权）；右键多选 Wave → Create Cue 自动生成 |
| MetaSound 随机 | Random Get 节点随机取波形（Lyra 同款体系） |
| C++ 数组随机 | ❌ 不推荐——把变体管理搬进代码，还需改 Definition 结构 |

**原则**：DA 存"一个可播放资产"，变体封装在资产内部（Cue/MetaSound 随机节点），
代码零改动。仅当玩法需运行时控制参数（动态音高/音量）才动代码。

### 7.2 DA 素材的运行时行为：加载 vs 生灭是两类成本

**硬引用链同步加载**：GameMode→BP_LyPlayer→BP_Weapon_Rifle→DA_Weapon_Rifle→
全部引用资产，随链路在**角色生成前**已进内存——开火播声、换弹播蒙太奇都是
引用内存对象，零加载。因此声音/网格/蒙太奇**不需要池**。

**池只解决生灭成本**（运行时反复分配+GC）：弹壳 Actor ×10、贴画组件 ×64 已池化。

| 剩余首次开销 | 现状 |
|---|---|
| Niagara 编译 | 已修：装备时 SetAsset 发起（案例 01） |
| PSO 首渲染 | 编辑器固有；打包 + PSO 缓存根治 |
| 音频流送 | 武器音效小，默认即可；大文件关 Streaming |

**P8 演进**：多枪后 Definition 资产改 `TSoftObjectPtr` + 装备时 AsyncLoad——
未装备的枪不占内存，切枪微等待。一把枪时代硬引用是对的（省异步复杂度）。
