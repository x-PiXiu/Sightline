# 11 · 远端傀儡动画同步方案（持枪 + 下蹲 + 瞄准）

> **目标**：远端玩家在对方客户端上看到的动作与本机一致——端枪走/跑、蹲下移动、
> 抬头低头瞄准。**本机玩家视角不动**（第一人称保持现状，后续单独做）。
>
> **素材来源**：Lyra Starter Game（Epic 5.7，与本工程同引擎版本，许可允许在 UE 项目中使用）。
> 操作手册：[`09`/`10` 手册](09-击中贴画系统操作手册.md) 的“素材迁移”章节可直接复用。
>
> **实施节奏**：协议一次改完（加尾不改头），表现分三期验证，每期独立可演示。
>
> **对应代码**：服务端 `dto.h` / `protocol_codec.h` / `room.h`；客户端 `SightlineRemotePawn` / `SightlineSessionComponent` / 新建 `ABP_RemotePawn`。

## 一、当前状态与差距分析

### 1.1 当前傀儡能做什么

```
远端玩家本机                        对方客户端
───────────                        ──────────
移动位置 ──C2S_Move──▶ 服务器 ──S2C_Move──▶ RemotePawn::SetTarget()
                                                  ↓ VInterpTo 插值
                                            ABP_Manny: Idle ↔ Run（速度驱动）

旋转朝向 ──同上（yaw）──────────────▶ Yaw 插值（RInterpTo）

（下蹲）  没有上报 ─────────────────▶  ❌ 不知道
（持枪）  没有上报 ─────────────────▶  ❌ 走路裸身
（瞄准）  没有上报 ─────────────────▶  ❌ 头不跟着转
```

### 1.2 差距根因

**不是素材问题，是协议不携带状态。** ABP_Manny 本身做好了 Idle/Walk/Run，
但它不读 `bIsCrouched`——因为 Move 消息里没有这个字段。
同理持枪和俯仰，ABP 状态机等着喂状态，上游却没喂。

**改动边界**：只要协议加对字段、C++ 把状态往下传，
动画蓝图只做"读状态、选动画"——网络层、服务器规则层完全不碰。

## 二、协议变更（一次完成，向后兼容）

### 2.1 字段设计

现有 Move：

```
C2S_Move：  [12B pos][4B yaw]           总 16B
S2C_MoveEvt：[4B pid][12B pos][4B yaw]  总 20B
```

追加（加尾，不改已有字段的偏移）：

```
C2S_Move：  [12B pos][4B yaw][1B flags][2B pitch]  总 19B
S2C_MoveEvt：[4B pid][12B pos][4B yaw][1B flags][2B pitch] 总 23B

flags 位域（小端 uint8）：
  bit 0 = bIsCrouched（下蹲）
  bit 1 = bIsFiring  （开火中——配合 ABP 射击覆盖动画；已有武器级 bFiring，这里复用）
  bit 2 = bIsAiming  （瞄准中——为将来的 ADS 预留，本期可不传）

pitch：int16 有符号，单位 0.01°（-327.68°~327.67°，精度足够）。
       范围：正常瞄准 -90°~+90° → -9000~+9000，int16 无溢出风险。
```

**向后兼容**：旧客户端收到的新字段会被 ExtractPackets 按长度前缀正确跳过
（多出的字节不读、不影响拆包）；旧客户端发的包服务器解码时 `readableBytes < 新长度`
→ fallback 为原行为（零状态），不崩溃。

### 2.2 涉及文件清单（协议变更）

| 文件 | 改动 |
|---|---|
| `include/domain/types.h` 或 `domain/player.h` | Player 加 `uint8_t flags = 0; float aim_pitch = 0.f;` |
| `include/application/dto.h` | MoveCommand / MoveEvent 追加 `uint8_t flags; int16_t pitch;` |
| `include/adapters/protocol_codec.h` | decode(C2S_Move) / encodeEvent(MoveEvent) 追加字段 |
| `SightlineSessionComponent.cpp` | `ReportMove` 追加 flags/pitch |
| `SightlineCharacter.cpp` | `HandleMove` 解出新字段传给 RemotePawnManager |
| `SightlineRemotePawnManager` | `OnMove` 追加 flags/pitch 参数 |
| `SightlineRemotePawn` | 新增 `bIsCrouched/AimPitch/bIsFiring` 属性 + 插值 |

## 三、服务端改动（纯透传，零判定）

服务端对这三个字段的职责是**存储 + 转发**，不做任何新判定（下蹲不改变 AABB、
瞄准不改变命中规则——这些都是本期保持现状的设计）。

### 3.1 Player 扩展

```cpp
// domain/player.h
uint8_t flags = 0;          // move 的状态位域
float    aim_pitch = 0.f;   // 瞄准俯仰角（度）
```

### 3.2 Room::applyMove 扩展

```cpp
bool applyMove(PlayerId pid, const Vec3& pos, float yaw,
               uint8_t flags = 0, float aim_pitch = 0.f) {
    // ...现有逻辑...
    p->flags      = flags;
    p->aim_pitch  = aim_pitch;
    return true;
}
```

### 3.3 DTO / Codec

- `MoveCommand` / `MoveEvent` 各追加 `uint8_t flags; int16_t pitch;`
  （pitch 存 int16，codec 负责量化/反量化，DTO 不丢失精度）
- `decode(C2S_Move)`：读新偏移的 3 字节；不足新长度时 fallback `flags=0, pitch=0`
- `encodeEvent(MoveEvent)`：追加写 3 字节

### 3.4 RoomService::handleMove

```cpp
if (!room->applyMove(pid, cmd.pos, cmd.yaw, cmd.flags, cmd.aim_pitch)) return;
channel_.sendToAll(room->othersOf(pid),
                   MoveEvent{pid, cmd.pos, cmd.yaw, cmd.flags, cmd.pitch});
```

### 3.5 单测

`test_room` 追加：`applyMove` 后 `p->flags == 0x01`（下蹲）、`p->aim_pitch == 15.5f`；
`test_room_service` 追加 mock channel 验证 MoveEvent 包含新字段。

## 四、客户端 C++ 改动

### 4.1 SessionComponent::ReportMove（上报方）

```cpp
// 从 GameState 组件读当前状态，打包进 flags
uint8_t Flags = 0;
if (GameState) {
    if (GameState->bIsRunning)  Flags |= 0x02;  // bit1 = firing（复用 running 位，或新增）
    if (GameState->bIsAiming)   Flags |= 0x04;  // bit2 = aiming
}
if (Owner->bIsCrouched)         Flags |= 0x01;  // bit0 = crouched

int16 Pitch = static_cast<int16>(
    Owner->GetAimDirection().Rotation().Pitch * 100.f);  // 0.01° 量化

S->SendFrame(MsgId::C2S_Move, USightlineProto::EncMove(Pos, Yaw, Flags, Pitch));
```

### 4.2 SightlineRemotePawn 扩展

新增属性（蓝图可读）：

```cpp
UPROPERTY(BlueprintReadOnly, Category="Sightline|Anim")
bool bIsCrouched = false;

UPROPERTY(BlueprintReadOnly, Category="Sightline|Anim")
bool bIsFiring = false;

UPROPERTY(BlueprintReadOnly, Category="Sightline|Anim")
float AimPitch = 0.f;    // 已插值，ABP 直接读
```

`SetTarget` 新签名：

```cpp
void SetTarget(const FVector& Pos, float Yaw, uint8_t Flags, float AimPitch);
```

实现要点：

- `bIsCrouched / bIsFiring` 从 Flags 位域解出，**直接赋值**（bool 无需插值）；
- `AimPitch` 用 `FMath::FInterpTo` 平滑（10Hz 快照插值，和位置同一逻辑）；
- **下蹲缩放**：当 `bIsCrouched` 变化时，
  `MeshComp->SetRelativeScale3D(FVector(1,1,0.6))`（半高）或
  调 `GetCapsuleComponent()->SetCapsuleHalfHeight()`（有胶囊时）——
  远端傀儡目前无胶囊，用 Mesh 缩放最简单。
  **注意**：Mesh 缩放不影响动画播放，动画自身会变形到下蹲姿态，
  缩放只是让碰撞/视觉占位也跟着变矮。

### 4.3 SightlineProto 扩展

```cpp
// EncMove 追加两参数（新重载，旧签名保留以兼容）
static TArray<uint8> EncMove(const FVector& Pos, float Yaw, uint8_t Flags, int16_t Pitch);

// DecodeMove 追加（同向后兼容策略：新长度→读，旧长度→fallback）
static bool DecodeMove(const TArray<uint8>& B, int32& OutPlayerId, FVector& OutPos,
                       float& OutYaw, uint8_t& OutFlags, float& OutPitch);
```

## 六、新 ABP 设计（ABP_RemotePawn）

**核心思路**：下半身走路/下蹲（Locomotion State Machine）+ 上半身持枪覆盖
（Layered Blend Per Bone）——和 07 手册第四项的蓝图思路一致，但动画素材换成了 Lyra 全套。

### 6.1 状态机结构

```
Entry
  │
  ▼
┌─ Unarmed_Idle ── Speed > 10 ──▶ Unarmed_Walk/Run（BlendSpace: Speed 0~600）
│  （不端枪：裸身 Idle，过渡用）
│
│  bIsFiring = true ?
│  ──────────────── yes
▼
┌─ Rifle_Idle ──── Speed > 10 ──▶ Rifle_Crouch_Walk  [bIsCrouched && Speed>10]
│  (MM_Rifle_Idle)                 (BS_MM_Rifle_Crouch_Walk)
│    │ bIsCrouched=false                      │ bIsCrouched=false
│    ▼                                         ▼
│  Rifle_Walk/Run ─────────────▶ Rifle_Crouch_Idle
│  (BlendSpace: MM_Rifle_Walk/Run) (MM_Rifle_Crouch_Idle)
│
│  bIsFiring = false ?
│  ────────────────── yes
└──▶ back to Unarmed_Idle
```

简化版（本期实用路线）：
**不搭完整状态机**，用一个 `ABP_Manny`（已有）+ 一个 `Layered Blend Per Bone`
覆盖上半身持枪层——下半身走路/下蹲仍走 ABP_Manny 的原有状态机，上半身根据
`bIsFiring / bIsCrouched` 混合不同持枪姿态。

```
ABP_Manny（下半身）──▶ Layered Blend Per Bone ──▶ 输出
                   │
                   └─ Blend Layer: MM_Rifle_Idle / MM_Rifle_Crouch_Idle
                      Blend Bool: bIsFiring
                      Spine bones: spine_01 ~ hand_r
```

### 6.2 AimPitch 处理

在持枪层的 Output Pose 之后，加 **AimOffset** 节点：

```
──▶ Layered Blend Per Bone ──▶ AimOffset (AO_MM_Rifle_Idle_Hipfire)
                                Pitch: AimPitch / 90.f  (-1~1)
                                Yaw:   0（已在动画里，不需要额外偏移）
```

AimOffset 按 Aiming 状态切换：

- 站立持枪 → `AO_MM_Rifle_Idle_Hipfire`
- 下蹲持枪 → `AO_MM_Rifle_Crouch_Idle`

### 6.3 下蹲过渡动画

Lyra 的 `MM_Rifle_Crouch_Entry` / `MM_Rifle_Crouch_Exit` 是**过渡动画**（从站到蹲、从蹲到站）。
在状态机里需要两个 Transition：

```
Rifle_Idle/Run ── bIsCrouched=true ──▶ Crouch_Entry（播放）──▶ Crouch_Idle/Walk
Rifle_Crouch   ── bIsCrouched=false ──▶ Crouch_Exit（播放）──▶ Rifle_Idle/Run
```

## 七、实施计划（三期，每期可独立演示）

### Phase 1：持枪同步（Day 1，优先级最高）

**协议**：Move 追加 1B flags（只用 bit1=端枪）+ 2B pitch；全链路贯通。

**素材**：迁移 `Locomotion/Rifle` + `Meshes` + `Weapons/Rifle/Mesh`。

**C++**：
- RemotePawn 新增 `bIsFiring` / `AimPitch`；
- `SetTarget` 新签名接收 flags/pitch；
- SessionComponent `ReportMove` 从武器读 `bFiring`；
- ABP_RemotePawn（新建，基础版）：ABP_Manny + Layered Blend Per Bone 持枪覆盖 + AimOffset。

**验收**：远端玩家端枪时傀儡上半身变持枪姿态；松开（不 fire）时裸身 Idle。
头上下转动时傀儡跟着转。

### Phase 2：下蹲同步（Day 2）

**协议**：flags bit0=下蹲追加进现有位域（Phase 1 已建基础设施，只加一个位）。

**C++**：
- RemotePawn 新增 `bIsCrouched` + 蹲下缩放逻辑（Mesh Scale 或胶囊）；
- ABP 加 Crouch 状态（MM_Rifle_Crouch_Idle/Walk）+ Entry/Exit 过渡。

**验收**：远端蹲下 → 傀儡蹲姿（半高缩放 + 下蹲动画）+ 站起时过渡动画。

### Phase 3：精细打磨（Day 3，可选）

- 原地转向动画（`MM_Rifle_TurnLeft_90/180`）；
- 下蹲切换的物理碰撞同步（服务器 hitscan 半高变化——需要新协议字段）；
- 武器模型挂点微调（`SM_Rifle` → `hand_r` 骨骼插槽）；
- bIsAiming 位（ADS 腿部走姿差异，Lyra 有 `MM_Rifle_Walk_Fwd` 站立瞄准版）。

## 八、已知边界与决策记录

| 问题 | 决策 | 理由 |
|---|---|---|
| 下蹲只改视觉、服务器 AABB 不变 | 一期这样 | 完全正确需要协议加 AABB 字段+服务端判定复杂度，二期再做 |
| bIsFiring 由谁上报 | SessionComponent 在 ReportMove 里读武器 bFiring | Character 已持有武器，10Hz 与 Move 同频，不增加协议 |
| RemotePawn 无胶囊，半高怎么调 | MeshComp SetRelativeScale3D(Z=0.6) | 无胶囊=无碰撞，视觉对齐即可；有胶囊后可改用 CapsuleHalfHeight |
| 旧客户端连新服务器 | flags/pitch fallback 为 0（裸身、头朝前） | 协议加尾不改头，旧客户端收到 MoveEvent 多余字节不读 |
| Lyra 动画骨架不匹配 | 两端 Manny 同源，个别动画右键 Retarget | 极少见，本质是同一 rig |
| AimOffset 来源 | Lyra 的 AO_MM_Rifle_*（75 个方向，俯仰全覆盖） | 官方现成，精度远超自建 |
