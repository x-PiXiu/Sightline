# 客户端架构评审与重构规划

> **性质**：架构评审报告 + 重构执行方案。不是理论分析——每一项问题都附带当前代码证据和修复方案。
> **触发**：连续多轮 Bug（动画不同步/开火卡顿/空指针崩溃）暴露出根本原因——**客户端缺少顶层架构设计**，代码是补丁式生长的。
> **原则**：先画清现状 → 识别问题 → 设计目标 → 分步迁移。每一步可验证、可回退。

## 三、问题识别（按严重度排序）

### 问题 1：ASightlineCharacter 是 God Class ⭐⭐⭐

**证据**：354 行 .cpp + 157 行 .h，承担 **7 种职责**：

| 职责 | 方法数 | 应该归属 |
|---|---|---|
| 会话管理（登录/心跳/房间） | 3 | Session 组件 |
| 消息路由（OnServerMessage→9 个 Handle） | 10 | 消息分发器 |
| 游戏状态（HP/PlayerId/Dead） | 3+9 钩子 | GameState 组件 |
| 远端傀儡管理（Spawn/Find/Destroy） | 3 | RemotePawnManager |
| 武器协调（CanFire/ReportFire/Equip） | 4 | Character 保留 |
| 视觉状态推送（SyncWeaponVisualState） | 1 | Tick 自然处理 |
| 定时器管理（Move/Ping/GroundZ） | 3 | 跟随所属职责 |

**后果**：每次加功能都要改 God Class → 改一个地方影响其他 → Bug 难定位。

### 问题 2：Character ↔ Weapon 双向依赖 ⭐⭐

```
Character → Weapon：CurrentWeapon->PushVisualState()、GetCurrentWeapon()->StartFire()
Weapon → Character：GetOwningCharacter()->CanFire()、GetAimOrigin()、GetAimDirection()、ReportFire()
```

**后果**：改 Character 的接口会破坏 Weapon，改 Weapon 的接口会破坏 Character。

### 问题 3：动画状态散落在两个对象上 ⭐⭐

| 动画数据 | 存在哪 | 谁读 |
|---|---|---|
| bIsFiring | ASightlineWeapon | ABP_VIRTUS |
| bReloading | ASightlineWeapon | ABP_VIRTUS + ABP_Arms（通过 Cast 链） |
| bIsRunning | ASightlineCharacter | ABP_Arms |
| bIsAiming | ASightlineCharacter | ABP_Arms |
| MoveX/MoveY/MoveSpeed | ASightlineWeapon | ABP_VIRTUS |

**后果**：ABP_Arms 和 ABP_VIRTUS 从不同对象读不同变量 → **同一帧拿到不同值** → 动画不匹配。

### 问题 4：武器 Actor 的弹壳池初始化副作用 ⭐

Spawn 10 个 BP_Casing → 每个 BP_Casing 的 BeginPlay/Construction Script 执行 → 可能触发声音/物理/粒子 → 导致"游戏启动就有子弹落地声音"。

### 问题 5：PIE 双开性能 ⭐

已知的编辑器结构性问题，不是代码 Bug。

## 四、目标架构（重构方案）

### 4.1 设计原则

1. **单一职责**：每个类只做一件事
2. **单向依赖**：上层知道下层，下层不知道上层
3. **状态单一真源**：每个状态变量只有一个类负责写入
4. **事件驱动解耦**：模块间通过委托/事件通信，不直接调用

### 4.2 目标类图

```
══════════ 传输层（不变）══════════
USightlineNetSubsystem        连接/收发/拆包/委托
USightlineProto               协议编解码

══════════ 会话层（★ 从 Character 拆出）══════════
USightlineSessionComponent (ActorComponent)
│   职责：登录/进房/心跳/断线重连/连接状态
│   持有：NetSubsystem 引用
│   暴露：
│     BlueprintAssignable: OnLoginAck, OnRoomStart, OnKicked, OnDisconnected
│   定时器：10Hz ReportMove, 2s Ping
│   方法：LoginToServer(), ReportMove(), SendPing()
│   状态：bIsLoggedIn, ConnConfig
│
│   ★ 不再管：HP/Dead/远端傀儡/武器/游戏状态

══════════ 游戏状态层（★ 从 Character 拆出）══════════
USightlineGameStateComponent (ActorComponent)
│   职责：游戏状态的**单一真源**
│   状态：
│     MyPlayerId, MyHP, bIsDead
│     bIsFiring, bIsReloading, bIsRunning, bIsAiming
│   远端表：TMap<int32, FRemotePlayerState>
│   暴露：
│     BlueprintReadOnly: GetPlayerId/GetHP/IsDead/IsFiring/IsReloading/...
│     BlueprintAssignable: OnHPChanged, OnDeath, OnRespawn, OnKillConfirmed...
│     (供 HUD/动画/武器读取)
│
│   ★ 不再管：网络发送/登录/远端傀儡 Actor

══════════ 远端管理层（★ 从 Character 拆出）══════════
USightlineRemotePawnManager (ActorComponent)
│   职责：远端傀儡的 Spawn/Destroy/位置同步
│   持有：TMap<int32, ASightlineRemotePawn*>
│   依赖：RemotePawnClass (TSubclassOf)
│   方法：OnRoomStart(playerIds), OnMove(pid,pos,yaw), OnPlayerLeft(pid)
│
│   ★ 不再管：游戏状态/网络/武器

══════════ 角色层（大幅瘦身）══════════
ASightlineCharacter (保留但大幅精简)
│   职责：UE 角色框架（移动/碰撞/输入/相机/武器挂载）
│   组件：Capsule + ArmsMesh + Camera + CharacterMovement
│        + SessionComponent + GameStateComponent + RemotePawnManager
│   方法：
│     CanFire() → 查 GameStateComponent
│     ReportFire() → 网络 + 通知 GameState
│   钩子：BP_On* 系列保留（蓝图覆盖画效果）
│
│   ★ 不再管：网络会话/游戏状态/远端傀儡——全部委托给组件

══════════ 武器层（简化）══════════
ASightlineWeapon
│   职责：开火规则/弹药/冷却
│   不变：StartFire/Reload/FireShot
│   变化：
│     CanFire() → 查 GameState（通过 Owner 的接口/组件）
│     ReportFire → Owner 的 ReportFire
│   删除：bIsRunning/bIsAiming/MoveX/MoveY/MoveSpeed（由 GameState 统一管理）
│   保留：BP_OnFireEffects/BP_OnReloadStarted（武器专属表现）

══════════ 动画层 ═══════════
ABP_Arms → 读 GameStateComponent 的统一状态
ABP_VIRTUS → 读 GameStateComponent 的统一状态（不再需要 WeaponRef）
ABP_RemotePawn → 读 RemotePawn 的 Speed
```

### 准备 2：BP_Player 的 GameState 访问路径声明

**蓝图侧拿到 GameStateComponent 的方式**（方案已锁定）：

```
BP_Player 事件图
├── Event BeginPlay
│   ├── ...（现有逻辑）
│   └── Find Sightline Game State Component → 提升为变量 "GameState"   ← ★ 存引用
│
├── 读取路径示例（所有 BP_On* 钩子里读状态用）：
│   └── GameState → Get HP / Get Is Dead / Get PlayerId
│
└── 设置路径示例（蓝图设置输入状态用）：
    └── GameState → Set Is Running / Set Is Aiming
```

**具体步骤**：
1. BP_Player 的 BeginPlay 最后追加：
   - `Find Sightline Game State Component` 节点（搜组件类型）
   - → 提升为 BlueprintReadWrite 变量 `GameState`（类型：`SightlineGameStateComponent` 引用）
2. 所有后续读取/设置都通过这个变量访问

**为什么不在 C++ 里做**：`FindComponentByClass` 在蓝图的 BeginPlay 里做更直观，蓝图侧直接存引用，不需要 C++ 管生命周期——`UPROPERTY()` 蓝图变量被引擎 GC 保护。

**不需要在 C++ Character 里加 GameState 引用**：Character 只做薄分发，查状态时才读组件（`FindComponentByClass`），不持有强引用——与现有 Weapon 读 Character 的 `GetOwningCharacter()` 对称。

GameState = FindComponentByClass<USightlineGameStateComponent>();
