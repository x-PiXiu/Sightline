## 一、系统四层咬合链（操作前先建立全景）

整个系统由四层组成，**每层只跟相邻层发生关系**，本文操作步骤即按层推进：

```
① 枚举层   项目设置 Surface Properties 里定义的名字（Dirt/Metal/Wood/Enemy/Concrete）
              ↓ 只是被"选中"，自己无法挂到任何东西上
② 载体层   PM 物理材质资产（PM_Dirt 等）——枚举值唯一能进入游戏的实体载体
              ↓ 挂到材质的 Phys Material 槽（或组件的 Phys Material Override 槽）
③ 挂载层   地图材质 / 远端胶囊组件——"这块墙是土"从挂上那一刻成立
              ↓ 开火时 trace 命中，C++ 解出枚举值
④ 数据层   DA_SightlineImpactFX：TMap<枚举值, {弹孔材质, 音效, 碎屑特效, 尺寸}>
              ↓ 蓝图查表得到表现包，交给 C++ 贴画池/播放
⑤ 表现层   弹孔 + 音效 + 碎屑（池化零 GC，预热零首枪卡顿）
```

**关键认知（后面操作都围绕它）**：
- DA 表的 key 是**枚举值**（Dirt），不是 PM_Dirt 资产——多个 PM 可以共用一个枚举值，DA 一行全覆盖；
- PM 与枚举值是多对一：**要用哪个枚举值，就必须至少建一个选了它的 PM 并挂到东西上**；
- `Default` 是枚举第 0 位，天生存在，**不需要也不应该建 PM**——什么都没挂的材质自动走它。

运行时数据流（C++ 已写好，无需操作）：

```
FireShot → 表现层 LineTrace（ECC_Visibility，忽略自己）
        → Hit.PhysMaterial（= 材质上挂的 PM）
        → UPhysicalMaterial::DetermineSurfaceType(PM) → 枚举值
        → BP_OnShotImpact(Hit, SurfaceType)   ← 蓝图从这里接手
        → TryGetImpactFX(SurfaceType) 查 DA → 出表现包
```

## 二、第 1 步：确认表面类型清单（项目设置）

**操作路径**：`Edit → Project Settings → Engine → Physics → Surface Properties`

当前项目已定义（**不要改动顺序**）：

```
Default / Dirt / Metal / Wood / Enemy / Concrete
```

**规则与禁忌**：

| 操作 | 允许？ | 原因 |
|---|---|---|
| 在**列表末尾追加**新名字 | ✅ | 例：以后要区分 Sand，直接加在最后 |
| **重排**已有条目顺序 | ⚠️ 禁止 | 底层按数组序号映射 SurfaceType1..N，重排会让 Dirt 和 Metal 悄悄互换，所有 PM/DA 引用错位，且**没有任何报错**，只会表现为弹孔贴错材质 |
| **删除**已有条目 | ⚠️ 禁止 | 同上 |

> 细节：这些名字只是 SurfaceType1/2/3… 的可读别名。引擎里所有表面类型下拉框（PM 资产、
> DA 的 Entries 键、蓝图 SurfaceType 引脚）显示的都是这套名字。

## 三、第 2 步：创建物理材质（PM）并挂载

### 3.1 现状与缺口

| 枚举值 | PM 资产 | 挂载点 | 状态 |
|---|---|---|---|
| Dirt | `PM_Dirt` | 地图的土质材质 | ✅ PM 已有，待挂材质 |
| Metal | `PM_Metal` | 金属材质 | ✅ 同上 |
| Concrete | `PM_Concrete` | 混凝土墙/地材质 | ❌ 需新建 |
| Wood | `PM_Wood` | 木质材质 | ❌ 需新建 |
| Enemy | `PM_Enemy` | **BP_RemotePawn 胶囊组件**的 Phys Material Override | ❌ 需新建 |
| Default | 无需 PM | —（材质不挂任何 PM 即是） | — |

### 3.2 新建 PM（每个约 30 秒）

1. 内容浏览器进入 `Content/Code/Physics/`；
2. 右键 `PM_Dirt` → **Duplicate**，重命名（如 `PM_Concrete`）；
3. 双击打开 → Details 面板 → **Surface Type** 下拉 → 改选对应名字（Concrete/Wood/Enemy）；
4. Compile & Save。重复建出三个。

> PM 里的摩擦/弹性/密度参数本项目用不到（服务器自算 hitscan），PM 在这里是**纯标签牌**。

### 3.3 挂载到地图材质

1. 视口点选一堵墙 / 一块地 → **Ctrl+B**（在内容浏览器中定位它用的材质资产）；
2. 打开该材质（或材质实例）→ Details 搜索框输入 `Phys`；
3. **Phys Material** 字段填对应 PM；
4. 地图里**每种材质**都过一遍——漏挂的走 Default 兜底，表现为"这面墙弹孔不对"。

### 3.4 挂载 Enemy 到远端胶囊（特殊）

打开 `BP_RemotePawn`：

1. 选中最外层 **CapsuleComponent**；
2. Details → Collision 分区 → **Phys Material Override** = `PM_Enemy`；
3. Compile & Save。

这样子弹 trace 打中玩家胶囊时直接返回 Enemy 表面，**蓝图里连 Cast to Pawn 分支都可以省掉**（见 6.3）。

## 四、第 3 步：创建并填写 DataAsset

### 4.1 创建

1. 内容浏览器空白处右键 → **杂项（Miscellaneous）→ 数据资产（Data Asset）**；
   - 找不到就用右键菜单顶部**搜索框**输入 `数据资产` / `data asset` 过滤；
   - 搜不到 `SightlineImpactFXConfig` 类型 = 编辑器没重启（见检查项 2）；
2. 弹窗里选 **SightlineImpactFXConfig**；
3. 命名 `DA_SightlineImpactFX`（放 `Content/Decals/` 或你习惯的配置目录）。

### 4.2 填写 Entries 表

双击打开 DA，`Entries` 点 **+** 逐行添加。**key 是枚举值下拉**（不是资产引用），按附录 A 的对照表填：

| Key | Decal Material | Impact Sound | Impact System | Decal Size |
|---|---|---|---|---|
| `SurfaceType_Default` **（兜底行，必填）** | `MI_VFX_BulletDecal_Concrete` | `SFX_Vefects_Shots_Squib_Concrete_Cue` | `FX_SquibConcrete` | 16 |
| `Dirt` | `MI_VFX_BulletDecal_Rock`（弹孔材质无 Dirt 专用，Rock 最接近） | `SFX_Vefects_Shots_Squib_Dirt_Cue` | `FX_SquibDirt` | 16 |
| `Metal` | `MI_VFX_BulletDecal_Metal` | `SFX_Vefects_Shots_Squib_Metal_Cue` | `FX_SquibMetal` | 16 |
| `Wood` | `MI_VFX_BulletDecal_Wood` | `SFX_Vefects_Shots_Squib_Wood_Cue` | `FX_SquibWood` | 16 |
| `Concrete` | `MI_VFX_BulletDecal_Concrete` | `SFX_Vefects_Shots_Squib_Concrete_Cue` | `FX_SquibConcrete` | 16 |
| `Enemy` | **留空**（人不贴弹孔） | 留空 | `FX_SquibBlood` | 16 |

### 4.3 字段语义

| 字段 | 留空的含义 |
|---|---|
| Decal Material | 该表面不贴弹孔（Enemy 行留空 = 打人不贴贴画） |
| Impact Sound | 不播音效 |
| Impact System | 不出碎屑特效 |
| Decal Size | 弹孔直径（厘米），X 分量兼作投射深度；16 对厚墙无穿透伪影 |

**Default 行为什么必填**：材质忘挂 PM、或 DA 没建对应行，两种"查不到"最终都落到 Default 行
（`TryGetImpactFX` 的回落逻辑）。兜底行空着 = 这些情况**毫无反馈**，比贴错弹孔更糟。

## 五、第 4 步：武器蓝图接线（BP_Weapon_VIRTUS）

### 5.1 填配置槽

1. 打开 `BP_Weapon_VIRTUS` → **Class Defaults**；
2. 搜索 `Impact` → **Impact FX Config** → 选 `DA_SightlineImpactFX`；
3. **Compile & Save**（填了这个，`BeginPlay` 的预热链才会启动）。

### 5.2 添加事件并接线

Event Graph 空白处右键 → 搜 `BP On Shot Impact` → 添加 **Event BP_OnShotImpact**
（两个输入引脚：`Hit` 结构体、`SurfaceType` 枚举）。

**推荐方案（配合 3.4 的 PM_Enemy，无需 Cast 判断）**：

```
Event BP_OnShotImpact (Hit, SurfaceType)
  │
  ├─[取配置] 变量 Get ImpactFXConfig（Class Defaults 里那个）
  │      → 连到 TryGetImpactFX 节点的 Target 引脚
  │      Surface 引脚 ← 事件的 SurfaceType
  │      输出：Out FX（结构体）、Return Value（bool）
  │
  ├─[分流] Branch（Condition = Return Value）
  │      TRUE ─→（Enemy 行 DecalMaterial 为空，下面①自动不执行，天然不贴人脸）
  │
  ├─①[弹孔] Out FX 拖出 → Break SightlineImpactFX
  │      Get Game Instance → Get Subsystem（类选 Sightline Decal Pool Subsystem）
  │      → Spawn Decal
  │        · Decal Material ← Break 的 Decal Material
  │        · Hit Location   ← Hit 拖出 → Break Hit Result 的 Location
  │        · Hit Normal     ← Break Hit Result 的 **Impact Normal**（用这个，别用 Normal）
  │        · Size           ← Break 的 Decal Size
  │
  ├─②[音效] Play Sound at Location
  │        · Sound ← Break 的 Impact Sound
  │        · Location ← Break Hit Result 的 Location
  │
  └─③[碎屑] Spawn System at Location
           · System Template ← Break 的 Impact System
           · Location ← Hit Location
           ·（可选）Rotation ← Make Rot from X（Impact Normal）——定向碎屑
```

### 5.3 备选方案（没做 3.4 时用）

若没给胶囊挂 PM_Enemy，trace 打中玩家会查到 Default 而贴出墙弹孔，需要显式分流：

在 Branch TRUE 之后插 `Cast to Pawn`（Object = Break Hit Result 的 **Hit Actor**），
**Cast Failed**（打的是环境）→ 接 ①②③；Cast Succeeded（打的是人）→ 留空或接 FX_SquibBlood。

### 5.4 清理旧逻辑

检查 `Event BP_OnFireEffects` 等处是否有旧的每枪 SpawnActor `BP_BulletDecal` 逻辑——**整段删除**。
池化系统就是来替代它的；留着 = 双份弹孔 + 每枪一个 UObject 生灭的 GC 债务。

## 七、常见问题排查表

| 症状 | 原因 | 处理 |
|---|---|---|
| 日志里没有 `[DecalPool]` 任何输出 | 武器没填 ImpactFXConfig；或编辑器没重启没加载新类 | 补填配置槽 / 重启编辑器 |
| 所有表面弹孔/音效都一样 | 材质没挂 PM（或挂的 PM 不是你想的那个）→ 全走 Default 兜底 | 逐材质检查 Phys Material 槽 |
| 某一种表面没反应 | DA 里没建该枚举值的行 → 回落 Default；或该表面的 PM 没挂到材质 | DA 补行 / PM 补挂载 |
| 完全没有弹孔、也没有报错 | Branch 没接对 / Out FX 没 Break / 蓝图没 Compile | 对照 5.2 逐引脚检查 |
| 有弹孔没声音、或没碎屑 | DA 行对应字段留空 | 补资产 |
| 打玩家身上贴出墙的弹孔 | 没做 3.4（胶囊 PM_Enemy）也没做 5.3（Cast to Pawn 分流） | 二选一补上 |
| 弹孔方向歪 / 插进墙里 | 用了 `Normal` 而不是 `Impact Normal`；或漏了系统内置的 0.5cm 抬升（代码已做） | 检查引脚连的是 Impact Normal |
| 预热日志正常但首枪仍卡 | 编辑器首次 PIE 全局着色器编译（非本系统）；用同一编辑器会话跑第二次 PIE 对比 | 第二次不卡 = 环境因素，可忽略；持续卡则 `stat unit` 定位 |
| 以后某天弹孔全部错位 | Surface Properties 列表被人重排/删除过条目（序号重映射，无报错） | 恢复列表顺序，PM 和 DA 逐项核对 |

## 八、日常维护：新增一种表面（5 分钟流程）

以新增 `Sand` 为例：

1. **项目设置** → Surface Properties → **末尾追加** `Sand` → 重启编辑器（枚举变更需要）；
2. 复制 `PM_Dirt` → `PM_Sand`，Surface Type 改选 Sand；
3. 挂到沙地材质的 Phys Material 槽；
4. `DA_SightlineImpactFX` 加一行：key=Sand，填 `SFX_..._Squib_Sand_Cue` + `FX_SquibSand`
   （弹孔材质沿用 Rock 即可）；
5. 武器蓝图**零改动**，C++ **零改动**。

其他维护点（都在 C++ 里，一般不用动）：

| 参数 | 位置 | 说明 |
|---|---|---|
| 池大小 64 | `SightlineDecalPoolSubsystem.cpp` `DefaultPoolSize` | 10 发/秒 ≈ 6.4 秒弹孔量 |
| 预热间隔 0.1s | `Warmup()` 默认参数 | 系统多、开局忙可调大 |
| 弹孔抬升 0.5cm | `SpawnDecal()` 内 | 防 Z-fighting，一般不动 |

## 九、已知边界

1. **远端玩家的弹着点**目前出不了弹孔：`S2C_Hit` 协议不带弹道 origin/dir。协议演进时
   在 Fire 广播里补两个字段，即可让远端开火复用整池（C++ 侧已按"谁开火谁出弹着"预留）。
2. **打包版**首启仍可能有全局 PSO 编译：PIE 的 Niagara 运行时编译在 cooked 版本大部分不存在，
   打包验证前不必继续为编辑器环境过度优化。
3. Enemy 行走 DA 分流而非硬编码 Cast，是刻意的：换一种"打人表现"（比如以后加护盾）只改 DA 行。
