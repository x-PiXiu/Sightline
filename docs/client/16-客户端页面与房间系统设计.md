### 1.3 房间生命周期现状

```
客户端连接 → C2S_Login → LoginAck(pid)
    ▼
C2S_JoinRoom(3) → RoomService::handleJoin
    ▼
findJoinableRoom() → 找到 WAITING 房 → addPlayer
                   → 找不到 → 创建新 Room(Waiting)
    ▼
playerCount >= min_players(2) → tryStart() → Playing
    ▼ (S2C_RoomStart 广播)
对战中...
    ▼
三杀判胜 → GameOverEvent + MatchEndEvent → Finished
    ▼ 5 秒
rematch() → Waiting → 人够自动再开
    ▼
玩家全走光 → 房间回收
```

**关键发现**：当前房间是**隐式创建**的——玩家发 JoinRoom 时如果没房就自动建。没有"显式建房"和"选房加入"的流程。协议号 22~25 已分配但服务端未实现。

```cpp
// RoomList(23)：[2B count] × N { [4B roomId][1B mode][1B cur][1B max] }
static void encodeEvent(const app::RoomListEvent& e, std::string& wire) {
    Writer w; w.u16(static_cast<uint16_t>(e.rooms.size()));
    for (const auto& r : e.rooms) {
        w.u32(r.room_id); w.u8(r.mode);
        w.u8(static_cast<uint8_t>(r.cur_players));
        w.u8(static_cast<uint8_t>(r.max_players));
    }
    finish(MsgId::S2C_RoomList, w, wire);
}

// RecordList(21)：[2B count] × N { [8B matchId][1B mode][1B win][2B kills][2B deaths] }
static void encodeEvent(const app::RecordListEvent& e, std::string& wire) {
    Writer w; w.u16(static_cast<uint16_t>(e.records.size()));
    for (const auto& r : e.records) {
        w.u64(r.match_id); w.u8(r.mode);
        w.u8(r.win ? 1 : 0); w.u16(r.kills); w.u16(r.deaths);
    }
    finish(MsgId::S2C_RecordList, w, wire);
}

// TopKills(27)：[2B count] × N { [8B accountId][2B kills] }
static void encodeEvent(const app::TopKillsEvent& e, std::string& wire) {
    Writer w; w.u16(static_cast<uint16_t>(e.rows.size()));
    for (const auto& r : e.rows) {
        w.u64(r.account_id); w.u16(r.kills);
    }
    finish(MsgId::S2C_TopKills, w, wire);
}
```

#### 事件图表（逐节点细化版）

**先回答两个前置问题：**

**Q1：事件图表从哪个事件开始？**
WBP_Login 一共 **4 个入口节点**，其中 `Event Construct` 是图表的起点（页面被创建时执行一次）。
**绝不用 Event Tick**——登录页没有任何逐帧逻辑，Tick 会白耗每帧性能（常见新手坑）。

| # | 入口节点 | 触发时机 | 职责 |
|---|---|---|---|
| 1 | `Event Construct` | CreateWidget 后立刻 | 绑定网络事件 + 初始 UI 状态 |
| 2 | `LoginButton → OnClicked` | 点登录 | 调 `TrySendLogin` |
| 3 | `RegisterButton → OnClicked` | 点注册 | 调 `TrySendRegister` |
| 4 | `Event Destruct` | 页面销毁 | 解绑网络事件（防悬挂/重复） |

**Q2：要不要封装成函数？**
要。原则：**OnClicked 图保持一眼读完，逻辑进函数；网络回包入口用自定义事件**。

| 封装 | 类型 | 职责 | 为什么 |
|---|---|---|---|
| `HandleNetMessage(MsgId, Payload)` | 自定义事件 | 全部 S2C 回包分发 | `Bind Event to OnNetMessage` 的挂点；将来加 Delay/SetTimer 只有自定义事件稳妥 |
| `TrySendLogin` | 函数 | 校验+哈希+发送 | 登录/注册复用同一段哈希口径；改提示语只动一处 |
| `TrySendRegister` | 函数 | 同上 | 同上 |
| `ShowError(Text, Color)` | 函数 | ErrorText 出口 | 成功/失败提示共用，避免 SetText+SetColor 散落四处 |

**① `Event Construct`（图表起点，4 节点串一条执行线）：**

```
Event Construct
 ▼  Get GameInstance Subsystem → 选 USightlineNetSubsystem     （搜索 "Get Game Instance Subsystem"）
 ▼  拖出该返回值 → 找 OnNetMessage 委托脚注 → Bind Event to OnNetMessage
      └ Create Event → 选下方 ⑦ 的 HandleNetMessage           （红色委托脚注节点）
 ▼  PasswordInput → Set Is Password (true)                     （设计器已勾可省）
 ▼  ErrorText → Set Visibility → Hidden
```

> 绑定形态说明：Widget 里走的是**委托绑定**（Bind Event to），不是 Override——
> `OnNetMessage` 是 `USightlineNetSubsystem` 上的 BlueprintAssignable 动态委托，
> 每条 S2C（含 2/18/21/23/25）都会从它广播出来。BlueprintImplementableEvent 的
> Override 是另一条路（C++ 组件面向 Character），Widget 页面不要混用。

**② `LoginButton → OnClicked`（1 个节点）：**

```
LoginButton → OnClicked → TrySendLogin
```

**③ `TrySendLogin` 函数体：**

```
TrySendLogin
 ▼  AccountInput → GetText ──────────────┐
 ▼  PasswordInput → GetText ─────────────┤
 ▼  NOT IsEmpty(两条文本) ──→ Branch      （任一为空走 False）
     ├ True：
     │    SHA256Hash(Password) → PassHash            （USightlineProto，C++ 已提供）
     │    Get GameInstance Subsystem(NetSubsystem)
     │    → Branch(IsConnected)
     │        ├ False → Connect("127.0.0.1", 8888) → 再 SendFrame（阻塞毫秒级，本地/局域网安全）
     │        └ True  ↓
     │    SendFrame(EMsg::C2S_Login, EncLoginAccount(Account, PassHash))
     └ False → ShowError("请输入账号和密码", 红色)
```

> ⚠️ **不要用 `EncLogin(Account + PassHash)` 拼接**（初版伪代码的错误）：
> EncLogin 会把"账号+哈希"整体当作名字编码成 `[2B 名长][名]`，服务器按名长切帧后
> 哈希并入名字、`pass_hash` 判空 → **永远走游客路径**。必须用 C++ 新增的
> `EncLoginAccount(Account, PassHash)`，它产出服务器要的 `[2B accountLen][account][64B 哈希尾]`。

**④ `RegisterButton → OnClicked`（1 个节点）：**

```
RegisterButton → OnClicked → TrySendRegister
```

**⑤ `TrySendRegister` 函数体：**

```
TrySendRegister
```

**⑦ `HandleNetMessage` 自定义事件（网络回包统一入口）：**

```
HandleNetMessage(EMsg MsgId, TArray<uint8> Payload)       ← 参数签名必须与 FOnNetMessage 一致
 ▼  Switch on EMsg (MsgId)                                 ← case 就是枚举名，不是数字
     ├ case S2C_LoginAck (2)：
     │    DecodeLoginAck(Payload) → PlayerId
     │    Branch(PlayerId > 0)
     │      ├ True：
     │      │    Get GameInstance Subsystem → Unbind All From OnNetMessage   （先解绑再销毁，防悬挂）
     │      │    RemoveFromParent
     │      │    → 通知切换控制器打开 WBP_MainMenu（Event Dispatcher `OnLoginSuccess`，见第六节）
     │      └ False → ShowError("登录失败（账号或密码错误）", 红色)
     └ case S2C_RegisterResult (18)：
          DecodeRegisterResult(Payload) → Ok, ErrCode
          Branch(Ok)
            ├ True  → ShowError("注册成功，请登录", 绿色)
            └ False → ShowError("注册失败（重名，换一个账号）", 红色)
```

> **EMsg 枚举升级（2026-09-22）**：`SendFrame` 的 MsgId 参数已从 int32 改为 `EMsg`
> ——蓝图引脚是**下拉框**，直接选 C2S_Login 等，无需字面量节点；
> `OnNetMessage` 委托同改，蓝图用 **Switch on EMsg** 分发。重编译后旧图上
> 已接的整型转换节点会断开（红），删掉换下拉/换 Switch 节点即可。

**⑧ `Event Destruct`（兜底解绑）：**

```
Event Destruct
 ▼  Get GameInstance Subsystem(NetSubsystem) → Unbind All From OnNetMessage
```

> Construct 里绑、Destruct 里解——漏掉解绑的后果：切回登录页重新 Construct 会二次绑定，
> 一条 LoginAck 触发两次处理；RemoveFromParent 后未 GC 的旧实例也可能继续吃消息。

#### 事件图表（4 个独立入口 + 3 个填充函数）

**节点来源字典（看懂伪代码的第一步——伪代码里每个名字怎么变成节点）：**

| 伪代码里写的 | 它是什么 | 蓝图里怎么得到 |
|---|---|---|
| Get GameInstance Subsystem(Net) | 子系统实例节点 | 右键搜 "Get GameInstance Subsystem"，Class 下拉选 SightlineNetSubsystem；SendFrame/Connect/Disconnect/OnNetMessage 都要从它的引脚拖出 |
| SendFrame / Disconnect | 子系统成员函数 | 从 subsystem 实例引脚拖出 → 搜 "Send Frame" |
| EncListRooms / EncTopKills / EncJoinRoom / EncCreateRoom / EncQueryRecord / DecodeRoomList / DecodeTopKills / DecodeRecordList / DecodeJoinAck | USightlineProto 蓝图函数库的**静态 Pure 函数**，不属于任何实例 | 任何右键/引脚拖出菜单**直接搜名字**（空格分隔，如 "Enc List Rooms"）；无执行三角，只有数据引脚 |
| EMsg::C2S_xxx | SendFrame 的 MsgId 是枚举下拉 | 点 MsgId 引脚的下拉直接选，不用字面量节点 |
| HandleNetMessage | 自己建的自定义事件 | 图表右键 Add Custom Event，或从 OnNetMessage 委托引脚拖出自动创建 |
| RoomList / OnlineText / StatusText… | 设计器控件的变量引用 | 勾了"是变量"后，图表右键搜控件名即得 Get 节点 |

**操作规则**：白色执行三角（▶）拖出 = 下一个动作；彩色数据引脚拖出 = 喂数据的函数。
**建图顺序**：先建 ③ 的自定义事件，再回 ① 接 Bind（Bind 的 Event 脚注要选它）。

### 5.3 codec encode 追加

```cpp
static void encodeEvent(const app::RoomListEvent& e, std::string& wire) {
    Writer w; w.u16(static_cast<uint16_t>(e.rooms.size()));
    for (const auto& r : e.rooms) {
        w.u32(static_cast<uint32_t>(r.room_id));
        w.u8(r.mode);
        w.u8(static_cast<uint8_t>(r.cur_players));
        w.u8(static_cast<uint8_t>(r.max_players));
    }
    finish(MsgId::S2C_RoomList, w, wire);
}

static void encodeEvent(const app::RecordListEvent& e, std::string& wire) {
    Writer w; w.u16(static_cast<uint16_t>(e.records.size()));
    for (const auto& r : e.records) {
        w.u64(r.match_id); w.u8(r.mode);
        w.u8(r.win ? 1 : 0); w.u16(r.kills); w.u16(r.deaths);
    }
    finish(MsgId::S2C_RecordList, w, wire);
}

static void encodeEvent(const app::TopKillsEvent& e, std::string& wire) {
    Writer w; w.u16(static_cast<uint16_t>(e.rows.size()));
    for (const auto& r : e.rows) {
        w.u64(r.account_id); w.u16(r.kills);
    }
    finish(MsgId::S2C_TopKills, w, wire);
}
```
