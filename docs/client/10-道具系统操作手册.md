# 10 · 道具系统操作手册（DataAsset 全流程）

> **定位**：P2 道具系统（血包/弹药箱）从零到双端验证的**完整操作文档**——每一步点哪个菜单、
> 填哪个字段、填错什么症状、怎么排查。设计动机与架构决策见 `P2-道具系统落点分析.md`，
> 本文只讲"怎么操作"。
>
> **前置状态**：双端代码已实现（服务器 `04c70a7`，客户端 `975e633`+`dfb9726`）。
> **预计耗时**：首次 15~20 分钟；新增一种道具约 10 分钟（含服务器改动）。
> **对应代码**：服务器 `domain/item.h` + `Room` 扩展；客户端 `SightlineItemActor` + `ASightlineCharacter` 的 Handle 分支

---

## 〇、开始前的三项检查（比贴画系统多一项！）

| # | 检查项 | 方法 |
|---|---|---|
| 1 | **服务器已更新** | 192.168.1.35 那台机器 `git pull` 重新编译运行——道具消息（15/16）只有新服务器会发 |
| 2 | 客户端 C++ 已编译 | UE 仓库最新提交含 `SightlineItemActor.h` 即可 |
| 3 | **重启编辑器** | 新类（SightlineItemConfig / AItemActor）要重启才出现在资产创建面板 |

> 与贴画系统最大的区别：贴画是**纯客户端**系统（材质查表），道具是**两端契约**系统——
> 服务器不更新，客户端一行道具日志都不会有。

## 一、系统原理速览（操作前建立全景）

```
服务器（权威）                                客户端（镜像 + 表现）
────────────────────────                     ────────────────────────
开局/重开 → spawnItems() 布点      ──15──▶   HandleItemSpawn → 查 DA → Spawn AItemActor
              (十字4点,NetId自增)              （存入 Items 镜像表，防重复）
applyMove 顺带两件事：
  ① tickItems：冷却到点的重生       ──15──▶   同上（重发即重现）
  ② tryPickup：走到道具上(半径150cm) ──16──▶   HandleItemTaken
       血包: hp=min(100,hp+50)                 ├─ 销毁场景 Actor（双端同时消失）
       弹药: 仅标记冷却(本地非权威)             ├─ 自己捡的: 血包→GameState->SetHp(权威值回填)
                                              │            弹药箱→Weapon->AddReserveAmmo(本地加)
                                              └─ BP_OnItemTaken 钩子 → 蓝图画拾取特效/音效
```

**三条设计要点**（面试可讲）：

1. **走过自动拾取**：拾取没有"用户意图"要表达，判定搭 applyMove 的车（10Hz），
   省掉 C2S_Pickup 消息和独立定时器——服务端权威还天然成立；
2. **惰性重生**：道具重生也搭 applyMove 的车——房间没人移动就不检查，零空闲开销；
3. **NetID/TypeID 解耦**：服务器只发 `netId`（房间内自增）和 `typeId`（1/2），
   道具"长什么样"完全由客户端 DA 决定——服务器换皮零改动。

**TypeId 两端契约表**（改值必须两端同步改）：

| TypeId | 含义 | 服务器定义 | 客户端定义 | 拾取效果 |
|---|---|---|---|---|
| 1 | HealthPack 血包 | `domain/item.h` ItemTypeId | `SightlineItemActor.h` ESightlineItemType | 服务器权威回血 50（封顶 100），HP 值随 ItemTaken 下发 |
| 2 | AmmoBox 弹药箱 | 同上 | 同上 | 本地加备弹（DA 里 AmmoAmount，默认 60）；协议不校验弹药 |

## 二、第 1 步：创建 DataAsset

1. 内容浏览器进入 `Content/Code/DataAssets/`（贴画系统时建的目录，道具 DA 放一起）；
2. 右键 → **杂项（Miscellaneous）→ 数据资产（Data Asset）** → 选 **SightlineItemConfig**；
3. 命名 `DA_SightlineItemConfig`。

> 搜不到 SightlineItemConfig 类型 = 编辑器没重启（见检查项 3）。

## 三、第 2 步：填写 Entries（两行）

双击打开 DA，`Entries` 点 **+** 加两行：

| Key (TypeId) | Mesh | PickupEffect | PickupSound | RotateSpeed | SpawnZOffset | AmmoAmount |
|---|---|---|---|---|---|---|
| `1`（血包） | 医疗箱网格（见下） | 可空 | 可空 | 90 | 见说明 | 不用填 |
| `2`（弹药箱） | 弹药箱网格 | 可空 | 可空 | 90 | 见说明 | 60 |

**字段语义**：

| 字段 | 留空/默认的含义 |
|---|---|
| Mesh | 道具网格（**必填**，空 = 道具存在但不可见） |
| PickupEffect / PickupSound | 不播拾取特效/音效（蓝图钩子里用，见第 4 步） |
| RotateSpeed | 自转速度（度/秒）；0 = 静止。纯表现，不入判定不传网络 |
| SpawnZOffset | 生成时 Z 轴抬升。**网格轴心在物体中心的模型会半埋进地面**，按模型实测填（先 0 试，埋了再加） |
| AmmoAmount | 仅 TypeId=2 生效：拾取时本地加的备弹数 |

**网格从哪来**：`Content/ShotSystem/StaticMeshes/` 与 `Content/ShotSystem/Shot_VFX/StaticMeshes/`
有现成弹药箱/补给类网格；`Content/Modular_Rural_Cabin/` 里也可能有箱子类。选轴心在底部的
模型最省事（SpawnZOffset 填 0 即可）。

## 四、第 3 步：BP_Player 接线

**4a. 填配置槽（必做）**

打开 `BP_Player` → Class Defaults → 搜索 `Item` → **Item Config** → 选 `DA_SightlineItemConfig`
→ Compile & Save。不填的话收到消息也只打一条 Warning，道具不会生成。

**4b. 拾取特效/音效（可选，只在想要反馈时做）**

`BP_Player` 的 Event Graph 添加 **Event BP_OnItemTaken**（参数：NetId/Picker/TypeId/PickerNewHp/ItemActor）：

```
Event BP_OnItemTaken
  → Branch (Picker == GetPlayerId)                ← 只给自己捡的播反馈
      → ItemActor Is Valid?
          → Get Definition（ItemActor 变量拖出） → Break SightlineItemDefinition
              ├─ PickupEffect 有效 → Spawn System at Location
              │     (System=PickupEffect, Location=ItemActor.GetActorLocation)
              └─ PickupSound 有效 → Play Sound at Location
```

> ItemActor 在钩子触发时**尚未销毁**（C++ 故意把销毁放在钩子之后），位置可以直接读。
> 血条刷新不用做——C++ 已走 `GameState->SetHp → BP_OnHealed`；备弹刷新也不用做——
> `Weapon->AddReserveAmmo` 复用 `BP_OnAmmoChanged`，HUD 自动更新。

**4c. BP_OnItemSpawned 钩子**：通常留空（生成已由 C++ 完成）；要做小地图标记之类的额外表现时才用。

## 五、第 4 步：验证

**5a. 日志验证**（PIE 启动、两人进房后）：

```
[Item] 生成 NetId=1 Type=1 at (-800,0,0)     ← 东西血包 ×2
[Item] 生成 NetId=2 Type=1 at (800,0,0)
[Item] 生成 NetId=3 Type=2 at (0,-800,0)     ← 南北弹药箱 ×2
[Item] 生成 NetId=4 Type=2 at (0,800,0)
```

（坐标显示为 UE 轴系；距原点 8 米、贴地。）

**5b. 全链路功能清单**：

- [ ] 双开双方都能看到 4 个道具（位置一致）
- [ ] 走到道具上 → **双端同时消失**，拾取者日志 `[Item] 拾取 NetId=x picker=y`
- [ ] 捡血包：受伤后捡 → HP 回 50（封顶 100），血条刷新（`[State] 治疗 hp=xx`）
- [ ] 捡弹药箱：备弹 +60，弹药 HUD 刷新
- [ ] 拾取后 **15 秒**同一位置道具重新出现（`[Item] 生成 NetId=x` 重现，NetId 不变）
- [ ] 一局打完自动重开：道具重新布点（旧道具先清场再重生成，无残留无重复）
- [ ] 拾取判定在服务器：两个人的客户端上，道具消失时机一致（权威性的直接体现）

## 六、常见问题排查表

| 症状 | 原因 | 处理 |
|---|---|---|
| 没有任何 `[Item]` 日志 | 服务器没更新（旧服务器不发 15/16）；或两人没进同一房 | 服务器 `git pull` 重编译重启 |
| `[Item] ItemConfig 未配置` Warning | BP_Player 的 Item Config 槽没填 | 第 4a 步 |
| `[Item] ItemConfig 无 Type=x 的定义` | DA 里缺该 TypeId 的行 | Entries 补行 |
| 道具生成了但看不见 | DA 的 Mesh 空了 | 补网格 |
| 道具半埋进地面 | 网格轴心在物体中心 | DA 里 SpawnZOffset 抬高（按模型实测，几十 cm 级） |
| 道具悬空 | 网格轴心在底部但误填了 Offset | SpawnZOffset 归 0 |
| 走上去没反应 | 服务器判定半径 150cm（水平距离），且要求角色存活、房间 Playing | 站近点；残血确认下没死 |
| 拾取后 15 秒没重生 | 重生是惰性检查——房间里**没人移动**就不会触发 | 随便走两步（设计行为，不是 bug） |
| 重开后旧道具还在/重复 | 客户端版本旧（RoomStart 清场是随 P2 加的） | 更新客户端 |
| 道具位置和远端玩家错位 | 两端代码版本不一致（出生点半径 18→1800 也在这次改动里） | 两端同步到同一提交 |

## 七、日常维护：新增一种道具（如护盾包 Shield，TypeId=3）

**与贴画系统的关键区别：这里每一步都是两端契约，顺序不能乱。**

1. **服务器**：`domain/item.h` 的 `ItemTypeId` 加 `Shield = 3`；`Room::tryPickup` 加效果分支
   （如临时护盾——需要协议/DTO 配合时先改 `dto.h` + codec）；重编译部署；
2. **客户端**：`SightlineItemActor.h` 的 `ESightlineItemType` 同步加 `Shield = 3`；
   `HandleItemTaken` 加自己的效果分支；
3. **DA**：Entries 加一行 Key=3，配网格/特效；
4. 布点：想让新道具出现在地图上，改 `Room::spawnItems()` 的布点表（服务器）；
5. 单测：`test_room.cpp` 补该道具的拾取规则用例。

## 八、边界与设计说明

| 边界 | 说明 |
|---|---|
| 弹药非权威 | 弹药是客户端本地演出（协议不管弹药），弹药箱的服务器效果只有"标记冷却"——外挂改备弹服务器不知道，这是**设计取舍**不是疏漏 |
| 拾取冷却 | 同一道具拾取后 15 秒内不可再捡（服务器 `item_respawn_ms`）——期间道具对所有玩家"消失" |
| 数量固定 | 开局固定 4 个布点，不做按人数动态调整（YAGNI） |
| 主动拾取 | 以后要"按 E 拾取专属武器"时，回到请求-验证模式（C2S_Pickup + S2C_PickupResult），现有接口不受影响 |
