# 动画与视觉打磨手册

> **时机**：P2 开发周期内穿插执行（全部客户端改动，不阻塞服务端 domain 逻辑）。
> **定位**：把"裸身 Mannequin + 无动画武器"升级为"有动画的角色 + 换弹蒙太奇 + 手臂动画状态机"，让 M3 对射演示看起来像真正的游戏。
> **前置**：P1+P3 已完成（C++ 基类+HUD 全部就绪）。

---

## 第一项：ABP_RemotePawn 换成有动画的 Mannequin（高优先级，30 分钟）

### 为什么做

现在远端玩家看到的是"裸身 Mannequin 站着不动"——10Hz 位置插值只管移动，没有动画状态机让它走路/跑步。引擎自带的 ABP_Manny 已经做好了完整的 Idle/Walk/Run/Jump 状态机，**直接指定给 BP_RemotePawn 即可**，不需要新建任何动画蓝图。

### 为什么用 ABP_Manny 而不是自建

| | ABP_Manny（直接用） | 自建 ABP |
|---|---|---|
| 工作量 | 0（配一个 Details 属性） | 30 分钟 |
| 状态机质量 | Epic 官方出品，Transition 平滑 | 你自己搭，初期粗糙 |
| 学习价值 | 低 | 高（但可以后补） |
| 对 P2 的影响 | 零——不影响道具系统 | 同上 |

**结论**：先用 ABP_Manny 快速出效果，理解了动画蓝图后可以随时换成自建版本（从 ABP_Manny 复制一份，改参数学习）。两条路对 P2 零影响。

### 操作步骤

1. 打开 `BP_RemotePawn`（继承 ASightlineRemotePawn）
2. 选中 Mesh 组件 → Details → **Animation** 分类 → **Anim Class** 下拉 → 选 `ABP_Manny`（Engine Content，需 Show Engine Content 可见）
3. 如果 Anim Class 下拉里找不到：Content Browser 齿轮 → Show Engine Content → 再回来选
4. 编译 → 保存

### 原理说明

ABP_Manny 内部的 Transition 条件用的是 `Get Velocity → Vector Length`——这正好读的是 C++ `ASightlineRemotePawn::GetVelocity()` 的覆写。你在 C++ Tick 里自己算的速度（`NewLoc - OldLoc) / DeltaTime`）→ 覆写 `GetVelocity()` → ABP_Manny 拿到速度 → 自动切换 Idle/Walk/Run。**动画蓝图完全不知道网络存在**，它只读速度选动画——这就是整洁架构在客户端的体现。

### 验证

双开 PIE → A 移动 → B 视角里 A 的 Mannequin 播走路/跑步动画（不再是僵硬滑行）。

## 第二项：BP_Weapon_Base 换弹蒙太奇（高优先级，1 小时）

### 为什么做

换弹逻辑已在 C++（`Reload()` → 2 秒定时器 → `FinishReload` 扣弹药），但视觉上还没有动画——玩家不知道换弹在进行。`BP_OnReloadStarted` 钩子就是为此设计的：C++ 通知"换弹开始了"，蓝图在这里播蒙太奇。

### 蒙太奇 vs 状态机：为什么换弹用蒙太奇

| | 蒙太奇（Montage） | 状态机（ABP 状态切换） |
|---|---|---|
| 特点 | 播放一次即结束，可指定起止帧 | 持续状态，自动循环 |
| 适合场景 | 一次性动作（换弹、挥拳、翻越） | 持续动作（走/跑/站立） |
| 可中断 | 可以——被打断时直接 Stop | — |

**换弹是一次性动作**（播完即回到 Idle）→ 用蒙太奇。

### 操作步骤

**2.1 确认换弹蒙太奇资产 ✅ 已有**

你的项目已有现成蒙太奇，**无需创建**：

```
/Game/XL_FPSPack/Weapons/MCX-VIRTUS/Animation/Weapon/Weapon_MCX-VIRTUS_Reload_Empty_Montage
```

这是 XL_FPSPack 自带的完整换弹蒙太奇（空匣换弹），直接引用即可。

**AN_Reload 不需要重建**——旧架构中 AN_Reload 负责在动画某帧"触发扣弹药"（逻辑混在动画通知里）。新架构中 C++ 定时器独立计时扣弹药，动画只是视觉演出——**逻辑与动画解耦，AnimNotify 不再承担任何逻辑职责**。如果后续想要帧级视觉同步（弹匣模型在第 X 帧消失），再创建纯视觉的 AnimNotify 即可（无逻辑）。

**2.2 BP_Weapon_Base 覆盖 BP_OnReloadStarted**

打开 BP_Weapon_Base → My Blueprint → Events → **BP_OnReloadStarted** → 右键 Implement Event：

```
Event BP_OnReloadStarted
    │
    ▼
Get Owning Character → Cast To BP_Player
    │
    ▼
Get ArmsMesh（BP_Player 上的 Skeletal Mesh 组件）
    │
    ▼
Get Anim Instance
    │
    ▼
Montage Play
    ├── Montage = Weapon_MCX-VIRTUS_Reload_Empty_Montage
    └── Play Rate = 1.0
```

**连线要点**：
- `Montage Play` 节点的 **Montage To Play** 引脚 → 选 `Weapon_MCX-VIRTUS_Reload_Empty_Montage` 资产
- Play Rate = 1.0（正常速度）
- 返回值（Montage Duration）不需要连——C++ 的 `ReloadTime` 定时器独立控制换弹时长

**2.3 蒙太奇播放完成后的状态恢复**

BP_OnAmmoChanged 覆盖里（换弹完成时触发）：

```
Event BP_OnAmmoChanged (InMag, Reserve)
    │
    ├── 调 HudRef → SetAmmo / SetReserve（弹药 UI 更新）
    │
    ▼
Get Owning Character → Get ArmsMesh → Get Anim Instance
    │
    ▼
Montage Stop (Montage = Weapon_MCX-VIRTUS_Reload_Empty_Montage)
```

> **蒙太奇时长 vs ReloadTime**：蒙太奇是视觉演出，ReloadTime 是 C++ 逻辑计时。
> 两者独立——蒙太奇 1.5s 播完但 ReloadTime 是 2s 时，有 0.5s 的"动画结束但还在换弹"间隙（正常）。
> 如果想精确对齐，把 Weapon 的 Reload Time 调成和蒙太奇时长一致。

**2.4 验证**

PIE → 打空弹匣 → 自动换弹：
- 手臂播放 MCX-VIRTUS 换弹动画
- 换弹音效（如果 Reload Sound 槽已填）
- 弹药 HUD 从 0 → 30
- 动画播完回到 Idle 姿态
```

### 验证

PIE → 按 R 换弹 → 手臂播放换弹动画 → 弹药 HUD 恢复 → 回到待机。

## 第三项：ABP_Arms 手臂动画状态机（中优先级，30 分钟）

### 为什么做

BP_Player 的 ArmsMesh（XL_FPSPack 手臂）现在只有默认 Idle 状态。射击和换弹时手臂应该有对应的动画响应（后坐力手抖、换弹动作），否则"开枪 = 手臂纹丝不动"。

### 架构说明

手臂动画和全身动画是**完全独立的两套 ABP**——它们互不影响：

```
本地玩家的屏幕：           远端玩家看到的：
┌────────────────┐       ┌────────────────┐
│  ArmsMesh      │       │  Mannequin     │
│  ABP_Arms      │       │  ABP_Manny     │
│  (第一人称)    │       │  (第三人称)    │
│  Idle/Fire/    │       │  Idle/Walk/    │
│  Reload 三态   │       │  Run 状态机    │
└────────────────┘       └────────────────┘
```

- ABP_Arms 控制"你的手看起来在干什么"
- ABP_Manny 控制"别人看到你在干什么"
- 两套动画由不同骨架驱动，互不干扰

### 操作步骤

**3.1 确认手臂骨架和动画资产**

1. Content Browser 搜 `ABP_FPSPlayer`（你现有的手臂动画蓝图）→ 打开看看内部结构
2. 它可能已经有状态机/AnimNotify → 记下结构（后续可能复用）
3. 如果是空的或结构粗糙 → 需要新建/改造

**3.2 新建 ABP_Arms（如果 ABP_FPSPlayer 结构不适合复用）**

1. Content/Code/Player/Animation/ 右键 → Animation Blueprint → 选手臂骨架 → 命名 `ABP_Arms`
2. 设计器里添加**状态机**（AnimGraph 右键 → Add State Machine）

**状态机结构**（三态）：

```
Idle Arms（默认）←→ Fire Arms ←→ Reload Arms
```

| 状态 | 内部资产 | 进入条件 | 退出条件 |
|---|---|---|---|
| Idle Arms | 手臂待机动画（XL_FPSPack 自带） | 默认 | bIsFiring 或 bIsReloading 变 true |
| Fire Arms | 手臂射击动画（后坐力手抖） | bIsFiring == true | bIsFiring == false（动画 Notify 回调设回） |
| Reload Arms | 手臂换弹动画 | bIsReloading == true | bIsReloading == false（BP_OnAmmoChanged 里设回） |

**转换条件**（每条 Transition Rule 里）：

```
Try Get Pawn Owner → Cast To BP_Player
    → Get 变量 bIsFiring / bIsReloading
    → Branch 连 Result
```

**3.3 bIsFiring / bIsReloading 变量管理**

在 BP_Player 里新建两个 bool 变量：
- `bIsFiring`：开火时设 true（BP_OnFireEffects 里），3 秒后动画 Notify 自动设回 false
- `bIsReloading`：BP_OnReloadStarted 设 true，BP_OnAmmoChanged 设 false

ABP_Arms 的 AnimInstance 通过 `Try Get Pawn Owner → Cast To BP_Player → Get bIsFiring` 读取。

**3.4 BP_Player 的 ArmsMesh 指定 ABP_Arms**

BP_Player → 选中 ArmsMesh 组件 → Details → Animation → Anim Class = ABP_Arms。

### 验证

PIE → Idle 手臂待机 → 开火播射击动画（后坐力手抖）→ 换弹播换弹动画 → 回到 Idle。

## 第四项：RemotePawn 上半身射击覆盖（低优先级，1 小时，M4 级打磨）

### 为什么做

远端玩家开枪时，Mannequin 的全身动画都是走跑状态——没有"开枪"动作。FPS 标准做法是**上半身播射击动画，下半身继续走路**（Layered Blend Per Bone）。

### 什么时候做

这是纯视觉打磨，不影响任何功能——**P2 完成后再做**（现在做会分散 P2 进度）。

### 原理说明

```
正常状态：        开枪时：
全身 Walk/Run     下半身 Walk/Run（不受影响）
                  上半身：射击动画覆盖（Layered Blend Per Bone）
```

### 操作要点（P2 完成后再详细展开）

1. ABP_Manny 复制一份为 `ABP_RemotePawn_Merged`（自定义版）
2. State Machine 输出后加 `Layered Blend Per Bone` 节点：
   - Base Layer = 走跑动画（全身）
   - Blend Layer = 射击动画（只覆盖上半身骨骼）
   - Blend bool = 远端玩家的 `bIsFiring`（通过同步消息或本地猜）
3. BP_RemotePawn 的 Anim Class 改为 `ABP_RemotePawn_Merged`

## 瞄准（ADS）：什么时候做、怎么做

### 位置：P3 后期或 P6 前，独立小特性

瞄准（ADS，Aim Down Sights）是**纯客户端本地表现**——服务器不知道也不关心玩家是否在瞄准（命中判定用的是射击时的 camera 朝向，开镜只是让你看得更清楚）。

| ADS 效果 | 归属 | 说明 |
|---|---|---|
| FOV 从 90° 降到 40°（画面放大） | **客户端本地** | 其他玩家看不到你的 FOV |
| 鼠标灵敏度降低（精细瞄准） | 客户端本地 | `Add Controller Yaw/Pitch Input` 乘以 ADS 灵敏度系数 |
| 手臂/武器切换到瞄准姿态 | 客户端本地 | ABP_Arms 的状态机加 ADS 状态，或蒙太奇 |
| 可选：服务器知道"我在瞄准" | **服务端规则**（如果要"瞄准时移速降低"） | 需契约面新消息，W3 一起做 |

### 什么时候做

**P2 完成、动画打磨完后**——瞄准需要一个"当前武器瞄准偏移"数据（每个枪的瞄准镜位置不同），这正是 P8 数据驱动的 `FWeaponDefinition` 里的字段（`AimOffset`）。提前做会和 P8 重复。

**快速原型**（不完美但能跑）：`IA_Aim`（你现有的输入资产）→ 按住时 `Get Player Camera Manager → Set FOV(40)`，松开恢复。这只需要在 BP_Player 加几个节点，10 分钟做完——可以现在做，后续再接武器姿态。

### 建议节奏

```
动画打磨穿插 P2（现在）：四项高/中优先级任务
P2 完成后：              RemotePawn 上半身覆盖（第四项低优先级）
瞄准快速原型：            P2 期间随手做（IA_Aim → Set FOV，10 分钟）
瞄准完整版：             P6 客户端预测时（ADS 灵敏度 + 武器姿态 + 可选服务端规则）
```

## 第五项：击中贴画系统——不同材质的弹孔/音效/碎屑（C++ 已实现，蓝图按此接线）

### 为什么做

子弹打中墙面目前没有任何反馈。资产其实早就齐了：13 套 `FX_Squib*` 碎屑特效 + 13 套
`SFX_Vefects_Shots_Squib_*_Cue` 音效（`Content/ShotSystem/`）+ 6 套弹孔材质实例
（`Content/Decals/Materials/MI_VFX_BulletDecal_*`）——缺的只是"打在哪、什么材质"的数据链和一套不卡顿的表现层。

**设计从性能教训出发**（2026-09 首枪卡顿排查：Niagara 运行时首编译 1.39s + 每枪 Spawn/Destroy 的 GC 债务）：

- **池化**：64 个贴画组件环形复用，写满覆盖最旧，永不销毁——GC 每轮"没账可收"；
- **错峰预热**：各表面命中特效每 0.1s 编译一个，绝不挤同一帧（把首枪卡顿换成开局卡顿是伪优化）；
- **数据驱动**：表面→表现的映射收在 DataAsset，换美术只改 DA 不动蓝图（P2/P8 数据驱动练兵同款）。

分工契约：**C++ 负责 trace、解 SurfaceType、管池子和预热；蓝图只决定"这个表面长什么样"；判定权仍在服务器**（`S2C_Hit` 不带位置也不用带——miss 时打在哪只有客户端自己知道）。

### C++ 已完成的部分（不用再写代码）

| 文件 | 职责 |
|---|---|
| `SightlineDecalPoolSubsystem.h/.cpp` | GameInstanceSubsystem：64 个 UDecalComponent 环形池（挂 WorldSettings）+ `SpawnDecal()` 蓝图可调 + 命中特效错峰预热（自动触发编译并打日志） |
| `SightlineImpactFXConfig.h/.cpp` | DataAsset 类型：`TMap<SurfaceType, {弹孔材质, 音效, 碎屑特效, 尺寸}>`，`TryGetImpactFX()` 查不到回落 Default 行 |
| `SightlineWeapon` | `FireShot` 增加表现层 trace（ECC_Visibility、忽略自己），命中即触发新钩子 `BP_OnShotImpact(Hit, SurfaceType)`；`BeginPlay` 自动调预热（前提是配了 ImpactFXConfig） |

### 操作步骤

**第 1 步：铺物理材质（最关键，漏了这步所有表面都查到 Default）**

1. `Content/Code/Physics/PM_Dirt` 右键 Duplicate，复制出 `PM_Concrete`、`PM_Wood`、`PM_Fabric` 等要区分的表面；
2. 打开每个 PM → Details → **Surface Type** 选一个互不重复的值（这就是后面查表的 key）；
3. 打开地图里每种材质 → Details → **Phys Material** → 指定对应 PM。⚠️ 材质不挂 PM，`DetermineSurfaceType` 永远返回 Default。

**第 2 步：创建 DataAsset**

内容浏览器 → 右键 → Miscellaneous → Data Asset → 选 `SightlineImpactFXConfig` → 命名 `DA_SightlineImpactFX`，按下表填行（key = 第 1 步各 PM 的 SurfaceType 值）：

| Key | Decal Material | Impact Sound | Impact System |
|---|---|---|---|
| `SurfaceType_Default`（兜底行，必填） | `MI_VFX_BulletDecal_Concrete` | `SFX_..._Squib_Concrete_Cue` | `FX_SquibConcrete` |
| PM_Dirt 的 SurfaceType | 同系列按表面填 | `..._Squib_Dirt_Cue` | `FX_SquibDirt` |
| PM_Metal 的 SurfaceType | `MI_VFX_BulletDecal_Metal` | `..._Squib_Metal_Cue` | `FX_SquibMetal` |

**第 3 步：武器蓝图接线（BP_Weapon_VIRTUS）**

1. Class Defaults → **Impact FX Config** → 填 `DA_SightlineImpactFX`（填了预热才会自动跑）；
2. Event Graph 添加 `Event BP_OnShotImpact`，按此接线：

```
Event BP_OnShotImpact (Hit, SurfaceType)
  → Get ImpactFXConfig → TryGetImpactFX(SurfaceType) → Branch(返回值) ─ true ─┐
   Cast to Pawn → 失败才继续（打人不贴贴画，可接 FX_SquibBlood）              │
   ├─ FX.DecalMaterial 有效：Get Game Instance → Get Subsystem               │
   │    (SightlineDecalPoolSubsystem) → Spawn Decal                          │
   │    (DecalMaterial=FX.DecalMaterial, HitLocation=Hit.Location,           │
   │     HitNormal=Hit.Normal, Size=FX.DecalSize)                            │
   ├─ FX.ImpactSound 有效：Play Sound at Location(Hit.Location)              │
   └─ FX.ImpactSystem 有效：Spawn System at Location(Hit.Location)           │
```

3. 删除旧的每枪 SpawnActor `BP_BulletDecal` 逻辑（如有）——池化系统就是来替代它的。

### 验证

PIE 启动日志应依次出现：

```
[DecalPool] 已预生成 64 个贴画组件
[DecalPool] 开始预热 N 个命中特效系统
[DecalPool] 命中特效预热发起: FX_SquibConcrete    ← 每 0.1s 一条
[DecalPool] 命中特效预热完毕
```

开枪：不同表面出不同弹孔/音效/碎屑，首枪无编译卡顿。打满 64 发后最旧的弹孔被覆盖（设计行为，零 GC）。

### 已知边界

- **远端玩家的弹着点**目前出不了弹孔：`S2C_Hit` 不带弹道 origin/dir，属协议演进项（服务器 Fire 广播补两个字段即可复用整池）；
- 弹孔尺寸 `DecalSize` 的 X 分量是投射深度，统一用 16cm 时对厚墙无穿透伪影。
