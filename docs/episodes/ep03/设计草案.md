## 2. 动画系统设计（本期主设计）

### 2.1 需求 → 机制映射（四条需求逐条落机制）

| # | 需求（领导原话） | 机制 |
|---|------------------|------|
| 1 | 同骨架，一套动画 | **一个 ABP 类（ABP_Mannequin），N 个实例**——本地角色与远端角色同骨架（SK_Mannequin），同一 AnimClass，零分支复用 |
| 2 | 全方向 + 上看下看流畅 | 移动层 = 2D BlendSpace（Speed × 方向角，8 向走位）；瞄准层 = AimOffset 2D additive（Yaw × Pitch） |
| 3 | 换武器自动换蒙太奇 | **武器动画数据表 FWeaponAnimSet**（§2.5）——C++ 按表查 Montage 播放，ABP 零武器分支；换武器 = 加一行数据 |
| 4 | 本地第一人称；远端显示正确 | 本地：相机挂头部 + 自身网格 OwnerNoSee（ABP 照跑）；远端：动画输入 = 网络状态（§2.4），位置差分算速度、网络 yaw/pitch 驱动 8 向与 AO |

### 2.2 一套 ABP 服务两类角色（关键架构）

```
本地角色：输入直读（WASD/鼠标）──┐
                                ├──→ ASightlineCharacter::Tick 聚合 FAnimInputs ──→ ABP_Mannequin
远端角色：ENTITY_STATE 网络喂 ──┘              （Speed·方向角·Yaw·Pitch·bFalling·WeaponType）
```

- 同一个 Character 类、同一个 ABP 类；**本地/远端只是 FAnimInputs 的数据源不同**——「对照组（本地丝滑）与实验组（远端随延迟劣化）同框」由此天然成立，正是本期演示画面
- 战位模式（strafe）：**角色朝向 = 视角 Yaw（网络量），移动方向相对朝向混合 8 向**——远端「向左走」= 向左动画（D3-01）

### 2.3 ABP 四层混合栈（自下而上）

| 层 | 内容 | 素材 | 期 |
|----|------|------|----|
| L3 武器动作层 | Slot `UpperBody` 查表 Montage + LayeredBlend 屏蔽下半身（边跑边开火） | FWeaponAnimSet 查表 | **ep05**（本期留空位） |
| L2 瞄准偏移层 | AO 2D additive，输入 = Pitch（网络） | `AO_MM_Unarmed_Idle_Ready`（成品） | **本期** |
| L1 移动层 | 状态机 Idle / Locomotion(BS) / Jump(腾空→落地) | `BS_MM_Unarmed_Jog_Walk` + MM_ 步态/Jump 序列 | **本期** |
| L0 骨骼层 | SK_Mannequin；Manny = 自己、Quinn = 远端（画面一眼分清谁是谁） | 已导入 | **本期** |

- 本期状态机只 3 态（Idle / Locomotion / Jump），Start/Stop/Pivot/TurnInPlace 全部 ep14——**素材已在库里躺着，摘就行**
- MM_/MF_ 双变体**只用 MM_ 系**（BS 仅有 MM_ 版；两套并接 = 翻倍工作量零收益，D3-14）

### 2.4 双数据源的硬细节（逐一校验抓出，**这是「对端卡死分不清网络还是动画」的解药**）

| 细节 | 事实 | 对策 |
|------|------|------|
| 远端直设位置**不产生引擎速度** | `SetActorLocation` 不走移动模拟，`GetVelocity()` ≈ 0——ABP 若读引擎速度，远端永远播 Idle（表现成「卡死」，实则数据源错） | Speed = **位置差分 + EMA 低通**（客户端本地，不占协议字节，D3-02） |
| 远端**腾空检测失效** | 远端 Pawn 的 MovementMode 恒 Walking，`IsFalling()` 永假——远端跳起来永远播不到 Jump | 协议带 **1B flags（bit0 = 腾空）**（D3-03） |
| 朝向/俯仰必须网络化 | 远端 yaw/pitch 服务器无从推断 | 上报带 yaw + pitch（f32 ×2） |
| 本地自机为什么永远丝滑 | 直发版服务器不回发自机位置（无回显）——延迟全在「看别人」上 | **本期教学点之一**：ep04 服务器权威后自机也会受延迟影响，前后对照 |

### 2.5 武器动画数据表 FWeaponAnimSet（「最重要的一条」的落地形态）

```cpp
// 换武器 = 加一行数据；ABP 图零改动。ep03 只填 Unarmed 行，ep05 摘其余三行
struct FWeaponAnimRow {
    EWeaponType  Type;
    TObjectPtr<UAnimSequence>  IdleAimPose;   // L2 瞄准层素材（AO 混合基底）
    TObjectPtr<UAnimMontage>   Fire;          // C++ PlayAnimMontage → UpperBody Slot
    TObjectPtr<UAnimMontage>   Reload;
    TObjectPtr<UAnimMontage>   Equip;
    // 武器骨骼网格体自己的动画（AM_Weap_*）ep05 随武器挂载一起接
};
```

- 蒙太奇播放完全由 C++ 驱动（查表 → `PlayAnimMontage`），**ABP 内无任何 per-weapon 分支**——上镜卖点：「换武器不改动画蓝图，加一行数据」
- 边跑边开火 = Montage 进 `UpperBody` Slot + LayeredBlendPerBone（spine_01 以上）屏蔽下半身；素材另有 `_Additive` 系（Reload/Equip/DryFire）作备份（D3-13）

### 2.6 第一人称处理

- 相机组件挂头部高度，`bUsePawnControlRotation`；鼠标 = Yaw/Pitch 控制旋转（Enhanced Input IA_Look）
- 自身网格 `SetOwnerNoSee(true)`：本地视角看不到自己（影子保留，定位用）；**自身 ABP 照常跑**——零分支复用，ep05 加 1P 手臂/枪模时不用改结构
- 素材子集**无 1P 手臂网格体**（Meshes 仅 SKM_Manny/Quinn/SK_Mannequin）——本期不做 Viewmodel（D3-06，ep05 再议：枪挂相机 or 借 3P 姿势）

## 3. 契约 v3 草案（14~18，批示后登记 MSG_IDS.md v3——1~13 一个字节不动）

| msgid | 名称 | 方向 | 字节布局 | 触发/推送时机 |
|-------|------|------|----------|---------------|
| 14 | `MSG_C2S_START_MATCH` | C→S | 空 payload | **仅房主**、在房中（D2-11 预留的兑现） |
| 15 | `MSG_S2C_MATCH_START` | S→C | `[4B 玩家数 n]{[4B PlayerId][1B 名长][名字][1B 出生点序号]}×n` | 广播全员 → 客户端切对局关卡、按名册生成角色 |
| 16 | `MSG_C2S_MOVE_REPORT` | C→S | `[12B pos xyz f32][4B yaw f32][4B pitch f32][1B flags]` | 30Hz（与服务器帧驱动同拍），对局中持续 |
| 17 | `MSG_S2C_ENTITY_STATE` | S→C | `[2B 数量 n]{[4B PlayerId][12B pos][4B yaw][4B pitch][1B flags]}×n` | 33ms tick 广播房内全员，**不含接收者自己**（自机无回显） |
| 18 | `MSG_S2C_ENTITY_LEAVE` | S→C | `[4B PlayerId]` | 成员离开房间/断线 → 对端销毁其角色 |

- 每实体 25B × 3 对端 × 30Hz ≈ 2.3 KB/s——**这个全量直发就是 ep09「带宽省 70%」的基线**，协议字段故意为对比实验留白
- 对局内断线：按既有规则重连后须重新 LOGIN（会话不保活）+ 实体已销毁——零新机制（D3-10）
- 对局退出 = LEAVE_ROOM（复用 10），对端收 18 回房间 UI；无胜负结算（ep07）

## 4. 服务器侧设计（ep02 图的生长点）

- **业务层长出新用例 `MatchService`**（与 LobbyService 并列，同样零 include net/*，纯单测）：StartMatch（在房校验）→ 返回名册广播事件；UpdateEntity（位置暂存）；Snapshot（快照组装）。**只认 PlayerId，不认 fd**（D3-15）
- **双用例互不 include，编排归适配层**（D3-15）：`wireMatch` 处理 14/16/断线——先查 lobby（是否房主 / fd→PlayerId / 房间名册，全部**纯数据过桥**），再调 match；MatchService 与 LobbyService 零依赖
- **实体**：`Entity{PlayerId, pos, yaw, pitch, flags}` 纯数据——服务器**只转发、不校验**位置（「故意做错」：此时改内存/改发包即可瞬移，正是 ep08 外挂期的攻击入口素材；ep04 上行从"位置"改"输入"+权威计算，位置校验自然失效，ep08 再补输入/频率校验与踢人）
- **帧驱动**职责 +1：分发帧之后、同 tick 内调 match 组装快照 → writer 投递（33ms，D3-08；与登录宽限清扫同属装配根编排）
- **FrameWriter** 扩展：Match 事件 → 15/17/18 帧翻译；广播展开复用 lobby 的 RoomMemberFds（除发者自己），适配层组合两个用例的查询（D3-15）
- **LobbyService 增量**：仅两个**纯查询**——IsHost(fd)、RoomRoster(roomId)（名字+加入序）；房主语义首次被消费——D2-11 预留兑现；出生点序号 = 名册序（FrameWriter 编码时落实）
- **关服收口（审计尾巴清偿，M1 同窗，D3-19）**：LobbyService 增 `ShutdownBroadcast()` 纯方法（每在线/宽限期连接一条 Kicked(code=3)），main 退回 `writer.deliver` 纯搬运——装配根零语义
- 依赖规则自检四问（ep03 口径）：① 换序列化——MatchService/Entity 零改动（编码在 FrameWriter）✓ ② 换传输——MatchService 不知道 socket ✓ ③ 脱离网络纯单测——名册校验/快照组装/位置暂存/离场清理全可测 ✓ ④ 新消息只注册——14/16 走 wireMatch，零改旧码 ✓

## 5. 客户端侧设计（ep02 图的生长点）

- **输入链路**（客户端图钦定类型）：Enhanced Input（IMC_Default + IA_Move/IA_Look/IA_Jump）→ ASightlineCharacter（ACharacter）→ 每 30Hz 调 `UMatchSession::ReportLocalState`（**纯结构入参，组帧在会话层**——Character 全程不碰字节，D3-17）
- **UMatchSession**（用例层，GI 持有并 OnFrame 转发，与 LobbySession 同构）：意图 StartMatch / ReportLocalState 只发包；收 15/17/18 解析 → 更新 **UEntityRegistry（纯态+委托，D3-16）**
- **UEntityRegistry**（D3-16）：PlayerId → FEntityState 纯映射，**零 UWorld 依赖**；15/17/18 → OnSpawned / OnUpdated / OnLeft 委托——生成/直设/销毁 Pawn 由**适配器（GameMode 侧 PawnSpawner）订阅执行**（自己=Manny/远端=Quinn；17 直设位置 + 喂 FAnimInputs，§2.4 对策落点）；Registry 可脱离 UWorld 纯单测（喂帧序、断言委托序）
- **GameMode_Sightline + L_Arena**：几何体小地图 + 4 出生点 + 静态光照（Phase A 交付物）；PIE 双开沿用（D2-15）
- **UI 增量**：房间界面房主见「开始对局」按钮（→ MatchSession 意图）；**Debug 面板（损伤滑块）本期首登场**——入站延迟队列落在**连接适配器**（0~500ms 滑块，延迟应用不丢包，D3-11）
- **传输端口倒置（审计唯一违规的修复，M4 第一项，D3-18）**：会话层声明 `ISendPort`（单方法 Send），`ConnectionSendPort` 适配器实现、GI 注入；两会话发包全走端口——第二个消费者（MatchSession）本期出现，按抽象时机判据从 ep09 提前；会话单测升级为 FakePort 断言字节布局
- **RoomListText 富文本升级（已实装编译通过，2026-10-15）**：UTextBlock → URichTextBlock（字段名不变）；名册列锚排版（房号 4 · 房名 24 · 人数 4 半角槽，全角补位，Font_Mono 等宽）+ 颜色标签 `<head>` 表头灰 / `<full>` 满员批示红——规格 `ui_roomlist_spec.drawio`，编辑器三步见蓝图操作方案 M2-E

## 6. 关键时序：A 建房 → 开始对局 → 双人互见（验收脚本原型）

```
A/B: 均已 LOGIN 且同房（ep02 时序照旧）
A(房主): START_MATCH(14) → 匹配校验
全员  ← MATCH_START(15, 名册+出生点) → 各自切 L_Arena、生成角色（0ms 下互相看见）
A/B: 各自 30Hz MOVE_REPORT(16) → 服务器 33ms 组快照
A/B  ← ENTITY_STATE(17, 不含自己) → 直设对方位置 + 喂动画
B: LEAVE_ROOM → A 收 ENTITY_LEAVE(18)，B 的角色消失
```

## 7. 损伤滑块与 KPI 采集

- **滑块**：客户端 Debug 面板，入站方向延迟队列（收包时间 + delayMs 才放行）——「自己不卡、看别人卡」是直发版最直观的教学点（D3-11）
- **KPI①**：0/50/150/300ms 四档操作手感主观分（自评表，脚本口播出对比）
- **KPI②**：位置误差曲线——**离线日志对齐**：发送端记「真实位置-时间戳」、接收端记「显示位置-时间戳」，对局后按时间戳对齐画差值曲线（不动协议，D3-12）
- **上镜镜头**：0ms 基线丝滑（Phase A 验收画面）→ 150ms 卡顿/瞬移/拉扯 → 滑块归零恢复——前后对比即本期标题
