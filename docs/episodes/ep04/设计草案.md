> 定位：系列第一个高光期。三部曲 = **variant 编解码（需求驱动）→ 主从 Reactor（演进兑现）→ 和解机制（挂新消息）**；客户端 = 预测先行 + 输入历史 + 回滚重放 + Debug HUD。

## §1 契约 v4（提案——批后登记 MSG_IDS.md）

### 1.1 新消息 19 · PlayerInput（C2S，25 字节）

```
[4B seq][12B 位置 xyz][4B 偏航][4B 俯仰][1B 状态] = 25B
```

- seq = 客户端本地预测序号（单调递增，uint32 回绕安全）
- 语义：16 号的升级版——服务器不再"记账"，而是拿它**推算权威位置**
- 16 号处置：保留但对局期停用（契约只增不改）；对局内客户端只发 19

### 1.2 17 号升级（**契约破例提案 · 待批 P1**）

17 号每实体 25B → **29B**：新增尾部 `[4B ackedSeq]`（服务器已确认的最新输入序号）。

- pos/yaw/pitch 字段**布局不变、语义升级**：从"转发客户端上报"变为"服务器权威推算值"
- **破例理由**：「只增不改」保护的是对外承诺；17 号第 3 期才定、第 4 期立即演进，属同一演进窗口；双端同仓同 tag 同步部署，无独立发布的旧客户端，真实兼容成本为零。破例在此记录（"先改文档"的规矩包含记录破例）
- 备选（不推荐）：独立 20 号 Reconcile 消息按拍下发——与 17 号内容近乎重复（24B vs 29B/实体），带宽双份

### 1.3 会话规则增补

- R10：对局内 16 号停用，19 号替代；服务器收到对局期 16 号视为无效帧丢弃（静默）
- R11：ackedSeq 语义——客户端收到快照中实体的 ackedSeq 即"服务器已确认该 seq 及之前的输入"

## §2 服务器三部曲

### 2.1 variant 编解码（先行——为 19 号开路）

**目标形状**：

```cpp
// protocol/messages_v4.h —— 每消息一个结构体，Parse/Encode 同居一处
struct PlayerInput { float x,y,z,yaw,pitch; uint8_t flags; uint32_t seq;
    static std::optional<PlayerInput> Parse(std::span<const uint8_t>); };
struct EntityStateV2 { uint32_t pid, ackedSeq; float x,y,z,yaw,pitch; uint8_t flags; /* Encode */ };
using C2SMsg = std::variant<Login, CreateRoom, …, StartMatch, PlayerInput /*…*/>;
```

- **Decode 两个落点**：`DecodeMsg(msgid, bytes)` 唯一 switch（msgid→选 Parse）；字节拆解与**长度校验全部进 Parse**（25→21 类欠账永绝）
- **Dispatcher → visitor**：`std::visit(overloaded{ handler<Login>{…}, handler<PlayerInput>{…} }, msg)`——签名 `(int fd, const Msg&)` 类型安全；未知 msgid 在 Decode 层拒绝
- **FrameWriter → visit Encode**：领域事件→S2C 结构体→Encode；编码解码同文件，双端漂移土壤铲除
- **迁移策略**：一条消息一条迁，msgid 级开关，旧 handler 并存；**客户端只做 Decode 集中化**（范围受控）
- 穷尽性：新增消息编译器逼补 handler（延续 -Werror=switch 纪律）

### 2.2 主从 Reactor（演进兑现）

**线程拓扑**（kIoThreads 配置；=0 即今日单线程——同一套代码两种形态）：

```
main 线程                          IO Worker ×N（独立 EventLoop + std::thread）
├─ Acceptor（收新连接）              ├─ 收字节 → TryDecode 切帧 → 投 frame_queue
├─ selectWorker（最少连接计数）      ├─ 归属连接的收发（EPOLLIN + 动态 EPOLLOUT）
├─ 定时器/时间轮/33ms tick          └─ 连接析构（同线程）
├─ 业务层（Lobby/Match 单线程串行）←——— frame_queue（唯一跨线程门）
└─ FrameWriter 编码 → outbound        MPSC：Connected / Frame / Closed 控制帧族
```

**三条铁律**：

1. 业务状态只在 main 线程碰——LobbyService/MatchService/连接表零锁，ep01「单线程世界」原则原样生效
2. 连接归属固定——fd 握手绑定 worker，该连接收发全在归属 worker（per-connection 零锁）
3. 队列先 mutex+deque，不上 lock-free（压测数据说话，ep12 决策点）

**交接机制**（复用现成原语，不新造）：`worker->queueInLoop([fd,peer]{ 建 ClientConnection + 注册 Channel })`——pendingFunctors_（mutex）+ eventfd 唤醒；**否决直接跨线程 epoll_ctl**（对象生命周期劈两线程+无唤醒语义+突发丢件）；**否决 SO_REUSEPORT**（无显式交接点，丢掉未来房间亲和的钩子）

**选择策略**：`argmin(connCount, N)`——计数归 main 单线程所有（accept 加、tick 处理 Closed 减），零锁零原子；轮询/一致性哈希/房间亲和留 ep12

**发路径**：main 编码完 → conn->Send = 写该连接 outbound 环形缓冲 + 首次入队 queueInLoop 到 worker enableWriting（EPOLL **MOD 动态挂摘**——唯一舞步点）；worker EPOLLOUT 排空 → 空则摘。第一版 outbound = mutex+deque

**关路径**：worker 发现 recv=0 → 投 Closed 控制帧 → main tick 统一消费（HandleDisconnect/lobby.Disconnect 时序原样）——**frame_queue 成为唯一跨线程门，与客户端 AsyncTask 对称**（"门就这一扇"双端闭环）

**不动清单**：LT 触发保持（一次只动一个变量，ET+readv 排干留 ep12）；时间轮/timerfd/心跳 echo 全在 main；业务层 45×3 单测一行不碰

### 2.3 和解机制（挂新消息）

**服务器（权威模式）**：

- UpdateEntity 升级：收 PlayerInput(seq) → **最小合法性钳制**（速度上限：本拍位移超界钳回——ep08 防作弊的预埋，本期只做保和解完整性所需最小版）→ 服务器**按输入自推权威位置**（权威=上次权威位置+钳制后增量）→ 存权威位+ackedSeq
- 快照照旧 33ms 拍点出，17 v2 布局，滤自己规则不变；**bHasReport 门控沿用**（未收到首条 19 的实体不进快照）

**客户端（预测先行）**：

- 本地照常先行移动（手感零等待）+ 每个输入入环形缓冲（**1s 输入史**：(seq, pos, yaw)）
- 收 17 v2 → 三方对账（per 实体）：

| 情况 | 处理 |
|---|---|
| \|权威位 - 本地同 seq 预测位\| < **ε（初值 5cm，实测定）** | 无感通过——只更新服务器认知；网络抖动不触发和解 |
| ≥ ε | **回滚**到权威位+ackedSeq → **重放**其后本地输入（Redo）→ 计和解次数 |
| seq 断档（缓冲中无 ackedSeq） | 朴素兑底：全量回滚到最新权威位 |

- 远端实体路径不变（17 直设，插值仍是省略项——ep09 的菜）

**Debug HUD（演示基建第二件套上线）**：AddOnScreenDebugMessage 扩展（零 UI 工作量）——实时显示：预测误差（当前/峰值）/ 和解次数 / 重放帧数 / 滑块值 / ackedSeq-本地 seq 差
