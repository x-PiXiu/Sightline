## 3. BotBrain 服务端决策（用户令写入·讨论稿）

### 3.1 架构定位：人机 = 没有网卡的玩家

```
真人：客户端输入 → 19 号 → match_wiring → MatchService.UpdateEntity
                  → 20 号 → match_wiring → MatchService.Fire（四道门+hitscan+回溯）
人机：BotBrain 决策  ──────────────────► MatchService.UpdateEntity（同一函数·同一钳制）
                    ──────────────────► MatchService.Fire        （同一四道门·同一判定）
```

- **BotBrain = 驱动适配器**（与 match_wiring 平级的"另一个输入源"）——MatchService **不知道人机存在**，人机只是一个 pid；
- **铁律**：人机的移动与开火**必须**经同一入口——不得直写 Entity、不得绕四道门（射速/弹匣/换弹一个不少）；人机超速照样被钳制——ep09 外挂期"人机不作弊"是结构性保证；
- **大厅侧登记**（评审❗1）：LobbyService 增 `botPlayers_`（pid/name/roomId），`RoomRoster` 合并输出→名册过桥零改动；人机无 fd → 天然收不到 S2C；Kick/顶号对人机跳过；
- **出生时机**（评审❗2）：StartMatch 后 BotBrain 立即以 spawnPoints[名册序] 调 UpdateEntity（首报即真值，与真人一致）——否则人机永落 (0,0,0) 幻影；
- **读侧**：BotBrain 经只读查询端口读权威世界（MatchService 增 `QueryWorld()` 快照式只读视图）；
- **ep06 回溯天然兼容**：人机是 Entity → 有历史环 → 真人瞄人机影子开枪，服务器照样倒带命中，零特殊逻辑；
- **主线程单线程**：BotBrain::Tick(nowMs) 挂服务器 30Hz tick，与 MatchService 同线程——零锁。

### 3.2 智能分层（"聪明"=可读的行为，不是最优的行为）

| 层 | 能力 | 依赖数据 | 本期 |
|---|---|---|---|
| **L0 移动** | 巡逻、绕障、追到射程内 | 导航栅格（§4 自动派生）+ 出生/巡逻点 | ✅ |
| **L1 感知** | 视线（墙后看不见）、听声（21 号枪响位置）、记忆（最后已知位置·3s 遗忘） | occluders（**复用 hitscan 的 CastRay**——人机看见的=子弹打得到的） | ✅ |
| **L2 战斗** | 反应延迟、瞄准误差收敛、转身速率上限、换弹时机、血少找掩体 | 掩体点（栅格自动选：墙后可隐蔽格） | ✅ 基础 |
| L3 战术 | 侧翼包抄、压点、团队配合 | 战术点位标注/影响力图 | ❌ 不做 |

**行业经验落地**：玩家感知的"聪明"来自**看得懂的反应**（发现你→转身→开枪→血少→躲墙后→探头），而非枪法准——太准的人机像外挂。四个"像人"的旋钮：

| 旋钮 | 默认 | 机制 |
|---|---|---|
| 反应延迟 | 250ms | **感知 = 查历史环(now − 250ms)**——ep06 的历史环直接给人机"人类反应速度"，零新数据结构 |
| 瞄准误差 | 首发 ±4° → 连射收敛到 ±1° | 误差锥随持续瞄准时间衰减（"越跟越准"） |
| 转身速率 | 360°/s 上限 | 禁止瞬间 180° 甩枪（防"锁头"观感） |
| 遗忘 | 3s 无视线 → 转搜索最后已知位置 | 记忆=上次看见的位置+时刻 |

**公平性对照**：人机读的是权威世界（无网络延迟），反应延迟旋钮把它拉回人类水平；视线限制保证**人机无透视**。

### 3.3 决策：有限状态机（FSM）

```
Patrol ──看见敌人──► Engage（转身→误差收敛→开火）
  ▲                   │ 敌人消失视线
  │                   ▼
  │◄──搜索超时──  Search（去最后已知位置）
Engage ──血量<30%──► TakeCover（栅格找最近隐蔽格）──回血/超时──► Engage
任意 ──hp=0──► Dead（复用真人死亡/重生状态机）
```

FSM 足够本期（状态 ≤6）；行为树/效用 AI 在状态 >10 时再上（留扩展点：状态接口化）。

## 4. 地图合同 v2（NewMap.json 完善·讨论稿）

### 4.1 现状缺口

现合同 = 遮挡盒×2（地板 + 一面墙）+ 命中体。**服务器不知道出生点**（v3 契约规则 7：出生=名册序，客户端挑 PlayerStart、服务器首报即真值）——**ep07 服务器权威重生必须知道出生点**，与做不做人机无关。

### 4.2 Schema v2

```json
{
  "map": "NewMap", "unit": "cm", "version": 2,
  "occluders": [...],                                        // 原样：挡子弹（默认也挡移动）
  "entityHitbox": { "radius": 34, "halfHeight": 88 },
  "spawnPoints":  [ { "pos": [x,y,z], "yawDeg": d }, ... ],   // 新：烘焙自 PlayerStart——重生/人机落位
  "patrolPoints": [ { "pos": [x,y,z] }, ... ],               // 新·可选：烘焙自 TargetPoint(tag=BotPatrol)
  "nav": { "cellCm": 50, "stepCm": 45 }                      // 新：栅格参数（栅格本身不入库）
}
```

**纪律**：导航栅格是**派生数据**——启动期从 occluders 算（单一真相源=occluders），不存进 JSON，防两份数据漂移。

### 4.3 导航栅格派生（nav_grid.h 纯函数·可单测）

```
① 地图 4000×4000 / 50cm 格 = 80×80 = 6400 格
② 只有与"身体高度带"相交的盒才挡路：盒顶 > 地面+台阶(45cm) 且 盒底 < 地面+身高(176cm)
   ——地板盒自动排除（顶面在脚下）
③ 盒按命中体半径 34cm 膨胀（闵可夫斯基和）→ 栅格化 → 中心点可达
④ A*（8 邻域）+ 视线拉直（栅格 LOS 跳点平滑）——6400 格最坏亚毫秒
⑤ 隐蔽格：对给定威胁点，CastRay 被遮挡的可达格（TakeCover 候选）
```

### 4.4 烘焙管道扩展（客户端 BakeLib）

SrvBakeOccluders 在现有 occluder 迭代外，增迭代 **APlayerStart → spawnPoints**、**ATargetPoint(tag=BotPatrol) → patrolPoints**；烘焙摘要增两项计数（防"放了没烘进去"）。

### 4.5 关卡补强（用户 UE 侧）

现地图（空地+一面墙）对人机智能**不可见**：直线可达任意点、无处可躲——L1/L2 行为没有舞台。建议补 **8~10 件掩体**（箱组/矮墙/长墙/中心掩体），构成：①视线可被切断的走廊 ②至少两条绕行路线 ③每个出生区附近有掩体。每件挂 Occluder 组件 → 烘焙。**纪律延续**：凡挡路的都要挂 Occluder（不挂=真人被 UE 物理挡、人机穿墙、子弹穿墙三不一致）。

- **感知**：墙后不可见（CastRay 复用）；反应延迟=历史环 now−250 采样；
- **人机同构**：人机开火过四道门（打空换弹同真人）；人机超速被钳制；
- **地图合同 v2**：spawnPoints/patrolPoints 解析；缺字段降级（无 spawnPoints=原点+告警）。
