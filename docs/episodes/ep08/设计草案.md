## 3. 配置体系：.lua 数据表 + 双缓冲 + 热重载

### 3.1 格式决策：服务端 .lua，客户端 DataAsset，同步走 30 号

> **判据：格式跟着生产者/消费者的生态走。**
> 人改的配置随服务端技术栈（.lua）；工具产的数据随工具母语（JSON）；客户端消费随 UE 母语（DataAsset）。
> ⚠ "双端同源文件"是伪需求——客户端从不读服务端的文件；运行时同步靠 30 号 wire。

| 层 | 格式 | 谁改 | 热更机制 |
|---|---|---|---|
| **数值**（枪参数/bot 旋钮/公式参数） | `game_config.lua`（纯数据表） | 运营/策划 | `reload` 整表换 |
| **公式**（伤害计算） | `damage.lua`（纯函数） | 开发 | `patch` 函数级换 |
| **决策**（人机 AI） | `bot_ai.lua`（纯函数） | 开发 | `patch` 函数级换 |
| **几何**（地图碰撞） | `map_geometry.json` | UE 烘焙工具 | 重启加载（C++ 工具产出 JSON 自然） |
| **客户端表现+预测兜底** | DataAsset | UE 编辑器 | 30 号运行时覆盖 |
| **双端同步** | 30 号 wire | —— | 自动 |

**"两条热更通道"故事**：同一个 .lua 格式，两种换法——数据表整体换（reload）vs 函数级换（patch）。观众看到的是机制差异，不是格式差异。

### 3.2 game_config.lua 形态

```lua
-- game_config.lua —— 纯数据表（⚠ 纪律：只放数字，不放逻辑）
-- 加载路径：sol2 读表 → C++ 逐字段校验（含跨字段）→ GameConfig 结构体 → 双缓冲
return {
    combat     = { damage_per_shot = 25, max_hp = 100, mag_capacity = 30,
                   reload_ms = 2500, fire_min_interval_ms = 95 },
    deathmatch = { respawn_ms = 3000, invuln_ms = 2000, kill_limit = 10,
                   spawn_clear_radius_cm = 150 },
    rewind     = { max_rewind_ms = 1000 },
    bot        = { react_ms = 250, err_start_deg = 4, err_end_deg = 1,
                   err_decay_deg_per_s = 3, turn_rate_deg_s = 360,
                   forget_ms = 3000, engage_range_cm = 900,
                   hp_cover_below = 30, move_speed_cm_s = 400,
                   fire_interval_ms = 400 },
    weapons    = { rifle  = { damage = 25, mag = 30, reload_ms = 2500, fire_ms = 95 },
```

### 3.3 收编清单（进表 vs 留编译期）

| 进 game_config.lua | 留编译期常量 | 理由 |
|---|---|---|
| 伤害/血量/弹匣/换弹/射速 | `kEye*` 三件 | 双端瞄准合同（改一侧必同步另一侧） |
| 重生/无敌/十杀/选点排斥 | `kEntityHistoryCap` | 结构容量（改需重建历史环） |
| 倒带上限 1000ms | `kMaxRangeUu` | 数值护栏 |
| BotTuning 十旋钮 | `kNav*` 四件 | 导航栅格参数（改需重建栅格=范围外，注释标"改需重启"） |
| weapons 表（每枪参数） | `kPi` | 数学常量 |
| formula 表（公式参数） | | |

### 3.4 双缓冲 + 版本 + 回滚

- **双缓冲**：`std::atomic<std::shared_ptr<const GameConfig>>`——加载→校验→原子替换→旧表 shared_ptr 延迟回收。消费方拿局部 `auto c = cfg_;` 防半途换表撕裂。
- **版本号**：`v{会话序号}-{FNV1a_hash8}`（如 `v7-a3f2c1d8`）+ `version_note`（操作人动机一行话）。
- **快照环**：内存保留最近 4 版——`rollback` = 换回上一版（**内存 revert，不重读磁盘**——坏文件可能还在）；审计行标注"与磁盘分叉"警告。
- **校验**：全字段范围检查（`0<reloadMs<10000` / `mag∈[1,100]`…）+ **跨字段关系**（`err_end_deg ≤ err_start_deg` / `fire_interval_ms ≥ fire_min_interval_ms` / `invuln_ms < respawn_ms`）——任一不过=**整表拒收**保留旧表+红字告警。
- **审计时钟**：UTC 墙钟（与游戏内 ADR-1 steady 单钟分立各司其职）。

### 3.5 热重载语义（三条·测试钉住）

| 类型 | 语义 | 例子 |
|---|---|---|
| **数值类** | 下一发/帧即时生效 | 伤害 25→50，下一枪就变 |
| **倒计时类** | 只影响后续事件，在途不动 | 已上钟的换弹用旧 reloadMs 到期 |
| **容量收缩** | magUsed>新容量→下次开火 MagEmpty→自动换弹补到新容量=自愈 | 弹匣 30→25，已打 28 发 |

### 3.6 reload 通道

- main.cpp 加 stdin 命令线程：`reload` / `rollback` / `version` / `help`——命令表结构预埋 level 字段（ep08 只有 console=最高级，GM 权限分级雏形）。
- **线程安全（A1 修复）**：stdin 线程只入轻量命令队列，**主循环每帧开头消费**（33ms 延迟无感）——Lua 永远只被主循环碰，单线程语义保住。
- 路径解析：env > CWD > exe 同级 > exe 上级（ep05 烘焙链同款）。

## 4. Lua 脚本层：策略接口 + 沙箱 + 热修

### 4.1 依赖倒置：接口归内层，实现归外层

```cpp
// ── 实体层（include/match/policies.h·零 sol2 痕迹）──
struct HitContext { float dist = 0.f; bool headshot = false; };

struct IDamagePolicy {
    virtual float Apply(float hp, float base, const HitContext& ctx) = 0;
    virtual ~IDamagePolicy() = default;
};
struct BuiltinDamagePolicy final : IDamagePolicy { /* 现行 DamageApply 搬入 */ };

struct IBotPolicy {
    virtual BotIntent Decide(const BotWorldView&, BotState&, BotMemory&,
                             std::uint64_t nowMs, const BotTuning&) = 0;
    virtual ~IBotPolicy() = default;
};
struct BuiltinBotPolicy final : IBotPolicy { /* 转调现行 Decide */ };

// ── 适配器（adapters/scripting_lua.cpp·唯一 include sol2）──
class LuaDamagePolicy : public IDamagePolicy { /* sol2 pcall damage() */ };
class LuaBotPolicy    : public IBotPolicy    { /* sol2 pcall bot_decide() */ };
```

### 4.2 Lua 三个面 + 两种热修

| 面 | 载体 | 热更机制 | 审计 |
|---|---|---|---|
| **参数面** | `game_config.lua`（纯数据表） | C++ 双缓冲 reload（整表换） | t_config_version |
| **公式面** | `damage.lua`（纯函数） | **同 lua_State 函数表原子替换**（dofile→沙箱自测→swap→旧表 GC） | 同上+diff |
| **决策面** | `bot_ai.lua`（同签名换实现） | 同上 | 版本行 |

### 4.3 沙箱红线

- `luaopen` 只开 base/string/math/table——**`os`/`io`/`package` 不装**（不用 `luaL_openlibs`）。
- `nowMs` 一律 C++ 传参（ADR-1 延伸：**Lua 不持钟**）。
- **内存 cap**（B4 修复）：`lua_Alloc` 包计数分配器，超 32MB→分配失败→Lua 抛错→pcall 兜底接住→告警。
- **出口校验**（A3 修复）：
  - `LuaDamagePolicy::Apply` 返回值必须有限且在 `[0, hp]`，否则回退内建；
  - `LuaBotPolicy::Decide` 出口 sanitize（坐标 clamp 到活动区/aimYawDeg NaN 兜底/枚举越界 switch 兜底）。

### 4.4 pcall 兜底：脚本崩不塌服务器

```
Lua 调用 ──pcall 成功──► 用返回值
           ──pcall 失败──► 回退 BuiltinDamagePolicy / BuiltinBotPolicy
                         + 告警计数 + 日志（"降级可以但必须喊一声"）
```

### 4.5 upvalue 陷阱彩蛋（大纲钦定演示）

```lua
-- v1：local base = 25        ← upvalue
-- function damage(hp) return math.max(0, hp - base) end
-- 热修 v2 改 base = 50：函数表 swap 后，若 C++ 持有的是 v1 闭包引用 → 照跑 25
-- 演示：改了不生效 → 逐帧抓真凶（闭包捕获）→ 修法 = swap 引用而非改值
```

### 4.6 调参纪律（C1）

`bot_ai.lua` / `damage.lua` **可调值一律从注入参数表读**，不许写 local 常量——防双源漂移。脚本只写逻辑（怎么用这些值），不写值本身。

### 4.7 对拍测试

- 同输入序列 C++ 基准 vs Lua 输出逐字段一致（**epsilon 浮点比较**——Lua double vs C++ float，中间结果可能差末位）。
- 防热修破坏行为：对拍不过=patch 被拒。

## 5. 三库数据层：按形态与热度选库

### 5.1 选型判据（面试论点）

> **按数据的形态（行/文档）与热度（快/慢）选库。**

| 库 | 一句话 | 管什么 | 形态/热度 |
|---|---|---|---|
| **Redis** | 按**热度**选 | 击杀榜 ZSET / 封禁热名单 TTL | 热·快·可过期 |
| **MySQL** | 按**形态：结构化行** | 战绩聚合行 / 配置审计行 | 冷·稳·要查询 |
| **MongoDB** | 按**形态：文档** | 战报明细（嵌套时间线）/ 未来玩家档案 | 半冷·灵活 schema |

**其他库的排期位**：MongoDB 玩家档案=ep10+；ClickHouse/ES=离线分析侧；Kafka=ep12+ 跨服；分库分表=单服 QPS 到了才做。

### 5.2 persistence 架构：事件订阅（不在用例层开 IStore）

```
MatchService::Tick()/Fire() ──事件向量──► main.cpp 三点扇出（B1 修复）
    ├─► writer.deliverMatch()（现有 wire 分发）
    └─► persistence.ingest(const& events)     ← ★ 三处各加一行
            ├─ MatchStart：开档（match_id = UTC 墙钟戳+会话内序号）
            ├─ Kill：战报缓冲 append + Redis ZINCRBY
            ├─ Ended：flush 战报文档(Mongo·best-effort) + t_match_result 行(MySQL·must)
            └─ AbortMatch：落空档（end_reason=2 战报也是战报）
```

**三个事件源**（B1 修复）：`match.Tick()`（main.cpp:239）+ `botDriver.Tick()`（main.cpp:238）+ `match.Fire()`（match_wiring 处理器内）——**三处各喂 `persistence.ingest()`**，通过 `std::function` 回调注入（组合根接线，MatchWiring 不直接依赖 PersistenceAdapter）。

### 5.3 双队列分级（C 修复）

| 队列 | 策略 | 丢了怎样 |
|---|---|---|
| **审计队列** | 不设界（或很大）**不丢** | 法律级——丢了就追责 |
| **统计/战报队列** | 1024 有界，满=丢+计数告警 | 可丢——对局优先于落库 |

**doctrine：丢得起/丢不起分级。**

### 5.4 三水槽设计

| Sink | 落什么 | DDL | 真相/投影 |
|---|---|---|---|
| **MySQLSink** | `t_config_version(version,source,diff_digest,note,created_at)` + `t_match_result(match_id,player_name,kills,deaths,ended_at,**config_version**)`（B3 修复：战绩行也带配置版本） | `init.sql` | **真相（must）** |
| **MongoSink** | 战报文档（roster/scores/kill_timeline/config_version/extra 空位）；索引 `_id` 唯一+`started_at` 倒序 | `init.js` | **尽力而为（best-effort）**+丢弃计数 |
| **RedisSink** | 击杀榜 `ZINCRBY leaderboard`；封禁通道 API（`ban(name,ttl)`/`is_banned`——ep08 只建通，ep09 消费） | —— | **投影**（MySQL 是真相；`REBUILD` 命令从 t_match_result 重建） |

**双写不一致（I 修复）**：MySQL 成功+Mongo 失败=聚合在、明细丢——doctrine：MySQL 行=must，战报明细=best-effort+丢弃计数。企业真解 outbox/事件溯源=口播对照不实现。

### 5.5 降级与生命周期

- **降级**：任一库挂=该 sink 丢弃计数+告警，**游戏零中断**（企业爆点镜头）；三库全挂=对局照打。
- **优雅停机**（B6 修复）：shutdown 三步——停 ingest→等队列清空（超时 2s）→join worker→三库正常断开。
- **生命周期**（J 修复）：`scripts/db_up.sh`（一键起三库+健康检查）+ 服务器**启动横幅**打印三库连接状态（✓/✗）。
- 连接串走环境变量（`SIGHTLINE_MYSQL_DSN`/`MONGO_URI`/`REDIS_URI`）。

### 5.6 战报文档 schema（BSON）

```json
{
  "_id": "20261106T023015Z-003",
  "config_version": "v7-a3f2c1d8",
  "started_at": ..., "ended_at": ..., "duration_ms": 85000,
  "end_reason": 1,
  "roster":  [ {"name": "cdp", "spawn_index": 0} ],
  "scores":  [ {"name": "cdp", "kills": 10, "deaths": 2} ],
  "kill_timeline": [ {"t_offset_ms": 12000, "killer": "cdp", "victim": "Bot2"} ],
  "extra": { }
}
```

- `match_id` = **对局开始 UTC 墙钟时间戳+会话内递增序号**（C3 澄清：跨重启唯一）。
- `extra` 空位 = 未来模式差异（手雷/多武器局）的自由位——文档库的意义就在这格。

## 7. 客户端设计

### 7.1 数据流

```
DataAsset（烤在包里·表现资产+预测兜底）──► 初始加载
```

## 8. 模块 × Lua 判定表（热区/冷区）

> 判据：**变化速率 × 错误代价**——运营天天要改、改错能回滚→Lua/配置；错一次全服塌/性能每帧掏钱/双端合同→C++。

| 模块 | 判定 | 企业同款 | 理由 |
|---|---|---|---|
| net/*（epoll/event_loop） | ❌ C++ 永久 | ✅ | 性能与正确性本体 |
| frame_codec + protocol | ❌ 双端合同 | ✅ | 契约脚本化=性能+安全双输 |
| lobby/match 编排 | ❌ 编排留 C++ | ✅ | 流程错一版=全服塌 |
| **常量/参数** | ✅ game_config.lua | ✅ | 运营改得最勤 |
| fire_judge 几何求交 | ❌ 每发子弹都跑 | ✅✅ | 性能自杀+作弊面 |
| ConsumeWeaponGate 状态机 | ❌ 执行留 C++ | ✅ | 正确性本体（参数已进表） |
| **DamageApply 伤害公式** | ✅✅ damage.lua | ✅✅ | 平衡/Buff=运营天天改 |
| **bot_brain::Decide** | ✅✅ bot_ai.lua | ✅ | 策划调手感不找程序员 |
| nav_grid 寻路 | ❌ 算法+性能 | ✅ | 企业用 Recast（C++） |
| **GM/运维命令** | ✅✅ 命令内容 Lua | ✅✅ | 补偿/封禁/活动开关=运营工具 |
| 活动/任务/邮件（未来） | ✅✅ Lua | ✅✅ | 内容脚本化=企业标配 |

**收口**：Lua 四面 = **伤害公式、bot 决策、GM 命令内容、（未来）活动内容**。几何/门/编排/契约/网络全留 C++。

## 12. 运营操作流

### 12.1 改枪参数（30 秒·热生效）

```
编辑 game_config.lua → 服务器终端敲 reload → 完
```
自动：校验→版本号→审计→30 号广播→客户端运行时覆盖→下一发生效。

### 12.2 新增换皮枪（同机理·半小时）

| # | 做什么 | 重编 |
|---|---|---|
| 1 | game_config.lua 加 `weapons.shotgun = {…}` | ❌ |
| 2 | EWeaponType 加 `Shotgun=2`（**双端同步**·契约锁） | ✅ 双端 |
| 3 | UE 建 `DA_Weapon_Shotgun`（拷 Pistol 改引用） | ❌ |
| 4 | （若未动态绑定）换枪输入加键 3 | ✅ 客户端 |

### 12.3 新增机理枪（散射等）

上面 4 步 + `damage.lua` 加散射分支（Lua 热修）或 fire_judge 加多射线（C++ 冷区）。

### 12.4 一键回滚

`rollback` → 内存快照环上一版 → 秒回。审计行标注"与磁盘分叉"。
