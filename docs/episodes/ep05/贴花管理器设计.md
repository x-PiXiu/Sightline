# 贴花管理器设计（Sightline DecalManager）——企业级缩小版

> ep05 · 2026-10-29 定稿 · 实现：`Game/SightlineDecalManagerSubsystem.{h,cpp}`
> 本文档同时是 ep05 脚本素材源（深度定律：脚本=开发期决策转译，本文记录每一步"为什么"）

## 1. 背景与演进四阶段

| 阶段 | 方案 | 结局 | 教训 |
|---|---|---|---|
| v1 组件池 | `NewObject<UDecalComponent>(池子系统)` + `RegisterComponent` + FIFO | **静默不可见** | 组件注册硬性要求 Owner Actor（见 §3 引擎源码证据） |
| v2 引擎原生 | `UGameplayStatics::SpawnDecalAtLocation(LifeSpan=6s)` | 能用，每秒建删+GC 波动 | 正确但无预算上界，规模放大即显形 |
| v3 环池管理器（**本文**） | 固定 64 槽 ADecalActor 环形复用 + 策略层 | 企业形态：预算上界、稳态零分配 | — |

演进的每个坑都成了设计约束：v1 的教训 → 槽位必须是 Actor（引擎语义标准）；v2 的教训 → 寿命必须归管理器（不能靠引擎 LifeSpan 无界建删）。

## 2. 架构划线（整洁架构 · 依赖永远向内）

```
Character（适配器：上下文翻译——眼位估计/探针取法线，Character 独有的相机与 Pawn 上下文）
   │ 组装 FSightlineDecalRequest（纯数据过界）
   ▼
USightlineDecalManagerSubsystem（用例：预算/复用/剔除/淡出/可观测 策略层）
   │ 驱动
   ▼
ADecalActor × 64（谦卑对象：无逻辑只摆位，引擎最外圈细节）
```

- **域层（MatchSession）对贴花一无所知**：21 号广播的是纯数据 `FSightlineFireResult`，贴花是表现层的自主决策；
- **体检四问**（手册 §7.6E）：换渲染方案（DecalActor→RT）改业务？否（请求结构即边界）；换调用方（ep15 手雷）改管理器？否（新参数组）；接新外部系统？不动内核；
- **诚实标注**：预算/环指逻辑仅一行取模，抽纯函数属过度设计——验收走可观测计数（Spawned/Reused）+ PIE 冒烟，而非脱引擎单测。

## 3. 关键决策记录（ADR）

### ADR-1 组件池在 UE 里不成立（引擎源码定罪）
`UActorComponent::RegisterComponent()`（`ActorComponent.cpp`）：
```cpp
AActor* MyOwner = GetOwner();
UWorld* MyOwnerWorld = (MyOwner ? MyOwner->GetWorld() : nullptr);
if (ensure(MyOwnerWorld)) { RegisterComponentWithWorld(MyOwnerWorld); }
```
组件注册**硬性要求 GetOwner() 返回 Actor**——池对象（outer=子系统）没有宿主，注册永远失败，组件永不渲染。结论：**可池化的是 Actor 和 Widget，不是自由组件**；"组件池"是伪需求。PIE 实勘证据：日志 `[弹孔] 活跃=32` 与屏幕零显示并存，`ensure(MyOwnerWorld)` 被 error reporter 同栈去重只报一次。

### ADR-2 槽位 = ADecalActor，而非"管理器 Actor 挂 64 个组件"
组件形态省 63 个 Actor 壳，但 Owner 语义要手工维护（ADR-1 雷区）；Actor 槽位引擎语义最标准（Spawn/隐藏/位置原生支持）。64 个无 tick 无网络的 Actor 壳开销可忽略。**选稳妥路线**。

### ADR-3 懒增长而非开局预热
前 64 发逐发 Spawn（无开局建件卡顿），填满后纯复用。对比预热：省一次加载期 hitch，代价是增长期无池收益——600 RPM 下 6.4 秒即达稳态，可接受。

### ADR-4 环形指针 = LRU
所有槽 age 均匀递增（按获取顺序），`Next=(Next+1)%Cap` 的环形覆盖与 LRU 等价，免维护时间戳。

### ADR-5 复用槽"取用即重置"
复用件自带未完成的淡出状态——显形前必须重置 `FadeStartDelay/FadeDuration`（池纪律：出生即隐藏、归还即重置、**取用即清账**）。

## 4. 策略层（专业性主体）

| 策略 | 实现 | 常量 |
|---|---|---|
| 预算上界 | 容量 64 槽环形覆盖，内存/渲染/GC 全部可预期 | `kCapacity=64`（企业 200~500） |
| 视口剔除 | `FadeScreenSize=0.02`，远处小贴花引擎自动隐去 | 撤此前反模式（0=永不剔除） |
| 距离剔除 | 落点距所有本地玩家 >8000cm 不生成（无人可见） | `kMaxRelevantDistance` |
| 淡出策略 | 显形 4s → 2s 淡完 | `kFadeStartDelay/kFadeDuration` |
| 防御校验 | 材质空/落点零向量 → 拒收（管理器不信任调用方） | — |
| 跨局自愈 | 切图销毁槽位 → UPROPERTY GC 置空 → 取用时就地重 Spawn | 槽位环 UPROPERTY 红线 |
| 可观测性 | Spawned/Reused 双计数（BlueprintPure）+ 预算满一次性日志 | 资源系统必须可观测 |

## 5. 生命周期全景

```
MATCH_START → GI.HandleMatchStarted → Mgr.Reset()（清账+计数归零，新对局=新预算周期）
第 1~64 发 miss → 懒增长（逐发 Spawn 隐藏槽位并显形）
第 65 发起   → 稳态复用：最老槽 挪位+显形+重置淡出（零分配零销毁）
对局结束切图 → 世界拆除销毁槽位 → GC 置空 → 新对局 Reset+自愈重建
```

## 6. 网络侧契约（已验证的企业一致项）

弹孔是纯表现：**绝不复制贴花 Actor**——服务器广播命中事件（21 号，22B 含落点），各客户端本地生成。法线不进契约（22B 一次定稿零改动），客户端用"落点 ±15/5cm 短程探针"回溯墙面法线（墙面点必命中该面；10km 天端点探空自动跳过=天然守卫）。

## 7. 验收标准

- 对同一面墙打 100 枪：`SpawnedCount` 停在 64 不再涨；`ReusedCount` 持续增长；
- 第 65 发日志出现 `[贴花] 预算满（64）→ LRU 覆盖开始`（一次性）；
- 弹孔正常显示（24cm）、4s 后淡出、对局结束无残留；
- 距离剔除：远处（>80m）着弹不生成（可用日志 absence 验证）。

## 8. ep15 扩展点

手雷焦痕 = 新的 `FSightlineDecalRequest` 参数组（更大 Size、不同材质、更长淡出）——管理器零改动。若焦痕需要"永久累积"语义（战场痕迹），届时评估 Render Target 贴花路线（另一条企业路径），请求结构即切换边界。
