## 2. 契约新增（草案，定稿才入 MSG_IDS.md）

| msgid | 名称 | 方向 | payload | 说明 |
|-------|------|------|---------|------|
| 20 | MSG_C2S_FIRE | C → S | **空** | 开火请求。**空 payload 是设计核心**：方向、位置、命中结果一概不收——判定全用服务器权威状态（pos/yaw/pitch 来自 19 号上报的权威推算），客户端连"往哪打"都不让插嘴（14 号 START_MATCH 同款纪律） |
| 21 | MSG_S2C_FIRE_RESULT | S → C | `[4B shooterPid][1B result][4B victimPid][12B hitPoint f32×3][1B victimHp]`（22B） | **房内全员广播**（不是只发射手）：shooter 用来出 Hitmarker、其余人用来画 tracer、victim 用来出红闪——一条消息三方共用。result：0=未命中（victimPid=0、victimHp=0 填充，hitPoint=射线终点——遮挡面交点或最大射程端点，tracer 据此停在墙上）/ 1=命中（victimPid+hitPoint 有效，hitPoint=圆柱面交点）。**victimHp=命中后余血（0~100）**：ep05 供 Debug HUD 血量行+受击红闪，ep07 接血条与死亡判定——**契约一次定稿，ep07 零改动**。tracer 两用：终点永远是 hitPoint |

编码侧：`Parse/Encode 同居`（variant 纪律）、`DecodeC2S` 唯一 switch 补 20 号分支、**20 号带 payload 直接拒收**（长度守门进 Parse）。

## 3. 服务器判定流水线（收到 20 号后的顺序，一处不过即静默丢）

```
① 在对局中？         ——未开局/已离房：丢（对局期消息 R10 纪律）
② 换弹中？           ——now < reloadUntilMs：丢；**到期（now ≥ reloadUntilMs 且 magUsed ≥ 30）就地补满 magUsed = 0**——状态机恢复时机必须显式，否则换弹后永远打不响
③ 弹匣空？           ——magUsed >= 30：触发换弹（reloadUntilMs = now + 2500），丢
④ 射速窗口？         ——now - lastFireMs < 95：丢（拒收计数 +1，ep08 升令牌桶）——**服务器阈值 95ms < 客户端步进 100ms**：时钟抖动不吞贴线射击
⑤ hitscan 判定       ——§4 数学（先遮挡原语盒/球、再打人，取最近者——§4.5），得 result/victimPid/hitPoint
⑥ 结算扣血           ——命中：victimHp = max(0, victimHp − 25)；**血见底钳 0 不触发死亡**（死亡状态机 ep07 启用）
⑦ 扣弹 + 记时        ——magUsed++；lastFireMs = now
⑧ 广播 21 号         ——房内全员（含射手自己）
```

**接口预留（第 6 期回溯）**：⑤ 的判定时刻自本期起做成参数 `judgeAtMs`（默认 = now）——回溯期只换这一个参数，流水线其余步骤不动。

**静默丢**是有意的：ep05 不给拒绝回执（省一条消息、ep08 才有"违规可见"的叙事），客户端本地跑同一套规则（§6）保证表现侧节奏一致，服务器校验兜底——**表现层预测、裁决层权威**，和移动同步同一个方法论。

## 4. hitscan 数学（服务器没有物理引擎——纯解析几何，这是本期设计故事核心）

### 4.1 方向重建（契约公式，双端一致）

UE 左手系 X 前 Y 右 Z 上；yaw 绕 Z（逆时针正）、pitch 抬头正，均为度。服务器存的是权威 yaw/pitch（末次上报即权威，`match_service.h` Entity 注释原文）：

```
rad = deg × π / 180
dir = ( cos(pitch)·cos(yaw),  cos(pitch)·sin(yaw),  sin(pitch) )   // 单位向量
```

### 4.2 射线起点（对齐客户端相机位）

客户端相机在胶囊上 `（18, 0, 82）`（SightlineCharacter.cpp:38）。服务器用权威 pos（=客户端上报的胶囊中心）重建同一点：

```
O = pos + Rot(yaw)·(18, 0, 0) + (0, 0, 82)
```

取舍记录：pitch 分量的 18cm 前移忽略（Rot 只转 yaw），误差 ≪ hitbox 半径 40，不值得为它多转一层。

### 4.3 命中体：垂直圆柱（参数=角色胶囊真身，烘焙而来）

| 常量 | 值 | 依据 |
|---|---|---|
| 半径 R / 半高 H | 烘焙值（默认 40 / 90） | **几何合同 §4.5 的 `entityHitbox`**：烘焙工具从角色蓝图 CapsuleComponent 读真实半径/半高——服务器判定体=客户端胶囊真身，不再猜（默认值仅作烘焙缺失兜底） |
| 最大射程 Lmax | 10000uu | 100m（1uu=1cm），对局地图内够用；未命中时 hitPoint = 射线终点（遮挡面或 Lmax 端点） |

服务器不收客户端胶囊的**运行时**参数——它是**构建期**随几何合同一起烘进库的合同数据。头部球（爆头分档）字段已在 schema 预留（`entityHitbox.headSphere`），第 7 期启用；逐肢体（物理资产）不做——需服务器骨骼姿态，带宽爆炸（D5-12）。

### 4.4 线段-圆柱求交（解析解，O(n) 扫全场实体）

对每个在场实体（除射手自己，18 号已离场的不在列）：

1. 投影到 XY 平面解圆：`|(O.xy + t·D.xy) − C.xy|² = R²`，一元二次，取实根中落在 `[0, Lmax]` 的最小 t；
2. 高度校验：`O.z + t·D.z ∈ [C.z − H, C.z + H]`，不过则该实体未中；
3. 全场取 t 最小者（挡子弹：两实体重叠，近者中）；
4. 无交 → result=0，hitPoint = O + Lmax·dir。

**为什么不用射线检测组件**：服务器没有 UE/物理引擎，引入一个物理库只为一条线段是依赖倒置；解析解 30 行、可单测、O(n)（对局 4 人，n² 都无所谓）——"企业级缩小版"的取舍要的就是这个明说。

**求交原语扩展（几何合同 v2 语义）**：遮挡不再限于轴对齐 AABB——

| 原语 | 服务器求交 | 说明 |
|---|---|---|
| 盒（带姿态，OBB） | 射线变换进盒子局部系 → **复用 slab 法** | 旋转过的下载地图 mesh 不再"变胖"，轮廓是真身 |
| 球 | 一元二次（与圆柱同族） | 圆柱状遮挡/近似 |
| 凸包 / 三角网格 | **不取** | 序列化与逐面求交成本不成比例（D5-12）；复杂 mesh 无简单碰撞时退化 AABB 兜底 |

原语枚举自 UE 简单碰撞（Simple Collision）的盒/球元素，烘焙时带局部变换组合进合同数据——全部仍是解析几何、仍可单测。

### 4.5 地图几何：编辑器烘焙合同（穿墙防线的正解）

**问题**：射线只和实体圆柱求交的话，**隔墙开枪服务器照样判命中**——观众一眼能看穿的穿帮，必须在本期堵住。

**方案（2026-10-24 用户批，替代手填合同表）**——**组件标记 + 编辑器一键烘焙 + 服务器启动加载**：

```
【客户端·编辑器期】                            【合同文件】                【服务器·启动期】
下载地图摆进 NewMap                             │                           main 装配时
→ 遮挡物挂 USightlineOccluderComponent          │                           map_geometry_loader
  （运行时零逻辑标记件，类型无关，               │                           读 JSON → 校验
   批量 Add Component 可行）                     │                           → 交给域层
→ 一键烘焙：扫组件 → 枚举简单碰撞原语        ──→  server/assets/maps/       │   OccluderTable
   （盒/球带姿态）→ 写 JSON                      │  NewMap.json              │
```

- **为什么是组件不是继承类**：下载地图的 Actor 类型不可控，组件=给任意 Actor 配"参与服务器碰撞"的角色（**组合优于继承**），参数（自定义包围盒覆盖/偏移）有落点。
- **为什么拒绝"对局开始运行时上报"**：遮挡只制造 miss——外挂客户端上传空遮挡表 → 全图穿墙射击，是**纯增益的隐蔽作弊**；且多客户端各报一份无权威可言。地图几何永远是**服务器侧数据资产**（构建期随库分发）——这正是第 9 期"对端不可信"的预埋，叙事不能自相矛盾。
- **几何合同 v1（schema）**：`{map, unit:"cm", occluders:[{primitives:[{type:box|sphere, transform, size}], fallbackAABB}], entityHitbox:{radius, halfHeight, headSphere?}}`——nlohmann-json 解析（毕设遗产依赖）；数量上限 64、半尺寸>0 校验；缺失/非法**启动即 fail-fast**（装配错误不留活口）。
- **边界**：取简单碰撞原语、不取网格碰撞；凸包/三角网格不取（D5-12）；无简单碰撞退化 AABB 兜底。验证器（可选上镜）：服务器命中体 BatchDraw 线框画回 UE，与引擎碰撞显示叠加——"图=代码一致"肉眼化。

**准星一致性附注**：客户端准星 = 相机 forward = 同一 yaw/pitch 的方向向量，与 §4.1 公式同源——双端天然一致，准星指哪打哪。

## 5. 射速与弹药（每实体三个字段，MatchService 持有）

| 字段 | 初值 | 规则 |
|---|---|---|
| `hp` | 100 | 命中 −25（D5-07 伤害常量，4 枪见底）；**钳 0 不触发死亡**（ep07 启用死亡判定） |
| `lastFireMs` | −∞ | ④ 射速窗口用；服务器阈值 **95ms**（客户端按 100ms 步进——容差吸收时钟抖动，幻影枪概率趋零） |
| `magUsed` | 0 | ③⑥ 弹匣；容量 **30 发** |
| `reloadUntilMs` | 0 | ②③ 换弹窗口；打空自动换 **2500ms**，期间开火全丢 |

**hp 同步口径**：hp 只随 21 号事件广播，**不进 17 号快照**——TCP 可靠有序保证事件不丢不乱，事件流等价状态流（省快照字节；UDP 时代才需要周期对账）。HUD 血量行初始值 100（MatchStart 时全员满血）。

**为什么弹药做在 ep05 而 HUD 留 ep07**：射速校验防的是"改包连发"（对局公平性的底线，属于"裁决可信"叙事），弹药是它的天然载体（没有弹匣，射速校验一枝独秀撑不起演示）；而弹药数字给**观众看**的载体是 HUD，那和血条一起做才不重复开屏。服务器先有真相，表现后到——顺序不能反。

## 6. 客户端本地同步模拟（表现层预测，写进蓝图操作方案）

客户端本地跑同一套规则（100ms 间隔 / 30 发 / 2.5s 换弹）：按下左键本地节流并扣本地弹匣，同时发 20 号。**本地状态只管表现节奏，服务器才是真相**——本地漂了不纠偏（下次换弹自动对齐），因为弹药数字本期不上 UI，观众看不到漂移，ep07 上 HUD 时如需严格一致再加服务器回执。范围纪律：不为本期看不见的东西做协议。

## 8. KPI：一次开火的全链路耗时分解（本期唯一 KPI 图）

五段堆叠（日志时间戳，滑块道具复用）：

```
T0 按下左键（客户端）→ T1 20 号发出 → T2 服务器收到并判定 → T3 21 号回到客户端 → T4 Hitmarker/tracer 上屏
```

- 0ms 滑块：全链路 ≈ 几毫秒（本机回环）；
- **150ms 滑块：T4−T0 ≈ 300ms+**（往返各 150）——口播落点："这就是命中不可预测的代价，也是为什么表现要预测、裁决要权威"；
- 掉血可见性：Debug HUD 新增**血量行**（对局期各实体 hp，21 号驱动）——开枪瞬间 HUD 数字 100→75，"掉血全链路"上镜载体（总纲原文口径保留）。
- **打点方案**：客户端本地维护 fire 序号（T0 按键/T1 发出各打一行日志），服务器 T2 收到即打判定行，客户端收到 shooterPid=自己的 21 号即 T3、Hitmarker 上屏即 T4——按"最近一次开火"配对，**协议零改动**（D5-01 空 payload 不破）。
