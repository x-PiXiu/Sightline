# P2 道具系统落点分析

> **性质**：第一次动服务端 domain 层的增量，客户端同步扩展。
> **时间**：2~3 天。
> **演进路线图依据**：见 `docs/演进路线图.md` P2 段。
> **前置状态**：P1 完成（全闭环可玩）+ P3 完成（HUD 全部视觉验证），顺带修一个已知遗留：出生点半径单位问题。

---

## 一、业务需求与演进定位

**核心目的**：让地图上出现可拾取的道具（弹药箱、血包），服务端权威判定拾取结果。展示三种架构能力：

| 能力 | 展示点 |
|---|---|
| 网络对象的动态生灭 | 服务端广播 Spawn/Taken，两端表镜像维护，拾取后双方同时消失 |
| NetID/TypeID 独立于 Blueprint 的对象标识体系 | 服务端分配 NetID，客户端按 TypeID 查表显示，二者解耦 |
| DataAsset 数据驱动练兵（客户端） | 道具的模型/效果/刷新参数走 DataAsset 而非蓝图子类——为 P8 武器数据驱动铺路 |

**P2 还顺带修一个 P3 联调发现的遗留**：`Room::spawnPoint` 的 radius 是 18（UE 厘米世界下 = 18cm，重生传送会到地图原点附近），改为 1800（18 米）。

## 二、设计决策：走过自动拾取 vs 按键主动拾取

| | 走过自动拾取 | 按键主动拾取 |
|---|---|---|
| 交互 | 走进道具区域自动触发 | 按 E 键拾取 |
| 消息 | 省 C2S_Pickup（拾取判定在 applyMove 内） | 需要 C2S_Pickup + 服务器回 S2C_PickupResult |
| 契约面 | **新增 2 条 S2C**（ItemSpawn/ItemTaken） | 4 条（+C2S_Pickup +S2C_PickupResult） |
| 权威 | 服务端在 applyMove 懒检查距离——权威天然成立 | 同样服务端权威 |
| 面试叙事 | 拾取没有"用户意图"要表达，省一条消息是纯粹的工程选择 | "请求-验证"模式更显式，适合拾取后需要权限校验的场景 |

**决定：走自动拾取**。拾取本质是"走过区域内的被动触发"，不是"用户有意图的动作"——省消息、省输入绑定、NetID 映射流程不受影响。若后续需要"按 E 拾取专属武器"，再回到主动拾取方案（此处变更不影响接口）。

## 三、服务端详细设计

### 3.1 domain 层（新增 item.h，Room 扩展）

**item.h**：道具基础类型（纯 C++ 头文件，零依赖）

```cpp
// ItemTypeId 枚举（两端共享数值契约，改值需同步）
enum class ItemTypeId : uint8_t { HealthPack = 1, AmmoBox = 2 };

// Item 结构体（房间内道具）
struct Item {
    uint32_t net_id;          // 房间内自增 NetID（不是全局唯一）
    ItemTypeId type_id;
    Vec3 pos;
    bool taken = false;       // 是否已被拾取
    float taken_at_ms = 0;    // 被拾取的时刻（惰性重生基准）
};
```

**Room 扩展**：

```
新增成员:
  items_: vector<Item>          道具容器
  next_item_id_: uint32_t       NetID 自增计数
  item_respawn_ms = 15000       重生间隔（毫秒）

新增方法:
  spawnItems():         按规则在地图上布点（开局时由 application 调用）
  tryPickup(pid, pos):  applyMove 顺带调用——遍历 items，距离<拾取半径且 taken=false 且冷却
                        → 标记 taken + 记时刻 → 结算效果 → 返回拾取结果
  tickItems(now):       applyMove 懒检查（顺带调用）——遍历 taken 且 now-taken_at_ms>item_respawn_ms
                        → 重置为可拾取 → 广播 S2C_ItemSpawn
```

**拾取效果**：血包 = `player->hp = min(max_hp, hp+50)`，弹药箱 = 标记拾取（客户端本地加备弹，弹药非权威）

**判定时机**：applyMove 里顺带——每次位置上报时检查"我现在站在道具上吗"。省掉独立定时器、不需要 C2S_Pickup 消息、和位置更新同频（10Hz）。

**出生点修复**：`spawnPoint` 的 `radius = 18` 改为 `radius = 1800`（18 米）。单测数值同步更新。

### 3.2 application 层

- `RoomService` 扩展：开局布点（`Room::spawnItems`，调 `ITimerScheduler::runAfter` 广播 Spawn）
- 收拾取结果后广播：`S2C_ItemTaken{netId, pid, typeId, pickerNewHp}`

### 3.3 adapters 层（codec 新增 2 条消息）

| MsgId | 方向 | 消息 | 布局 |
|---|---|---|---|
| 15 | S→C | ItemSpawn | `[4B netId][1B typeId][4B x][4B y][4B z]`（共 17B） |
| 16 | S→C | ItemTaken | `[4B netId][4B pid][1B typeId][4B pickerNewHp]`（共 13B） |

- 契约面清单（协议文档第十一节）登记这两个消息号。
- TypeID 枚举值 `HealthPack=1 / AmmoBox=2` 作为两端契约（服务端定义在 item.h，客户端在 SightlineProto.h 的 EMsg 下补注释）。

## 四、客户端详细设计

### 4.1 SightlineProto 扩展

- EMsg 追加：`S2C_ItemSpawn = 15`、`S2C_ItemTaken = 16`
- 新增 `DecodeItemSpawn`（返回 NetId/TypeId/Pos）与 `DecodeItemTaken`（返回 NetId/Pid/TypeId/PickerNewHp）
- 坐标换轴：同 Move 的处理（服务器 y→UE Z）

### 4.2 ASightlineCharacter 扩展

新增状态：
```cpp
TMap<uint32, AActor*> Items;   // NetId → 场景中的 BP_Item 引用
```

新增 Handle：
- `HandleItemSpawn`：调 `BP_OnItemSpawned` 钩子；如果 Items 里已有同 NetId 则忽略（防重复）
- `HandleItemTaken`：找到对应 Items[NetId] → `DestroyActor` → 从 Map 移除；如果 pid==MyPlayerId 且 typeId==HealthPack → 触发已有 SetHP 路径（血量回涨通过 `BP_OnRespawned` 类机制，或新增 `BP_OnHealed` 钩子）

### 4.3 BP_Item（继承 AActor，蓝图子类）——**数据驱动练兵**

```cpp
// BP_Item 数据驱动骨架（C++ 定义，蓝图只填资产）
USTRUCT(BlueprintType)
struct FItemDefinition
{
    GENERATED_BODY()
    UPROPERTY(EditAnywhere) uint8 TypeId = 0;
    UPROPERTY(EditAnywhere) TObjectPtr<UStaticMesh> Mesh;
    UPROPERTY(EditAnywhere) TSubclassOf<AParticleSystem> PickupEffect;  // 拾取特效（可空）
    UPROPERTY(EditAnywhere) float RotateSpeed = 90.f;   // 旋转动画速度（度/秒）
};

UCLASS(BlueprintType)
class AItemActor : public AActor
{
    GENERATED_BODY()
public:
    UPROPERTY(EditAnywhere, BlueprintReadWrite)
    FItemDefinition Definition;
    UPROPERTY(VisibleAnywhere)
    UStaticMeshComponent* MeshComp;
    virtual void Tick(float DeltaTime) override;  // 旋转动画（纯表现，不影响拾取判定）
};
```

Blueprint 子类（`BP_Item`）只需在 Details 填 `FItemDefinition`——每种道具一行 DataAsset，零蓝图逻辑。

### 4.4 表现钩子

| 钩子 | 触发时机 | 蓝图覆盖内容 |
|---|---|---|
| `BP_OnItemSpawned(NetId, TypeId, Pos)` | 收到 ItemSpawn | 按 TypeId 选 DataAsset → Spawn AItemActor → 存入 Items Map |
| `BP_OnItemTaken(NetId, Pid, TypeId, PickerNewHp)` | 收到 ItemTaken | Destroy AItemActor + 从 Items 移除；拾取者为自己时播放拾取特效（可选） |

## 五、已知问题与边界

| 问题 | 处置 |
|---|---|
| 出生点半径 18=18cm 重生在原点 | 顺带修复：radius 18→1800 |
| 弹药箱效果：弹药在客户端本地加，没有服务端校验 | 当前协议弹药非权威——设计如此，注明 |
| 道具数量：开局固定布点（3~5 个），不做"按人数动态调整" | YAGNI，不加复杂度 |
| 道具视觉旋转动画 | `AItemActor::Tick` 里纯表现旋转——不入判定、不传网络 |
| 弹药箱拾取后服务端无法"回收"弹药效果（下次再捡没有效果） | 标记 taken+冷却后才重置——冷却期间拾取无效果，冷却结束道具重置后才能再次生效 |
